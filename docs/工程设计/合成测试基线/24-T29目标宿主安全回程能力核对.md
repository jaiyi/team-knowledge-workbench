## 获分项授权后才执行的目标验收

1. 我们先核定固定目标 Desktop/Host/插件版本及隔离 profile，拿到**可供第三方使用**的系统浏览器唤起、原发起 Host 回程／路由准入契约与 Host/renderer/同用户 agent 的秘密边界；由实际掌握目标设备、身份与部署权限的责任方分别准许对应实验，不假定存在独立 Desktop 平台／安全 Owner。若同用户 agent 威胁模型下无法安全保管秘密，停止真实接线，不向 renderer 或任意深链交付 bearer、code 或 IdP token。
2. 只有受支持的回程契约明确且取得目标运行授权后，才在固定隔离 profile 做**无身份材料**的 Host 路由／回程实验，检查是否可回原发起 Host 及错误 Host、重复、过期、卸载时拒绝；一次路由 200 只证路由，不证明秘密隔离或人员身份。当前目标安装、浏览器回程与该实验均 `not_run`，不得以 VM 的固定 503 冒充目标读回。
3. 另由实际身份及 Backend／部署权限责任方批准隔离测试 IdP 的 issuer、client、redirect、audience、测试主体和撤权策略，受信任的固定 HTTPS Backend/环境/TLS 分发来源；明确 `(issuer,sub)` 绑定、会话/引用有效期、一次性领取、重启恢复、登出、账号切换、撤权传播上限及故障拒绝。不得提交真实 token、cookie 或生产凭据作证据。
4. 固定版本上再分别读回获准的登录／原 Host 领取／会话查询／登出，与错误 Host、环境/地址/签发方/受众、state/nonce/PKCE/引用篡改和重放、超时、切号、撤权、断网/服务不可用等拒绝；检查 renderer、包与普通日志无凭据，失败不产生业务能力。由相关责任方按脱敏回执复核，不以文档推测或 fake 测试结果代替。T29 真实身份门通过后，资源权限责任方另批 A/B Git／WeKnora 只读目标及 ACL，再验 T07 的零／单／多空间、跨设备/跨空间拒绝、撤权与对象级读回；T08 在途操作与恢复门独立验收。此轮不接真实资源、不开放生产 `/v1/context` 或真实团队写路由。

真实身份、ACL、隔离、撤权和恢复门未通过前不得真实团队资产写入；不得将 fake/admin 或不完整外部读回标记 `real_verified`。未批准 Skill Draft 不在获准隔离非生产 Runner 外执行；生产凭据、敏感原件、完整 Prompt 或敏感 Tool 参数不进入代码、日志、fixture、包或证据。维持 `p0_overall: no_go`、`p0_transition: allowed_with_no_go`、`p1: not_started`。
