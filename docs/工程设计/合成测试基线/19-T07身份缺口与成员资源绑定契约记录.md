## 身份信任起点：目标版调查

- 固定调查对象是已安装的 DSH Desktop `0.2.0-rc.2` 的**随包文档**，不是运行中的账户。`dsh-deepseek-account/README.md` 描述 Host-only 的 `getPlatformSession()` 和可能为 `null`/滞后的 `userId`；`dsh-deepseek-account-platform/README.md` 描述限定 Platform origin 的 grant、profile 快照与注销/远端撤销局限。该账户 ID 和 Platform token 不是面向 Workbench Backend 的人员证明，不向 Backend 转发 token。
- 随包 `dsh-client-connection/README.md` 的浏览器 cookie/launch token 是本地 operator Peer 会话；文档明言 Host/Origin 检查不建立人员身份。[隔离 CLI Web 健康路由证据](../evidence/10-DSH-isolated-web-host-health-smoke.md)中的 401/403 也不能外推到 Desktop 人员身份。
- 当前随包 Host 只注册包身份和本机 `/healthz` 探针（`packages/distribution-adapter/src/workbench-package-fixture.ts`）；公开 `apps/api/src/server.ts` 仍只有健康路由。`AuthenticatedPrincipal` 是内部调用参数，不是后端验证的 DSH 断言。已检查的版本匹配文档**没有给出**受支持的 Host→Workbench Backend 人员断言；不据此断言平台绝无其他私有能力。`GET /v1/context` 等仍是设计草案，不是可用入口。
- 后续由平台/安全 Owner 明确目标载体和受支持的签发/验证机制、信任锚、Workbench Backend audience 与环境绑定、有效期、nonce/重放防护、账户切换、会话注销与远端撤销、稳定 `dsh_subject`→本服务 principal 映射；经授权固定目标版本运行正反例之前，不实现 JWT 猜测或公开写路由。

## 合成 PG 授权与元数据

- 新增可选的**隔离合成契约**迁移 `apps/api/migrations/003_asset_space_authorization_bindings.sql`，不修改此前 `001` 与尚未提交的 T08 `002`，不回填旧角色为成员。`team_memberships` 单独记录虚构 `(actor_id,team_id)` 的 active/disabled；`asset_space_resource_bindings` 把非敏感 Git 仓库稳定 ID/固定 protected ref、WeKnora space ID、配置版本和 `pending|disabled` 绑定到 `(team_id,asset_space_id)`，复合 FK、唯一目标约束拒绝错绑/重复。**没有** URL、密钥、服务身份、已激活状态、Provider 网络连接或真实连接检查。
- 内部 `recordKnowledgeTransition` 在持有 Knowledge state 锁的同一事务内对成员和空间角色分别 `FOR SHARE` 重查；在 replay 确认及 evidence verifier 前拒绝缺失/撤销成员，state/event/outbox 不追加。锁行的并发撤权顺序尚未由独立 PG 双连接验证。`captured→candidate` 不是 Git/WeKnora 调用，不因缺外部连接拒绝这个内部合成状态转换；正式业务写入仍被整体门禁阻断。
- 内部 `readAssetSpaceBinding` 仅在传入主体声称范围、**当前** active 团队成员和该空间角色都存在时读回非敏感配置摘要；无成员/空间权限返回 `null`。它无公开 HTTP 路由且主体仍由调用方传入；`pending/disabled` **都不能用于执行 Provider 操作**。版本字段只代表本合成行的读回版本，不代表已有管理员配置 CAS、审计或旧 operation 固定版本。真实资产快照与仓库 ID 的服务端权威来源、Provider ACL 和管理员资源登记待独立准入。
