- 固定可信 HTTPS origin，TLS 反向代理只转发至 `127.0.0.1` 本地端口；必须保留与 public origin 相同的原始 `Host`，丢弃客户端和上游的 `Forwarded`/`X-Forwarded-*`，不要为兼容代理放宽服务端 Host/origin 检查。只在确定代理配置、HTTPS 浏览器 Secure `__Host-*` cookie、登录状态、切号/登出及实际 IdP 撤权传播上限后声明目标结果；通过签名 ID token 的单次登录不等于之后 IdP 停用立即撤销本地会话。
- 审定非秘密部署参数（均必须显式提供）：`WORKBENCH_WEB_OIDC=1`、`WORKBENCH_WEB_ISSUER=<批准的 HTTPS issuer URL>`、`WORKBENCH_WEB_CLIENT_ID=<批准 client>`、`WORKBENCH_WEB_ORIGIN=<固定公开 HTTPS origin>`、`WORKBENCH_WEB_ENVIRONMENT=<隔离环境>`、`WORKBENCH_WEB_PORT=<loopback 端口>`；`WORKBENCH_WEB_DATABASE_URL` 是**秘密**，只由受控运行环境交付，使用 `postgresql://...?...sslmode=verify-full`。审定后才可显式执行 `./node_modules/.bin/tsx apps/api/scripts/web-oidc.ts`；绝不从 DSH 面板或普通页面提供该配置。实际 HTTPS、issuer、数据库连接及运行在本轮均 `blocked/not_run`，此文不是运行许可。
- DSH 外链 URL（构包时的 `--web-login-url https://<已批准的 Workbench origin>/auth`）独立于本机 HTTP `backendEndpoint` 健康探针。固定目标 DSH/profile、受支持的外部系统浏览器打开行为、干净可追溯的安装包和批准的 HTTPS URL 后，才能构包、安装及点击实测。面板外链的 VM 测试不证明目标版 Desktop 系统浏览器或回程能力；个性化面板需另行取得原发起 Host 的安全回程和秘密保管契约，DSH→MCP 逐人身份更是独立门。
