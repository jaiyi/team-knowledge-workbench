## 5. 阻塞项

1. 既有 Desktop `desktop` profile 的 Host 安装/卸载和静态 Client 面板有历史人工读回；临时独立 `DSH_HOME` 的 Desktop 已完成 fresh-profile 初始化、离线安装、重开、旧产物应用 Console 健康读回及新产物动态面板读回。Settings 插件清单人工 Host Loader 快照见 [13](./evidence/13-DSH-isolated-desktop-host-inventory-readback.md)；包级禁用后的侧栏/面板消失及路由 404 见 [14](./evidence/14-DSH-isolated-desktop-disable-readback.md)；重新启用并正常重启后的包/Host 运行中及侧栏/面板恢复见 [15](./evidence/15-DSH-isolated-desktop-reenable-restart-readback.md)；再次停用并退出、重新打开后的停用状态及侧栏不可见读回见 [21](./evidence/21-DSH-isolated-desktop-disabled-reopen-readback.md)。仍缺独立 Host/Client 分项 load/错误报告、完整安装前后快照及后台资源全部释放；旧版源码中的 Workbench 专属 API 未在目标版本证实；
2. Workbench-specific readiness、source/完整 artifact digest 的 **Desktop 宿主**读回仍未取得；本机 API 进程存活的应用 Console 和面板人工读回不能替代业务/Provider 健康；
3. 隔离 CLI Web Host 及隔离 Desktop 应用 Console 已读回 Connection `/api` 脱敏健康状态、会话保护和本机 API 可达→失联→恢复；新产物的 Desktop 面板另有人工作出的不可达→可达→不可达→可达读回。包级禁用后面板/入口消失、健康路由在同一 Desktop 会话为 404；该 UI 实测仍不提供独立 Host/Client load report、后台资源全部释放、业务 readiness 或最后一次停止测试 API 后的第五次面板读回；可重复 rollback 尚未完成；pnpm 卸载后的软链接清理需形成确定性验证；
4. 脱敏 fake principal/ACL、FakeGit 受控 merge 回读/旧 head 拒绝与 FakeWeKnora ingest/timeout/unknown/迟到结果/mismatch/reconciliation 回归已加入；隔离 SQLite operation 元数据增加连接重开、租约 CAS、独立 Node 子进程退出后重领，以及测试专用 fake event/operation/合成请求同事务提交/回滚与跨进程读回。内部 PostgreSQL 状态/event/outbox 事务和数据库当前授权绑定检查已有录制客户端/PGlite 测试，见 [17](./evidence/17-P0-postgres-transaction-authorization-foundation.md)；隔离服务器上真实 `pg.Pool` 应用事务的有限合成数据读回见 [19](./evidence/19-P0-isolated-cloud-pg16-application-transaction-readback.md)。仍无可信资产快照存储、PG 容器重启或备份恢复、Provider Worker；内存 Provider fixture 和 fake 幂等不等于生产 payload 安全方案或完整 Worker 恢复；历史 Git merge 的真实当前 head 绑定与签名验证、已落库 `index_unknown` 的补偿、完整 Provider rollback、真实 Worker 重启与可信外部 read-back 仍缺；fake 身份/证据不能替代真实认证或外部事实；

## 6. 后续开发与验证顺序

1. **最小 UI 宿主补项**：目标 Desktop `0.2.0-rc.2` 的通用 `./client` + `main`/`sidebar.panellist` 契约已有静态面板读回；隔离 Desktop 应用 Console 的 Host `/api` 健康 route 读回见 [11](./evidence/11-DSH-isolated-desktop-health-readback.md)。新 Client 已从干净提交构建并在[隔离 Desktop 面板](./evidence/12-DSH-isolated-desktop-dynamic-health-ui.md)读回固定“本机 API”文案及失联/恢复；[包级禁用](./evidence/14-DSH-isolated-desktop-disable-readback.md)后面板与侧栏入口消失，同会话健康路由 404；[重新启用与重启](./evidence/15-DSH-isolated-desktop-reenable-restart-readback.md)后包/Host 条目运行中、侧栏/面板恢复；[再次停用并重新打开](./evidence/21-DSH-isolated-desktop-disabled-reopen-readback.md)后仍停用且侧栏不可见。继续补 Host/Client 分项 load/错误报告及后台资源释放，不从 API 进程可达推断业务 ready。
2. **补齐 package Spike**：独立临时 `DSH_HOME` 的 Desktop fresh-profile 初始化、离线安装、重开后旧产物的静态 UI/健康路由 Console 读回及新 digest 产物的动态面板状态循环已完成；包级禁用后的 UI/健康路由移除、重新启用后重启恢复，以及再次停用状态跨隔离实例重新打开保持也已分别人工读回。继续分别核验 Host/Client 分项 load、完整 artifact digest/source 的宿主 read-back、后台资源释放与失败路径、卸载残留自动清理、旧 digest/空 profile rollback。后续 disable、卸载、rollback 或清理须按具体范围另行授权；单独作 Workbench package 决策。
3. **P0 fake Provider contract 与安全边界**：现有脱敏 fake principal/ACL、FakeGit/FakeWeKnora 及隔离 SQLite 回归只作为 contract 证据；补齐 P0 所需的失败、重放、越权及脱敏用例和未验证项清单，不以 fake 成功代替真实身份、外部验签或 Provider read-back。Knowledge-first 纵向切片属于 P1；真实 Provider 发布链不在 P0 实施。
4. **P0 隔离/恢复证据与真实写入硬门禁分开**：本地 PG 事务基础见 [17](./evidence/17-P0-postgres-transaction-authorization-foundation.md)，隔离云端 PG16 的真实 `pg.Pool` 合成事务子路径 4/4 见 [19](./evidence/19-P0-isolated-cloud-pg16-application-transaction-readback.md)。P0 如未完成真实身份/双空间隔离、Worker 重启恢复和对账，只能记录缺口及 `transition_allowed_with_no_go`，禁止真实资产写入；可信控制面、可恢复 Worker、PG 备份恢复的完整实现与验收属于后续 P2 硬门禁，不作为本轮 P0 退出的隐含开发任务。
5. **Provider/云端 readiness**：先依据[只读盘点](./evidence/20-P0-provider-cloud-readiness-inventory.md)由授权环境和 owner 核对 Git、WeKnora、SkillHub、DSH/Harness 的目标版本、环境、能力、阻塞原因、fallback/回滚路径及腾讯云非生产部署可行性；拿不到最终 read-back 则如实标记 pending/blocked，不为 P0 开始真实发布或完整业务链。TeamAI/TeamLab 默认 `readiness_only/non_blocking`，未显式纳入目标路径不作为本期硬门禁。
6. 分别记录 Workbench package、cloud/provider、P0 overall 三项带责任人、复审日期与证据引用的 Go/No-Go；若 package 或其他门禁仍阻塞，明确 `transition_allowed_with_no_go` 仅允许隔离 fake/admin 开发，不等于 `P0 overall_go`、N0 完成或真实资产写入许可。以上是 P0 验证与决策范围，不宣称 P1 已启动。

## 7. 强制边界

- fake/admin 不能报告为 `real_verified`；
- 服务可访问不能报告为已集成；
- package 安装成功不能报告为 Knowledge、SkillHub、Harness 或业务成功；
- 本地测试通过不能解除 P0 硬门禁；
- 不得将生产 Token、Cookie、密码、API key、完整业务原文、完整 Prompt 或敏感工具参数写入代码、日志、fixture、bundle 或 evidence manifest；
- User-authored Plugin creation/release/runtime 未实现；
- TeamAI 默认是 readiness-only/non-blocking；
- P1 当前未启动，不因已经编写部分 fake contract 设计而改变阶段状态。
