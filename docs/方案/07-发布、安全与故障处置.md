# 发布、安全与故障处置

## 1. 知识发布链

用户拟通过经验证的 DSH Desktop 身份上下文进入 Workbench；后端身份交换与撤权机制尚需目标环境验证。后端仅将已验证的 DSH subject 映射为 `principal_id`、团队成员和 asset-space 角色；认证上下文只决定请求者身份，不能直接扩大 Git、WeKnora、SkillHub 或 TeamLab 权限。用户确认/审批与外部技术执行分开记录：`confirmed_by`/`approved_by`/`released_by` 是业务责任人，`executed_by`/`service_identity_id` 是实际调用 Git bot、WeKnora adapter、SkillHub publisher 或 TeamLab adapter 的服务身份。

只有 `Knowledge Creation Session` 中的 approved draft revision 才能启动发布。发布前必须同时锁定团队资产空间和规范 Git path：

```text
Knowledge Creation Session
  → approved draft revision
  → 服务端校验 principal、team/asset-space 权限、base revision、taxonomy、repo path、来源、敏感性和幂等键
  → Git branch/MR（受控 service identity 执行）
  → CI
  → steward/审核人批准
  → 合并受保护 main
  → Git merge event（验签、去重、落库）
  → Workbench outbox operation
  → persistent worker 从 merge commit 读取 canonical 内容
  → WeKnora ingest
  → 真实读回 document/version/source/repo_path/ACL
  → 检索冒烟验证
  → knowledge = published
```

Webhook 到达、任务入队、provider 接受请求或 HTTP 200 都不能直接推进 `published`。Worker 崩溃、索引超时或读回不一致时进入 `index_unknown`/`reconciling`；索引失败保留旧版本的**证据**，只有旧版仍有授权且有效时才继续服务，敏感/过期旧版须先阻断。站内草稿保存仅落 PG，不写正式 Git 或 WeKnora；修改需在提交/合并前检查 base revision 冲突。详细的增改退役/重命名、紧急撤权和三方对账契约见[工程设计 5.2–5.3](11-开发工程设计与集成基线.md#52-knowledge-增改退役与权限变更契约拟议)。

### 1.1 普通退役与紧急撤权不是同一条链

- **普通退役**：有权 owner 发起→记录理由/旧版目标→审核 tombstone MR/CI→protected merge→PG receipt/outbox→Worker 按原目标清理或隔离 WeKnora 所有相关旧索引→在受控和允许的直连入口做负向检索读回→才置空当前可用指针并标 `deprecated`。下架 API/旧索引不可见性需在目标版本 Spike 确认；无法验证时显示 `withdrawal_unknown/manual_required`，暂停相关入口并升级，不能以 Git 删除或 PG 状态掩盖外部仍可检索。Git 历史和审计按保留策略留存，不宣称物理删除。
- **紧急撤权/泄露**：经可信事件确认后先记录阻断 epoch 并即时拒绝服务端检索、撤销会话/缓存和未外调任务；并行由有权平台/数据 owner 排查 WeKnora 直连、共享链接、已下发副本和 Git/存储入口并实施阻断/负向读回，无法确认即按安全事件暂停受影响空间。随后走 Git 更正/退役 MR 与索引对账；**不等 Git 审核才能停止受控访问**，也不把受控入口已拒绝误报成所有外部访问均已撤销。

## 2. Skill 审核、固定包与条件性发布链

Git MR/CI、指定审核人批准及受保护分支 merge 是正式 Skill 源码不可绕过的审核链；DSH 自带 Skill 格式／加载校验须按目标版本实测，它既不能替代业务契约、边界/回归测试，也不构成正式审批。TeamAI 是优先验证的多端分发方案，只有目标 CLI/Hook、固定版本映射和逐目标安装读回实测通过才启用；SkillHub 仅当需要独立 Registry 契约且目标验证通过时加入，不是首期硬依赖。候选选择与 fallback 依[工程选型门](11-开发工程设计与集成基线.md#7-skillhub-与-teamai-的角色评估及选择门)留 ADR。

只有 `Skill Creation Session` 中完成测试并获批准的 draft revision 才能启动发布：

```text
Skill Creation Session + 指定草稿修订
  → contract/golden/regression/security 与目标 DSH 格式校验（能力待实测）
  → 服务端核主体、空间、base revision、依赖、effects、路径和审查资格
  → Git MR/CI + Skill owner/指定审核人批准（合并前仍审核中）
  → canonical Git protected main 经审核 merge（Skill 已发布）
  → 从固定 merge commit 构建不可变 package/digest
  ├─ 经验证的 SkillHub/等价 Registry release/version/digest 读回（选用时）
  └─ 有期限、可审计的管理员固定包 fallback（未选 Registry）
  → TeamAI 受审目标分发（优先验证、启用时）或其他受控目标安装
  → 逐目标安装文件 manifest/digest 读回
  → DSH 指定 profile 的 discovery/load/digest 独立读回
```

`approved` 只说明审核批准，不等于 Skill `已发布`；只有核实 canonical Git 受保护 main 上的受审 merge commit，才将该 Skill 版本标为 `已发布`。合并前保持 `审核中`；已合并但 webhook 丢失、验签/归属/审核无法确认时先 `unknown/reconciling`，按固定 commit 对账，不能凭事件入队、打包或管理员 fallback 提前晋级，也不能因下游失败撤销已证实的 Git 发布事实。package/digest 是后续独立制品证据；选用 SkillHub 时，其真实 release/version/digest read-back 才证明该 Registry 的 `registry_released`（而非 Skill 的 Git `已发布` / `skill.released`），失败或未知只阻断该 Registry 路径的 release/后续目标分发，不撤销已核实的 Git Skill 发布事实；管理员固定包另列 `fallback_only`，不能冒称 SkillHub/Registry release，更不能替代 Git merge。选用 TeamAI 时它只能消费已确认的 pinned digest，并读回 target、installed revision、文件清单和实际 digest；TeamAI 安装不等于 DSH loaded 或业务成功。

## 3. Workbench Plugin 市场安装链

`team-knowledge-workbench` 是可复用的 DSH Desktop Workbench Plugin，可以通过宿主支持的 market/catalog 或内部受控安装路径分发给多个团队：

```text
构建 server/client package
  → canonical repository identity、版本和 digest 校验
  → DSH Workbench market/catalog 安装
  → Desktop 重启
  → client/server 注册、enabled、Session ownership 和 UI read-back
  → 团队管理员完成 team/asset-space binding
  → Workbench 可用
```

这条链只证明 Workbench package 到达目标 Desktop。它不证明 `team-knowledge-asset` 已发布、Git/MR 已批准、WeKnora 已索引、SkillHub 已发布或 Harness 已加载。Workbench host 的本地 state、ownership metadata 和 market install record 不是团队授权或资产 canonical source。Workbench 后端使用独立身份和 worker credential；DSH launch token 不是可复用 API credential。

同一 Workbench 可以被多个团队安装，但每个安装必须绑定独立的 `team_id`、`asset_space_id`、Git repository、WeKnora space、ACL 和治理策略。安装、升级、禁用、卸载和配置变更都要有审计、回滚和读回；前台 mode switch 不会自动停止后台任务，长任务必须使用显式 owner、cancellation、幂等和 reconciliation。
## 4. 分发与交接链（验证后）

```text
已审固定包 digest（SkillHub release 若选用；否则受控管理员 fallback 或经 ADR 批准的等价 Registry）
  → 受审团队仓库 commit 与包 digest 映射（TeamAI 如启用）
  → 已初始化目标在下次受支持会话 pull，或有权成员主动 pull
  → 目标文件清单/摘要与批准包 digest 映射读回
  → DSH handoff
  → DSH profile/loaded digest/read-back
  → beta/stable profile 可消费
```

在**现有候选拓扑**中 TeamAI、SkillHub 和管理员不是并列的 Skill 发布权威：SkillHub 若选用，须真实读回其 release/package/digest；若不选，已审 Git/CI 固定包经受控管理员 fallback（或经 ADR 批准的等价 Registry）单独留证，不伪造 SkillHub 的 `registry_released`；Skill 本身仍以经核验的 canonical Git merge 判定 `skill.released`。TeamAI（如启用）仅负责对应受审团队仓库版本的目标侧同步，默认 `pull` 不天然锁定 digest，必须校验版本映射及目标文件摘要；TeamAI 不可用时管理员按同一个固定 digest 受控安装。DSH 最后确认 profile 实际装载；未读回时禁止报告 `loaded` 或开始运行。若拟由 TeamAI 同时承担等价注册发布职责，须另行验证治理契约并作 ADR。

TeamAI 的上游机制是成员首次 `init` 后，以 SessionStart Hook 在下次受支持的会话启动时 `pull` 团队 Git 的已审版本；不是发布时实时推送所有本机，也不能仅凭 `teamai push` 成功绕过 MR。若使用独立 TeamAI 仓库，固定包须经镜像仓受审 merge 并记录源包→仓库 commit→目标文件摘要映射。管理员「团队空间与连接」仅管理获批团队仓库、目标 workspace/profile、拉取模式、初始化状态、固定版本与回执，成员本机首次初始化和独立 Git 只读授权不能由后端连接检查替代；需目标端逐机/逐 profile 读回，才可声称 installed。具体见[工程设计 3.2/5.4](11-开发工程设计与集成基线.md#32-teamai-配置与成员设备引导仅选用时拟议)。

### 分发门禁

目标仓库和分支保护、路径/删除安全、secret 和敏感信息扫描、依赖锁定、profile 兼容、版本 pin、Hook 权限限制、幂等、安装/删除清理、文件清单读回、回滚和审计。外网或跨安全域只允许脱敏/公开样本，不得同步正式敏感知识、生产凭据或高风险工具。

TeamAI 不可用或目标能力未验证时，不能以 SkillHub Registry 发布代替目标安装；如目标 DSH/权限契约允许，由有权管理员按同一固定 package/digest 对指定目标受控安装，逐目标核文件摘要、DSH profile 装载及回滚，标 `fallback_only` 与期限。无法安全安装或读回时保持 blocked/unknown，不宣称目标可用。

## 5. CI 门禁

### 共同门禁

格式、schema、ID、路径、owner、sensitivity、来源、secret、个人敏感信息、重复 canonical key、链接、CODEOWNERS、受保护分支和变更范围。

### Skill 门禁

input/output schema、确需知识查询时的固定引用与查不到/无权/失效后请求用户核实的失败处理、effects 和 profile 权限兼容、依赖锁定、许可证/SBOM、golden/regression、digest 生成和危险权限变更。无知识查询需求不强制声明知识依赖；CI 核说明及 fixture，不以静态检查冒充真实检索或运行验证。

### 发布链门禁

- merge commit 必须与批准的 head SHA 一致；
- merge event 必须验签、去重并在确认接收前落库；
- package digest 必须由固定 merge commit 的构建产物计算，不接受客户端传入；
- 若使用 SkillHub，release read-back digest 必须与 package digest 一致；fallback 单列管理员固定包及读回，不能写 SkillHub 成功；
- 若使用 TeamAI，request 必须引用已审且确认的 pinned digest，不能引用 `latest`；
- TeamAI installed digest 必须与 pinned digest 一致；
- DSH profile 必须与目标 digest/profile 兼容并返回 loaded read-back。

### Plugin 门禁

manifest、tool input/output schema、最小权限、Secret Manager 引用、网络/数据范围、依赖锁定、许可证/SBOM、宿主兼容性、沙箱/进程隔离、超时/重试/幂等、health、digest、安装/卸载清理和危险权限变更。

CI 判断机器可验证事实，不能代替业务 steward、Skill owner 或 Plugin owner 判断事实、任务价值和外部系统责任。

## 6. 审核规则

- 知识结构/格式变更：至少 1 名 steward；
- 知识事实、范围、敏感等级变更：steward + 领域审核人；
- Plugin manifest、权限/凭据、宿主兼容性、health 或安装变更：Plugin owner + 平台/安全审核；
- 跨域、机密、权限和生产写入：双人审核或额外 owner 批准；
- beta/stable、撤回、退役和回滚：明确责任人和审计理由；
- 合并前重新检查 head SHA、CI 和 approval。

## 7. 权限和数据保护

Creation Session 使用 session-scoped authorization：用户只能读取当前会话授权的 source refs、drafts、测试 fixture 和外部操作；共享来源只能以只读引用访问。所有生成、提交、发布、handoff、恢复和重试都必须带 `session_id`、`idempotency_key`、`correlation_id` 和 expected `state_version`。旧会话、旧 draft revision 或旧 provider callback 不得覆盖当前状态。

Skill 只能声明能力需求，实际权限由用户、workspace、profile、tool policy、环境和运行时授权共同决定。普通 Agent 默认看不到高风险工具；工具调用必须重新校验 schema、ACL、risk 和 approval。

Git 只保存脱敏内容、Skill 源码、测试和引用；WeKnora 按文档、空间、用户和业务域过滤；Secret 通过受控 Secret Manager 提供，不进入 Prompt、Skill、Git、Memory 或 trace。

## 8. 审计

发布、交接、消费、反馈、权限变更、索引、审批、回滚和反馈至少记录：`event_id`、`merge_commit_sha`、`outbox_operation_id`、`job_attempt`、`provider_operation_id`、`invocation_id`、`attempt_no`、`requested_by`、`created_by`、`confirmed_by`、`approved_by`、`released_by`、`executed_by`、`actor_type`、`service_identity_id`、action、resource/type、version、source commit、package/pinned digest、target、TeamAI installed revision、DSH handoff/load id、runtime/outcome status、feedback reference、badcase category/status、request、reason、result、readback status、时间和 correlation。

消费事件接入必须校验来源身份、payload schema、team/asset-space、实际 Skill version/digest、幂等键和事件时间；未知 digest、跨团队引用、重复或迟到事件进入拒绝/隔离或对账流程。指标报表不得包含 Prompt、完整输出、业务原文、Token、Cookie、密码、个人敏感信息或完整 Tool Call trace。Harness 的 session/run/tool trace 由下游保管，本项目只保存必要的消费/结果/反馈引用和聚合指标。

审计必须能关联 Git MR/CI/merge event、WeKnora index job/read-back、SkillHub release/read-back、TeamAI distribution/install/read-back、DSH handoff/load、消费引用、反馈 triage、approval 和修复版本。Harness 的 session/run/tool trace 由下游保管，本项目只保存必要的外部引用。

## 9. 故障处置

- merge event 丢失：持久游标扫描经验证受保护 Git commit，对照 PG receipt/outbox 和 WeKnora；补齐已审核且范围合法的 operation，不能用未经审核的 diff 自动索引；Skill 经 canonical main 审核合并已核实时可恢复其 Git `已发布` 证据，不等异步 package/Registry 结果；扫描不全不推进游标；
- merge event 重放/乱序：按 event id 去重并校验 commit 祖先、asset ID、change kind、当前状态版本和阻断 epoch；迟到旧版只留审计；
- Git/PG/WeKnora 漂移：PG 缺审核后 commit 则补 receipt；WeKnora 缺索引先按固定目标查未知结果再决定重试；多出的/旧版可见或 ACL 漂移的索引先隔离受控查询、核外部直连并由 owner 接管，不反写 Git；
- outbox backlog 或 worker 租约过期：知识不推进 `published`，Registry/安装/加载不推进各自状态；Skill 若受审 canonical merge 已核实可保持 Git `已发布`，否则保持 `审核中` 或 `unknown/reconciling`；恢复租约后先读回再重试；
- WeKnora ingest 已调用但 read-back unknown：保留旧索引，进入对账；
- 选定 Registry 的 release unknown 或 digest 不一致：禁止向目标分发并独立对账 Registry，不把 SkillHub 标 released；经核实的 Skill canonical Git `已发布` 不回退。若仅管理员固定包 fallback，按已批准 digest、目标和人工读回独立对账，不记真实 Registry release，也不能将未合并 Skill 标已发布；
- 选定分发目标的 installed revision/digest 与 pinned digest 不一致（TeamAI 如启用）：阻断 DSH handoff；
- DSH loaded digest 与 pinned digest 不一致或状态未知：禁止运行；
- handoff 部分成功：进入 reconciling，不自动创建新版本；

## 10. 回滚

### 知识

定位错误版本 → 立即在受控入口冻结/阻断有害检索并检查外部入口 → 有权 owner 发起受审 Git 修订/退役 commit（保留历史） → 基于固定 commit 重新索引或对旧索引执行经验证的下架/隔离 → 正向版本和旧版不可见性分别读回 → CAS 更新当前可用指针、审计和复盘。旧版若仍安全且授权，正常修改的索引失败可继续提供旧版；旧版不安全或需撤权时不能等待重新索引才阻断。无法证实旧索引/直连入口关闭时保持 `unknown/manual_required`，不报告回滚或退役成功。

### Skill

停止新的 Skill release/固定包安装 → 定位旧已批准 package/digest → 若选 Registry，核旧 release/read-back；否则核管理员 fallback 的固定包与批准记录 → 恢复旧 pinned digest → 若启用 TeamAI，重新分发并读回目标；否则用受控目标安装与读回 → DSH 目标 profile/load/read-back → smoke/regression → 审计和复盘。

### 交接

停止新的目标同步/DSH handoff → 定位 target、pinned digest、installed revision 和 handoff status → 从已批准旧 commit 找到相同旧 package/digest（Registry 读回或管理员记录分别留证）→ 使用所选分发/受控安装路径恢复目标并读回 → 再读回 DSH loaded 状态、清理残留文件 → 审计和复盘。

### Plugin

定位 Plugin/package/installation/profile 版本 → 停止新调用 → 禁用或撤回 → 回到旧 digest/profile pin → health/smoke/regression → 读回实际权限和工具注册 → 审计和复盘。

取消 HTTP 请求不代表外部动作已取消；所有取消和超时都必须补查真实状态。
