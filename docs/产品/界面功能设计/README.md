# 界面功能设计：先推敲工作，再决定画面

这里是逐页讨论稿，不是[当前可视化原型](../可视化原型/index.html)的功能说明书，更不是 DSH 已实现能力清单。设计起点是：**让本团队的人在当前任务中找到可核对的依据；用过知识或 Skill 后，能报告具体失效并带到准确版本及有权处理者；经确认的修订才进入后续任务并验证结果。** Workbench 在 DSH Desktop 内承接资产协作和治理，不复制宿主对话、任务执行和业务审批。初版只设计一个团队、一个 `team-knowledge-asset` Git 仓库；不设计跨团队流通。Workbench 左侧的五个入口为「我的工作台／提炼知识&经验／打磨可复用的技能／连接业务数据源／团队业务资产大盘」；**我的工作台**拟新增由本人手动保存、回访和删除的个人 Inbox，与现有本人使用反馈及具体工作项并列；从 Inbox 提交团队候选必须针对内容、来源及团队目标再次授权。Inbox 不自动读取 DSH Session、使用反馈、Git、WeKnora 或已有本地 `knowledge-inbox/deposits/`；当前 HTML 已显示「我的工作台」和个人 Inbox 的浏览器内存暂存、查看、删除及到知识页的待核交接提示，**没有**真实保存、团队再次授权或服务端受理，刷新/模拟撤权即清空。详细权限、PG 元数据／获准加密对象存储或原系统引用的存储选择见[02 工作台](02-Workbench工作台.md)。DSH 原生对话是宿主而非 Workbench 第六个入口。原「导入材料」与「引入 Skill」仍按输入类型分开：前者用于周报／纪要的事实与经验梳理和去向树，后者直接核对团队已有或外部形成的 Skill 的有权来源、精确版本／digest、适用任务、步骤依赖与测试证据，不用先导入材料；后者不是上传、发布或安装按钮。材料可选第五步仍可把与该材料有关的 Skill 问题关联到 Skill 核对，跳过也不影响知识去向。没有独立「能力体检」页或按钮。导入获准的完整本地文件，或用篇幅、章节完整的脱敏合成材料演练；缩写不能冒充全文，格式／附件未读须报告。事实与经验分别以当前选中项待核稿／评论为桌面约 2/3、同一选中项的已有事实记录／知识准确版本对照为约 1/3；右栏随选择切换但不悬浮固定，移动端对照接在本项后，证据逐项区分已核／来源自述待核／冲突／未取得／不适用。事实梳理中数字先核指标口径，只有当前身份、用途、对象/字段、时间窗与只读 Tool 通道获授权才就地核验，不单设数字步骤。「加入知识库」以去向文件树预览来源、事实、经验、规则、报表／计划的独立路径与门禁，不给非知识内容伪造 Git 路径；第五步仅在有稳定可测 Skill 缺口时条件性比较合成 Skill 与人工写法的正常/边界/异常示例，可跳过，并非真实试跑或独立体检。指定正式版受控修订或 Skill 深层创作才按条件进入相应会话；一个入口不等于批准所有去向。入口在工作台承接，知识与 Skill 会话分别处理被核证后的分流；原生 DSH 任务仍在宿主中，不在静态原型里运行模型、子 Agent、文档解析或业务 Tool。

上表“一页”指一个需要单独核对功能逻辑的页面/视图，不一定意味着独立技术路由；**Workbench 只有五个并列一级入口**，01、12 都属于宿主，13 是跨入口骨架规格。材料导航有四步共用主路和可跳过的第五步 Skill 核对；另有独立「打磨可复用的技能」（原「引入 Skill」）输入入口，不强迫已有或外部 Skill 走材料五步。事实与经验对当前选中项评论并随项更新右侧版本对照，第四步展示去向文件树；指定知识修订和 Skill 的真实测试／受控共享仍按各自门禁处理，**不另设「能力体检」页面或按钮**。当前静态原型已用 **111 行完整虚构合成周报**、同 ID 预编排对照、第四步本地去向树及可跳过的第五步示意上述五步导航；文件选择器可在本机阅读全文读取 UTF-8 TXT／MD／CSV（≤200 KB），但仅内置示例或指纹精确匹配的文件有人工编排议题，粘贴和普通文件没有通用抽取。第四步未生成规范 Git 文件预览或独立 Tool 请求节点，真实材料不经授权核证、正式版本检索或发布；下文页名是拟议功能位置而非已实现集成。业务对象页和工作记录详情是 13 所定义的拟议视图，原型已有虚构示意、尚无真实资料接入。Tool 两个 tab 单独写，是因为**已经开放的目录**和**尚待申请的目录**不是同一种状态。讨论、提议、核对和地图虽非左侧一级入口，也分别有自己的判断任务。

## 同一任务跨页评审矩阵（拟议检查，非业务发现）

以虚构的“该用哪版清单”**作为检验线索，不作为已确定试点**。每行只标现有页面应回答的最小决定；完整原始任务、授权与结果证据尚未取得，不能将同一静态样例当作真实跨系统连通。

| 触点 | 用户此刻需要决定 | 应核依据与当前原型缺口 | 缺证时最短动作 / 负责方 |
| --- | --- | --- | --- |
| [宿主任务](01-DSH对话与任务.md)与[工作台](02-Workbench工作台.md) | 这次任务的类型、生效时点和所需业务决定是什么；若使用了资产，哪一次没帮上忙、下一步由谁核对 | 原业务系统状态、当时有权看的来源/知识版本及最小消费事件；静态对话和工作台固定个人情景不是调用或任务回执，真实成功率不可计算 | 回原系统/联系有权人；没有事件引用仍可报告最小疑点，先核来源与版本，再决定是否值得修资产，不能要求先导入资料 |
| [来源与业务对象](13-团队知识骨架与工作记录.md)、[材料/知识](03-知识创作会话.md) | 来源当时说过什么，现有判断是否在此任务可用，真的有增量吗 | 原件版本、时间与 ACL、事实的时效、知识准确版/范围和反例；原型人工议题及右栏合成对照不是权威读回 | 来源不可得就先补证或留待核线索；已有准确版则引用/改查找入口，零增量或一次性状态不沉淀 |
| [Skill](07-Skill创作会话.md)与 [Tool 目录](08-已开通Tool.md)、[待申请](09-Tool广场.md) | 稳定步骤需不需要封装；实时信息是否有权取得 | Skill 候选/精确版、测试与安装/加载/执行各自回执；Tool 目录、数据责任方和运行时授权/调用各自回执，原型均未接真实服务 | 无稳定步骤则不用 Skill；无实时访问权则回业务系统/按正式渠道申请，不能把推荐或目录当执行 |
| [讨论](04-内容讨论.md)→[提议](05-修订提议.md)→[核对](06-修订核对.md) | 哪句有问题、改哪一版、谁能确认何种范围 | 旧版锚点、原始来源及反证、特定草稿和确认资格；静态模拟确认/读回不产生正式版本 | 明确补证、拒绝、暂缓或按原业务流程处理；没有承接人显示待分派，不因提交评论自动生成发布待办 |
| [团队资产](10-资产与发布.md)与[候选地图](11-候选能力地图.md) | 下一次是否找得到、用得对、有人维护；该继续投入吗 | 资产版本/诊断候选与任务结果分开；固定资产指标和四个判断点不证明业务效果 | 由业务结果 Owner 对照同类任务及总维护耗时；结果缺失记未知，必要时改入口、保留人工或停止资产化 |

每个触点都追问权威系统、证据版本/时点/权限、反例、下一责任人和如何回任务；同一任务允许只用一通电话或原系统链接完成。业务侧授权的一手观察、人工基线与独立复核见[初版验证协议](../04-初版假设与迭代.md#真实试点前的原始素材研究和独立复核协议)。不要用矩阵完备性替代观察真实工作。

## 单入口的判别与场景评估（拟设计）

成员只表达一件事：**给出获准使用的材料，或描述在某类任务中缺少的能力**；同一入口先导入版本可定位的完整材料（或完整合成 fixture），再分别梳理事实与总结经验：每项当前待核稿与评论对照同项的已有事实记录／知识准确版本；数字口径及 Tool 逐次授权在事实梳理就地核；「加入知识库」以去向文件树预览独立路径与门禁。**拟议产品**在没有稳定可测 Skill 缺口时从第四步结束，有具体缺口时才出现可跳过的第五步「Skill 核对」；**当前静态 HTML** 始终显示可跳过的第五步按钮，仅提供合成 Skill 与人工写法对照，未核实真实缺口。没有中间独立体检分流或「已体检」成功状态；可输入文本／获准文件定位、当前任务情境与期望结果；不要求先选知识、Skill、Tool 或“是否有候选”。界面随后给出「材料可处理性与分享资格」「已有知识／Skill／Tool 在该场景是否适用」「还欠什么证据」的分层结果：来源/归档去向、已有准确版本引用或修订、新知识待核议题、已有 Skill 修订或新 Skill 设计、Tool 的目录/授权申请、仅原任务人工处理、证据不足暂不资产化。一个意图可有多个独立去向，但没有哪条去向自动批准下一条。能力缺口不等于缺知识；要求实时数据或逐次审批时不得转写为静态知识/Skill。

**场景评估卡**贯穿 DSH 复盘、工作台索引、知识/Skill 会话与候选能力地图，绑定限定任务、判断点、样本/时间窗、适用对象及场景 owner（待指派时明示）、核证责任人和最近复核时间；列出每项获准来源、具体知识 ID／版本及有效起止、Skill 版本／发布与安装加载执行状态、Tool 接口/接入和逐次授权状态、真实任务结果或缺口、反例及下一次复核/失效日期。项目负责人、材料作者、资产维护人和业务批准者不能相互代替；生效日期须来自有权依据，未知不能默认“至今有效”。每个判断按证据标「暂定／待补证／已核证可在该范围引用／失效」，场景卡的结论不替代正式资产版本状态、业务批准或实时执行结果。不能取到原件、版本、授权或调用回执时显示无法确认及负责核对者，不从无命中推断不存在。

正式路径须分别拿到来源授权和格式/锚点能力核验、已有资产准确版本和适用边界核对；知识需 Git 审核及 WeKnora 逐文档读回才算知识已发布，Skill 需指定草稿脱敏测试、指定审核与 canonical 受保护 Git main 合并核验才算 `skill.released`。包 digest 仅标识构建；可选 SkillHub/Registry release/version/digest 读回另记 `registry_released`，未知不得遮蔽已核 Git 发布。管理员固定包 fallback 仅在 Git 发布后供下游取包，本身不是发布；逐目标安装、DSH 加载、真实执行和业务结果各自取回执，不能互推。Tool 提供方及运行时授权/真实调用也须分别核对；展示每道门槛的证据出处、时点、状态及阻断/下一责任人。**当前静态原型只展示人工 fixture 和本地交互，没有真实 Tool 指标核验、合成 Skill 对比的试跑，也没有原生 DSH 或未来数字员工/员工 Agent 使用接入**；其使用归因只可标为待验证，不得把浏览、推荐、粘贴、模拟回复当引用/加载/调用。

## 导航与返回约定（拟设计）

1. **原生任务 → 自愿复盘 → 讨论确认 → 人工复制。** DSH 对话与任务为主线；任务后成员可主动调用[任务复盘 Skill](12-任务复盘Skill.md)回看步骤、现有知识/Skill/Tool 的使用证据与额外调整，逐条讨论哪些可复用、哪些仅当次处理及是否新建/更新资产。经用户核对、脱敏的结论才可复制到有权访问的知识或 Skill 创作会话。报告/PPT 等产物只在来源和分享权限获核对后，引导成员去**经验证**的团队资料库入口提交；资料入库与正式知识修订分开，复盘不会自动上传、建待办或发布。初版不依赖任务结束事件、自动卡片、插件嵌入会话或自动传参。
2. **最小线索 → 核来源 → 主动发现增量 → 对照已知。** 粘贴到 Workbench 仍是“用户提供、待核实”；只有检查可分享范围并明确提交、得到真实受理回执后才显示“已收到”。[团队知识骨架](13-团队知识骨架与工作记录.md)把获准分享的工作记录、待核项目/产品事实、描述性经验与稳定可测试的 Skill 区分开；知识创作再由产品主动识别 0..N 张候选，按有权访问的版本/边界核既有知识，只对真实缺口提问，明确无增量、重复覆盖、修订、冲突和查重不可核的去向。原件版本和事实核对另行进行，不让复盘片段冒充纪要全文或当前事实。没有资产可先记录最小化任务疑点，不伪造可评论的知识条目。未来若 DSH 提供获验证的结果卡/最小上下文深链，可优先落到具体对象；直接从左侧入口进入则按团队习惯搜索/选择项目、来源或内容。
3. **问题 → 修订 → 发布 → 展示。** 内容讨论归档线索、处理回执；修订提议确定基线与差异；核对页判定特定草稿；知识或 Skill 创作会话按类型完成正式审核、发布及目标读回；团队资产的「最新进展／全局概览／智能诊断」先进入同路由只读详情，成员主动选择补证、讨论或创作后才跨页。经批准的知识可在获授权的 WeKnora 阅读层检索并展示版本引用，Git 仍为正式版本权威；不能凭知识库 URL 嵌入异源页面或推断具体文档已索引。任何一步都不能因为前一步“完成”而自动生效。关联只在授权范围内可见。
4. **Workbench → 原任务。** 初版由成员在宿主手动返回原生会话；待导航能力验证后可保留不含对话原文的可失效返回定位，返回时 DSH 重验任务、团队和内容权限。任务关闭、链接过期或被撤权时，不恢复内容，提供宿主任务列表或受控的人工处理入口。处理结果可回访，但“问题有人受理”“知识版本已更新”“当次业务问题已解决”要分开显示。
5. **Tool 的两条路。** 已开通和广场都按提供方/数据中台目录返回的业务域及系统标签查找，服务端在本团队可发现范围内搜索、筛选和分页；从宿主或 Skill 依赖可定位已开通 Tool 详情，或去广场了解申请路径。详情参数结构不等于调用权；低风险只读试参必须由受控宿主/提供方测试通道逐次授权执行，广场不可试调。申请由外部提供方/数据责任方处理；回到 DSH 任务查询仍须宿主接入、调用身份、环境、字段/对象/用途授权、接口健康与运行时策略逐次核验。若日后展示团队调用次数，须据宿主授权回执另行做最小化 PG 聚合，不从目录浏览、试参或推荐推算。Workbench 不代发生产请求或存密钥。

人工复制的候选只带用户核对、获准分享的**最少内容**，不把整段对话或受限产物粘进团队仓库；产物仅在真实入口和授权核实后由成员另行提交为来源资料，不能自动变为正式知识。未来自动跳转若实现，也只能携带最小授权上下文：团队空间标识、源任务的可失效返回定位、资产 ID / Git 版本、段落稳定定位与文字快照（若有）、反馈类型、相关修订/问题 ID；不携带完整聊天、完整 Prompt、Tool Call trace、实时库存/价格或敏感业务原文，目的页重新授权。选区定位是待验证的交互方案，旧版锚点不能静默贴在新版相似文字上。

## 统一的状态与权威边界

- **资料/工作记录**有来源但不代表已确认；**Agent 整理/复盘原材料**是线索；**评论/任务疑点**已收到不代表已处理；**草稿修订**已提出不代表已确认；**针对特定草稿的确认**不代表已发布；**正式可引用的知识版本**还须 Git/CI、指定人审、获授权 WeKnora 逐文档读回及范围确认；**Skill 已发布**须指定审核与 canonical 受保护 Git main 合并核验，包 digest 不是发布，Registry 读回可选且另记，未知不隐藏已核 Git 发布。内容版本前台用“整理中／待核对／团队可用／已停用”，后台门禁证据不能丢；来源记录、原材料回执、Skill 安装/加载/执行各有自己的状态。当前项目分工等事实还须核来源、生效时间及业务权威；当前任务是否获批仍以原业务系统/有权人判断为准。
- 目录可见、组织开通、团队可发现、用户/服务身份获数据授权、宿主接入、运行时查询成功，都是不同事实。任何外部状态 `unknown` 要待对账，不能写成成功。
- 团队成员在能访问的范围内均可指出问题、补背景和建议；确认、审核、发布、Tool 数据调用与业务审批按各自策略授权，不按“员工/专家/管理者”拆页面。
- 初版只围绕一类低风险、证据可查的任务。真实 DSH 集成、搜索和推荐能力、接口目录及授权状态、回访链路、维护成本和收益都须验证；未经真实访谈，不以本稿证明需求或效果。
