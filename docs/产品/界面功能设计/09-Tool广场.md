# 09 · Tool 广场（拟议页面规格）

> PM 待评审设计，不代表真实广场、申请流程或任何审批/接入已实现。此页对应「业务接口目录」的“待申请”tab（原 Tool 广场），不是独立 Plugin Marketplace 或内部生产接口编辑器。返回[页面索引](README.md)。依据：[产品蓝图](../03-Workbench如何解决.md)、[初版假设](../04-初版假设与迭代.md)、[交互原型](../可视化原型/index.html)、[系统权威边界](../../方案/05-系统架构与权威边界.md)。

## 场景与目的

成员为了某任务发现外部提供方可能开放的查询能力，弄清为何本团队尚不能使用、需要谁批准/接入，而不是把目录浏览当作 Tool 可调用。广场只展示**按提供方策略允许本团队发现、但未获准作为本团队已开通能力使用**的条目；条目可见性也不是公众可见。例 `get_part_price(part_id)` 仅是虚构的采购价格只读接口示意，字段、对象和用途须由实际责任方确定。

## 页面内容

- 同一「业务接口目录」中切换：[团队可发现](08-已开通Tool.md) / 待申请；团队由服务端核验，目录来源/更新时间在结果区显示，不重复顶部团队说明。接口多时按**提供方目录自带的业务域、源系统、用途标签**展示，例如 ERP/MES/采购；多标签保留原样，缺项标“未分类/待核”，Workbench 不代替数据中台维护分类，也不从接口名推断授权。关键词搜索匹配获准展示的名称、公开用途和 ID；标签、风险、提供方可组合筛选，并由服务端在本团队可发现范围内处理分页/排序与空结果，不先取全量再在浏览器过滤。输入变化/切换 tab 时应避免旧响应覆盖当前查询；结果注明来源及最后刷新时间。加载中、零匹配、无权或目录故障不能混为一谈。
- 列表及详情：名称、稳定 Tool ID、目录标签、提供方、数据责任方、用途、输入参数 schema 与输出的获准公开摘要、字段/对象/环境限制、接口版本/风险标识、接入条件、可能依赖的 Skill、申请去向与审批责任方（可能是业务数据 owner，不固定为数仓）、当前能证实的状态。进入广场或筛选后默认显示第一条有权可见的匹配 Tool 详情；无匹配则显示空态，不能保留上一条详情。广场列表不展示“本团队实际调用次数”统计，避免把可发现误当已开通或已调用。详情重新核验权限；即便展示参数结构，也不展示真实请求值、价格/库存响应或生产凭据。
- 广场内只解释参数与使用前提，**不提供直接试参调用**；如确有经授权的低风险只读测试通道，必须先走外部审批并核实接入、身份和环境，再按[已开通 Tool 的详情试参](08-已开通Tool.md)约束处理。目录可见或“可申请”不是可调用。
- 将“目录可见”“申请意向（尚未提交）”“已在提供方流程提交/受理”“有权人批准特定范围”“技术接入/宿主运行资格”逐项显示。未知或无回执就保持未知，不能以已申请、已批准或可调用代替。
- 操作只提供获验证的外部申请入口或责任人联系方式、查看申请要求、回任务/Skill 草稿；若未来拟收集意向，显式说明仅记录意向及可见范围，不显示“提交成功/已受理”。首版不在此收集凭据或重建审批。

## 功能流程与状态

| 触发与前提 | 用户 / 系统步骤 | 状态变化与成功去向 | 失败、权限或未知去向 |
| --- | --- | --- | --- |
| 从 Tool tab 或 Skill 依赖打开广场；已验证团队及目录发现资格 | 后端按外部目录策略读取本团队可见的标签及条目，服务端搜索、筛选、分页；选择详情时重验字段可见性 | `目录加载中→可发现/无匹配可见项`；在详情识别谁负责下一步 | 无权/撤回发现资格不显示条目/摘要；目录故障与空列表分开呈现，“无法确认”可重试或联系提供方；新查询不能被过期响应覆盖 |
| 用户选择“了解申请/记录意向”；未获团队使用资格 | 系统仅在提供方已验证入口时跳转外部申请，或展示人工联系路径；若明确有内部意向登记，展示“尚未提交/非审批”；用户按外部流程递交必需材料 | `可发现→申请意向`（如有）或经**外部回执** `已提交/受理`；成功目的地是提供方流程及其回执，不是[已开通 Tool](08-已开通Tool.md) | 无申请入口/责任人未知就显示未知与核实对象；申请被拒或需补材料，在外部流程处理，不自动接入；未读回申请状态不得写成“已受理” |
| 外部审批/接入状态改变；具备可核验提供方证据 | 系统或有权人核对批准范围、团队/环境绑定及目录分类，再刷新本团队可见列表；仍需单独确认宿主接入/运行身份资格 | 外部确已对团队开放且团队可发现时，转[已开通 Tool](08-已开通Tool.md)核对详情；即使批准，DSH 实际调用仍由宿主逐次校验 | 批准范围/接入/权限回执不一致，保持“待核实/对账”；撤回或过期则停止宣称可用。不能用 Workbench 中的依赖声明制造批准事实 |

Tool 广场**不提供价格或库存查询结果**；申请、审批、技术接入和一次实际调用属于不同权威和不同状态。写入/生产高风险能力若可发现，默认仅显示受限说明和单独治理要求，不提供试调用快捷键。

## 跨页路径

从[工作台](02-Workbench工作台.md)的 Tool 入口进入；从[Skill 创作会话](07-Skill创作会话.md)的“外部能力需求”或[候选能力地图](11-候选能力地图.md)的“缺实时数据”进入本团队可发现的指定条目；返回草稿或判断点只携带获准公开的引用/需求状态，不能填入假授权。后续确证开放才到[已开通 Tool](08-已开通Tool.md)，实际任务查询在[DSH 对话与任务](01-DSH对话与任务.md)且须运行时核验。[团队资产](10-资产与发布.md)只读展示知识/Skill 与获准公开的 Tool 依赖引用，不负责 Tool 审批或发布。

## 访问与数据边界

每团队的目录可见范围与团队 Git 资产范围分别核验，不能因另一个团队已开通就向本团队暴露目录详情、授权或数据。Tool 由外部系统/数据平台供给，提供方负责接口和目录策略，数据责任方批准使用范围，宿主管理运行身份、工具策略与实际调用；Workbench 不批准或保存生产接口、业务数据、请求字段值、生产凭据和 Tool Call trace。目录引用与申请意向若需要留存，只保留授权处理所需最小元数据与外部回执引用；业务写操作另行治理。

## 与当前原型的差距及待确认

原型用多条**虚构目录**示意广场的关键词搜索、数据中台标签、列表与参数结构；采购价格条目的“模拟记录申请意向”仍只记录浏览器内存里的**申请意向**，未提交、未受理、未获批。广场无真实申请链接、可执行试参、目录或授权读回，页面刷新重置，不能用它证明提供方会开放价格字段。

- 实际目录来源、发现策略、可公开字段和责任方如何确认？若目录不可接入，是否只给经核实的原系统入口？
- 哪个外部流程给出申请/审批/撤回的可验证回执；无法取得回执时是否完全不展示申请进度？
- 获批给团队与获批给个人/服务身份、宿主接入各由谁核实并更新分类？
