# 08 · 已开通 Tool（拟议页面规格）

> PM 待评审设计，不代表目录、接口或宿主查询已接入。「业务接口目录」是 Workbench 的独立入口；此页对应“团队可发现”tab（外部目录已对团队开放的 Tool），不是知识/Skill 发布页或审批后台。返回[页面索引](README.md)。依据：[产品蓝图](../03-Workbench如何解决.md)、[初版假设](../04-初版假设与迭代.md)、[交互原型](../可视化原型/index.html)及[权威边界](../../方案/05-系统架构与权威边界.md)。

## 场景与目的

本团队成员要确认某个外部查询能力的用途、来源、数据范围、Skill 依赖与实际使用前提，再回当前任务判断下一步。**“已开通”仅指组织已开放且该团队按外部目录策略可发现**，不意味着本用户/服务身份获数据权限，也不证明宿主已接入或接口此刻可用。初版可以是获准引用的目录信息和外部入口，不承诺自建 Tool 目录/网关/审批或生产接口。

## 页面内容

- 团队/资产空间由服务端核验，不要求在目录页顶部重复展示横幅；入口「业务接口目录」下为“团队可发现 / [待申请](09-Tool广场.md)”两个 tab，默认不混入[团队资产](10-资产与发布.md)。加载失败/目录不可确认不能显示“没有 Tool”。
- 大量接口以**搜索 + 紧凑列表 + 详情**承载，按外部数据中台/提供方目录返回的业务域、源系统、用途等标签筛选与分组，例如 ERP、MES、采购；同一接口可有多个标签，不要求它们互斥。标签展示来源、版本与更新时间；缺标签标“未分类/待核”，不从名称自行推断。只对当前团队允许发现的目录范围做服务端搜索、筛选与分页，保留筛选条件及返回列表的位置；不把所有条目加载到浏览器再过滤。进入 tab 或搜索/筛选后，默认展示当前**第一条有权可见的匹配 Tool** 的详情；手动选择的 Tool 若仍在结果中则保留，已不匹配时回到第一条；确实零匹配时右侧给明确空态，不保留旧详情。加载中、确实无匹配、失权、目录故障/状态未知须分开。例 `get_product_inventory(product_id)` 为**虚构只读示例**，不是现有 ERP 集成。
- 列表展示名称、稳定 Tool ID、业务域/源系统标签、用途、提供方、只读/写入风险、目录状态与更新时间；点击查看详情。详情从提供方接口读取获准公开的参数 schema（必填/类型/约束）、返回摘要、对象/用途和时效限制、接口版本、数据责任方、接入/申请去向及相关 Skill 依赖声明；并列四个不同事实：“目录可见/组织开通”“团队接入”“当前身份与字段用途授权”“宿主运行时健康/可调用”。各项注明来源、最后核验时间和未知项；不能凭一个绿标签推出其余三项。
- **详情试参（受控设计，不是目录授权）**：仅当提供方明确允许且为低风险只读接口、具备受控测试通道时出现可执行入口；先标测试环境（优先沙箱/脱敏数据），再校验当前身份、团队、环境、用途、字段与对象范围、宿主策略及速率/配额。提交和结果由宿主/提供方执行及审计；未知、失权、写入/高风险接口或广场条目只展示参数结构与申请去向，不给试调按钮。测试结果注明来源、请求环境与时间，不与真实任务值或业务审批混同。Workbench 不存生产参数值、凭据、原始返回值或完整 trace。无法建立测试通道时仅提供“回 DSH 任务/查看提供方资料”路径，不能由前端直接请求生产接口。原型中只有 ERP 库存详情有可展开的**本地试参情景**，用来切换固定脱敏测试按钮的演示条件；它不是整页的“接入状态”，不改变目录、其他 Tool 或真实权限。
- **本团队调用量（可选、后续）**：在**已开通列表的每条 Tool** 下直接显示该 Tool 的本团队实际成功调用次数、时间窗及最后同步时间，原型无证据则逐条显示“暂无法统计”，不另占一块汇总面板；广场未开通条目不显示调用次数。目录主数据仍由外部 API 提供，统计不反向决定目录分类/权限。如确有授权的宿主实际调用回执且团队有权查看汇总，可在 Postgres 只存 `team_id + 稳定 tool_id + 时间窗 + 成功调用数 + 去重水位/来源与最后同步时间` 这样的最小化聚合；试参、失败/未知、页面浏览和推荐另计或不计，不冒充成功使用。事件须按稳定 ID 去重，并处理迟到、撤权及重新分类；原始调用审计归宿主/提供方。权限、回执或同步不可核验时显示“暂无法统计/最后核实于…”，不显示假 0；小样本能反推敏感调用时隐藏/合并，不做个人使用画像。是否值得落 PG，待确认调用事件接口、团队粒度与留存策略后再定。
- 提供“查看提供方资料/申请去向、回 DSH 任务、查看依赖 Skill”；若未验证外部申请链接，显示责任方和人工办理路径，不伪造审批按钮或查询值。

## 功能流程与状态

| 触发与前提 | 用户 / 系统步骤 | 状态变化与成功去向 | 失败、权限或未知去向 |
| --- | --- | --- | --- |
| 打开 Tool→已开通；服务端已确认本团队及目录发现资格 | 后端按提供方目录策略取本团队可见的条目、标签和最后更新时间；服务端处理搜索、标签筛选、分页，详情重验可见性与字段范围 | `加载中→可发现/无匹配可见项`；保留搜索/筛选与列表位置，可选详情或[Tool 广场](09-Tool广场.md) | 未绑定/无权不展示名称或摘要；目录超时显示“目录状态未知”及重试/联系提供方，不能当零条；撤回可见性后隐藏详情与统计 |
| 在详情点“核对使用条件”；有权查看该条目 | 系统分开展示外部目录开通、接入、数据责任方授权和宿主运行校验；用户查看输入/输出和限制，选择按提供方流程申请或回任务 | `组织开通/团队可发现→待使用资格/待接入/已确认前提` 等**并列状态**；回[DSH 对话与任务](01-DSH对话与任务.md)仍须在宿主就该次调用重新校验 | 申请未提交/审批未读回只记“待申请/待核实”，不标已批；接入或权限被拒则展示去向，不在 Workbench 绕过外部决定；健康状态未知时禁止声称可调用 |
| 在 DSH 任务选择实际只读查询；外部接口已接入 | 用户主动发起；宿主验证运行身份/服务身份、环境、工具策略、数据字段与对象用途、审批及接口健康；仅授权后调用并显示有来源与时间的值 | `未查询→运行校验通过→查询成功/失败` 属 DSH/外部系统，不是此 tab 的开通状态；成功返回[DSH 对话与任务](01-DSH对话与任务.md)，仍不得代替业务审批 | 无权、未接入、查询失败、超时或状态不明：不返回伪实时值，提示申请/原系统核对/人工处理；禁止用历史知识填“当前值” |
| 在详情试参；提供方允许低风险只读测试且当前身份通过全部运行校验 | 宿主/提供方展示参数 schema，标明测试环境；执行前重新验证身份、团队、接入、字段/对象/用途、健康、配额和审计要求 | 由受控通道返回可展示的测试结果，明确环境、来源及时间；不增加真实任务成功调用数，若需试参统计另列 | 广场、写入/高风险、权限或健康未知时无试调入口；失败/超时不以旧结果替代，也不保存敏感参数或原始返回值 |
| 展示列表内可选团队用量；存在获授权的真实调用回执 | 按稳定 Tool ID 与团队、时间窗做最小聚合和事件去重；统计服务可读取 PG 聚合，标注来源、成功口径与最后同步时间 | 在对应已开通 Tool 列表项内展示有权查看的团队汇总，不把试参/浏览/推荐算成调用，也不推断个人绩效 | 回执缺失、权限不明或同步失败逐条显示“暂无法统计”；小样本隐藏/合并，不能用 0 掩盖未知 |

上述状态不构成单一逐级“开通→可用”流水线：目录权限、团队接入、数据授权和运行健康可独立变化。写入类 Tool 不能沿用只读示意的按钮或门禁，需另行设计执行约束。

## 跨页路径

[工作台](02-Workbench工作台.md)通过独立 Tool 入口到此；从[DSH 对话与任务](01-DSH对话与任务.md)的查询前提或[Skill 创作会话](07-Skill创作会话.md)的能力需求链接到指定目录条目，返回时保留任务/草稿位置；依赖关系仅供核对。未开放/待申请能力转[Tool 广场](09-Tool广场.md)，已开通条目不因一个人的申请意向而改变。涉及“当前事实”的判断点可从[候选能力地图](11-候选能力地图.md)进入此详情；不经过知识的[内容讨论](04-内容讨论.md)、[修订提议](05-修订提议.md)或[修订核对](06-修订核对.md)来授予 Tool 权限。

## 访问与数据边界

团队资产仓库只保存获准公开的目录引用与 Skill 的版本化依赖，不拥有外部生产接口、实时数据、密钥或批准权。目录条目可见性以外部提供方策略为准；团队成员身份与资产访问不能推导数据字段的权限。提供方负责接口和接入，数据责任方负责用途/字段/对象许可，宿主负责每次用户或服务身份、profile 与工具策略核验；任务业务决定仍在业务系统/有权人。无权来源不可通过名称、摘要、关联 Skill 或聚合统计间接泄漏；不存查询值、敏感参数、凭据或完整 Tool Call trace。

## 与当前原型的差距及待确认

原型用多条虚构 ERP/MES 等目录条目示意标签分类、搜索、列表与默认首条详情；已开通列表逐条显示“本团队实际调用次数：暂无法统计”，没有独立用量面板。仅 ERP 库存详情有固定脱敏参数的本地模拟试参及可展开的情景按钮；它们只切换此处测试按钮是否就绪，**不是接口接入/授权事实**。原型没有外部目录、PG 汇总、真实授权/健康读回或宿主调用，不能把本地试参计入真实调用。DSH 中手点出的固定虚构库存值也不是 ERP 调用；宿主任务的演示查询状态和本详情的试参情景彼此独立。

- 哪个外部目录及提供方政策允许本团队发现哪些字段、名称和关联 Skill？不可发现时如何解释而不泄露？
- 初版是否仅给提供方入口；接入、授权、健康和状态读回分别能否获取，无法获取时如何保持“未知”？
- 只读查询失败与过期的时效阈值由谁定义，写操作是否完全不在首版范围？
