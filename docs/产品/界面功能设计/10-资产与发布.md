# 10｜团队资产：最新进展、全局概览与智能诊断

> 页面位置：Workbench 左侧一级入口「团队业务资产大盘」。这是团队内容的**只读展示、查找与创作引导页**，不是个人待办或审核/发布操作台。知识与 Skill 的确认、审核、发布及读回仍在各自创作会话。以下为拟设计；[原型](../可视化原型/index.html)的数字、事件和资料摘要均为虚构示例。

## 入口与共同规则

- 老成员想知道团队本周有哪些**项目/产线事实进展与知识资产变化**、当前有哪些可用知识和 Skill；新成员想沿业务/产品、项目、职责、经验、Skill 认识团队；成员发现待核的分工或适用边界时可选择补证、讨论或创作。
- [工作台](02-Workbench工作台.md)只呈现与当前成员有关、仍有效的具体行动及其关注进展；浏览资产或打开详情**不会**创建我的待办，也不应以「看详情」先跳工作台。
- 三个 tab 共用团队资产路由和**只读详情层**。切换 tab 保持所在团队；详情关闭后回到原 tab 及筛选/所选项目上下文。按当前身份、团队、对象、来源和版本过滤列表、事件、正文及深链；撤权时清空可见详情与缓存。没有核实权限或数据时显示“暂无法统计/无法核实”，不能显示虚假的 0、受限标题或可反推个人的信息。
- 来源记录、事实、经验知识、Skill 属不同对象；项目与产品线只是查找轴，同一知识关联多个对象仍按资产 ID 去重。正式知识以受控 Git 审核版本为权威；索引命中不自动证明该版可用。

## Tab 1｜最新进展（默认）

首屏按**知识 / Skill / Tool** 三组展示本团队存量与本周变化：可用知识、可用 Skill 与团队已开通 Tool 的总量为大数字；下方小数字显示正式发布/更新（Tool 为开通）数量、对应的引用/执行/调用次数以及使用人次。知识阅读和引用、Skill 安装/加载/执行、Tool 浏览/试参与授权成功调用须区分；同一对象按稳定 ID 去重，同一版本重复读回不重复计发布数。次数、人次应由有权服务端在明确时间窗内汇总使用证据，而不是由浏览、推荐或本地按钮推导。原型用固定虚构样例展示排版，知识 128 篇、Skill 24 个、Tool 36 个只在最新进展展示；并未接入实际用量回执。Tool 的逐条实际调用次数仍在「业务接口目录」的团队可发现列表内，待申请列表不显示；此处仅为团队层面跨资产概览，不替代按接口归因的明细。正式产品需标自然周、团队时区、可见范围、来源和刷新时间；无可靠证据显示“暂无法统计”，小样本按权限聚合/隐藏。

指标下方分为两列：**项目 / 产线进展**把获授权工作记录、业务材料及权威系统状态梳理为有来源、版本、生效时间的阶段成果、当前事实、风险线索和有依据的后续安排；**团队经验 / 技能更新**展示知识修订、正式发布、Skill 草稿及实际复用的变化，相关 Tool 变化可纳入。左侧业务事实不能仅凭会议说法确认为当前状态，右侧候选、确认、合并、发布及目标读回不可混写；已有可用旧版不会因新草稿消失。每条以时间/对象/阶段/简要结论高密度呈现，标题或正文的**文字本身可点击**，进入团队资产内的只读详情，而不是额外摆放“看只读详情”按钮。详情仍须展示具体 ID/版本、证据引用、最近核实时间和下一步去向；外部 `unknown` 待对账。

**与团队周报的关系**：项目/产线的业务成果、风险和事实本来就可以从原材料中经授权、核实后整理出来；知识/Skill 的变化可作为资产进展引用，计划有可信依据时再加入，不必为了凑栏目强行推断。此页可以服务于周报或成为周报的信息入口，但不能把未经核实的资产事件当成业务成果或替代业务侧确认与审批。页面顶部已经标明概念稿，卡片中不重复堆砌免责声明。

## Tab 2｜全局概览

**概览不是第二个数据看板，也不是把知识目录、版本列表和 Wiki 拼在一起。** 它先回答“团队做哪几类工作，项目怎样跨产品线协作，哪些经验和 Skill 已沉淀、适用到哪里，还有哪些关系待核？”统计与时间事件留给「最新进展」，逐判断点核验限定任务的能力地图另见[候选能力地图](11-候选能力地图.md)。这里的业务与能力版图**不计算全团队能力覆盖率**。

默认展示整个团队的**产品线工作主题 × 项目工作主题**及交叉处的关系：项目和产品线是正交轴，一个项目可关联多个产品线，不强制归属唯一一条线。每个交叉处说明是什么协作主题、关联依据还是待核候选；未登记的关系不等于业务上不存在。下方把可复用经验和 Skill 按稳定 ID / 版本作为**唯一能力节点**展示，标明关联范围、适用条件和发布 / 运行证据。K-01 v1 同时与项目 A 和产品线 P 关联，仍只是一份受控版本，不在两个对象下复制成两份权威知识。尚未发布的修订与可用旧版分开，Skill 发布、目标安装、加载和执行也分开；灰显或没有相关能力仅表示在当前可见证据中无已核关联，不作缺失或不可用结论。

选择一个项目或产品线只**高亮其关联、保留全队上下文**，在同页展开简短概述、相关经验 / Skill 及历史出处；再点具体对象或资产进入团队资产的精简只读详情。概述须标范围、阶段、已核事实与有效时间、待核问题，不能仅凭占位关系推断当前进展。真实服务按团队、对象和逐条来源 ACL 过滤节点、关系及摘要，缺权时连可推断的标题也不展示；来源不可达显示“无法核实”，不能把空白解释为没有业务关系。

会议纪要、旧周报、交接材料是**历史来源**：只有核对来源、生效区间与权威状态后，才能把里面的陈述整理为当前业务事实；周会提及“某人接手”不会自动成为当前负责人或系统审批权。深层原文默认留在有权原系统；只有 WeKnora 已独立托管对应来源文档并经授权/精确映射，才从概览跳外部阅读，概览不复制全文、不做另一个 Wiki。

### 历史文档如何衔接 WeKnora

**用户动作（仅在目标已核可用时）**：在项目/产品线下看到历史来源，先查看来源的最小元信息；若确认这份原件确实由 WeKnora 独立托管、指定文档和版本可核且有权阅读，才显示「在 WeKnora 阅读 ↗」并在新页面打开该来源文档，由目标服务重新验证登录/访问资格。WeKnora 仅有正式知识索引或没有来源文档映射时，展示有权的原系统定位/人工核对路径和「原文未接入／无法核实」，不借正式知识页面伪装原文。Workbench 不内嵌全文或自建持久原文阅读器。知识版本的正式文档如获准索引，可按独立的知识 ID/版本映射跳到精确阅读位置；它不证明原始来源也在 WeKnora。Skill 详情仍在团队资产 / Skill 创作流程，不把它放进 WeKnora 管理。

**显示条件**：服务端须建立并核对团队/对象/来源 ACL、来源文档 ID/版本与 WeKnora 来源 document ID/version、阅读资格及真实逐文档深链；知识阅读另须核对 Git `knowledge_id/version/source_commit/repo_path` 与 WeKnora 正式知识 document/index version、检索读回及 ACL。来源被索引不等于知识已发布。未完成映射、失权或状态未知只展示可安全展示的来源摘要/“原文未接入”，不渲染虚假深链。Wiki 派生页及其页面关系图不是 Git 正文或业务实体关系图谱；只读详情仅在相应来源、权限和版本可核时给出派生入口，不把未核实体边写成项目当前事实。用户提供的知识库 URL 目前只能确认前端外壳和 `X-Frame-Options: SAMEORIGIN`，尚无登录后文档 ID/深链，因此原型**不打开该 URL、也不伪造 S-01 或 K-01 的 WeKnora 入口**。

## Tab 3｜智能诊断：AI 巡检雷达（目标设计，尚未接入）

前两个 tab 分别回答「最近发生什么」和「某个业务对象能找到什么」；智能诊断主动提出**成员尚未发起的问题线索**，不等用户先评论或创建修订。正式产品在本团队授权范围内，按获准来源变化、受控版本/复核时点和可核验的运行信号增量巡检；页首标明纳入哪些对象和来源、最近一次**成功**巡检时间、未接入或不可达的来源。能否人工重试由实际接入和限流策略决定，未执行扫描不能伪装成“实时无异常”。

| 发现类型 | 触发前提与对照方法 | 展示与建议动作 |
| --- | --- | --- |
| 事实/规则说法冲突候选 | 同一业务对象、字段或判断问题、相交的任务范围与生效区间，出现不同来源或正式版与获准后续来源的不一致；对照来源 ID/版本、出处、形成及有效时间，先查权威状态 | 并排给出两个可访问的说法及待核的共同范围；让成员补来源、核有效期、讨论或针对指定知识版修订。两个时期/不同任务的说法可并存，不直接宣布“当前事实冲突” |
| 进展更新待复核 | 该对象事先有**约定的更新节奏或复核期限**；到期后核对权威来源的最近成功读回、状态时间及变更。没有期限、读回失败或原系统不可达时只能报「无法判断/待核验」 | 指明约定期限、最后可信记录、扫描时间和缺少哪次读回；引导核现状、补有权来源或约定下一次复核。不能从文档沉默推断业务停滞 |
| 业务流衔接缺口候选 | 先限定一类由团队梳理过的业务流及关键判断点，关联知识边界、Skill 的版本/测试/发布/安装/加载/执行回执、外部 Tool 接入/调用资格和必须由人判断的节点，查缺失的证据或不可衔接的步骤 | 具体到任务和步骤说明「缺执行证据」「需获准实时数据」「本就逐次人工判断」等不同情形；引导核 Skill 依赖、补证、核 Tool 前提或保留人工路径，不把“已推荐 Skill”“目录有 Tool”当成流程跑通 |

每条发现的详情沿「**AI 观察 → 可见证据与版本/时间 → 尚不能证明什么 → 建议下一步**」组织。真实服务应按团队、对象与逐条来源 ACL 过滤发现和关联标题；权限丢失或来源无权时不展示可反推敏感内容的摘要。用对象/判断点/有效范围与来源版本关联重复线索；人工可标待补证、不适用、暂缓并记录范围/理由，新证据/来源恢复后重新评估而非静默覆盖旧反馈。AI 只发现**候选**，经人核查才可能形成当前事实、正式修订或有责任人的事项；确认、发布、Skill 安装或 Tool 调用仍各有门禁。没有明确承接者不自动进入个人工作台，也不以数量、调用人次或处理速度给团队/个人评分。[候选能力地图](11-候选能力地图.md)可用于查看限定任务的判断点，但不是「自动算出全团队覆盖率」。

## 共用只读详情与明确分流

事件、业务对象、来源、具体知识版本/修订、Skill 和巡检候选统一先进入团队资产内的**精简只读详情**：对象 ID 与类型、版本/阶段、适用及截至时间、权威与可见来源、未决问题、与其它版本的关系和最后核实时间；巡检候选还须区分实际扫描批次、缺失的证据与人工反馈状态。长篇历史原文在对应来源获准访问且文档级映射就绪时跳 WeKnora，不在详情复制一份虚构 Wiki 正文。Skill 的指定版本另列：任务适用与旧版关系、维护人、契约/依赖及其固定版本、绑定草稿修订的测试证据；正式版须有 Git/CI/有权审核及 Skill 在 canonical Git 受保护主分支的 merge commit 核验证据；固定 package digest 与选用时 Registry release/read-back 是另列的后续证据，不能因无 Registry 回执抹掉已核实的 Git 发布，也不能从 Git 发布推断包已构建或目标已可用。目标分发/安装、DSH profile 加载、真实执行的技术/契约结果与业务结果按环境、时间和同一 digest 分开展示权威回执或“未知”；当前版本的草稿缺项不能抹掉旧可用版本。这里依[Skill 分层质量判断](07-Skill创作会话.md#一条-skill-的分层质量判断拟设计不是单项评分)解释证据而不重新审核，也不把单次执行成功当作 stable。不能把关联来源当成已核事实，也不能把目标外部 `unknown` 当可用。

详情里的「继续处理」是**与阅读分开的明确动作**：讨论/补证到[内容讨论](04-内容讨论.md)或相应来源/业务对象的核证会话；修订经验到[知识创作会话](03-知识创作会话.md)并定位精确基线；已登记团队正式 Skill 从可访问的资产版本明确进入[Skill 创作会话](07-Skill创作会话.md)，**由选择动作带入**准确 ID/revision，成员不手填 ID；外部形成的 Skill 不在团队资产里冒充已有版，只从独立「打磨可复用的技能」入口带来源定位进入。仅有稳定步骤的记录是工作流候选，不因位于资产详情就有 Skill 正式 ID；当前业务数据与 Tool 授权到[业务接口目录](08-已开通Tool.md)及原系统。真实目的页重新核验身份、团队空间、来源 ACL、对象 ID、版本基线及动作权限；Skill 正式版详情只交接所选准确资产 ID/revision、待核适用条件与最小缺口，草稿只交接自身草稿定位，不能把“浏览过”或资产页汇总状态带成测试通过、创作资格或实际加载；其它对象也只交接最小授权定位/待核问题，不带受限原文、完整对话、Prompt、Tool Call trace 或生产数据。没有可安全定位的目标时停留在详情并说明原因，不跳个人工作台。确认、审核、发布、读回和对账只在对应知识/Skill 的创作会话中完成。

| 想做什么 | 本页怎样引导 | 不能误读什么 |
| --- | --- | --- |
| 浏览周变化与正式版本 | 三 tab → 团队资产只读详情 → 返回原 tab | 浏览不派单；Skill 已发布须核受保护 canonical Git merge，知识 published 另需 WeKnora 读回；目标可用另核安装/加载与权限 |
| 补来源、核事实或经验 | 详情 → 主动选择对应来源/业务对象核证或知识讨论/修订 | 来源说过不等于现在成立；贡献不等于有确认权 |
| 封装稳定步骤 | 详情 → 明确发起 Skill 创作会话 | 草稿、发布、安装、加载、执行各自独立 |
| 确认修订、正式审核、发布与读回 | 详情只展示状态；实际操作在类型对应的创作会话 | 不能在资产页直接变更权威版本或绕开门禁 |

## 权限、原型与验证边界

统计、进展、巡检发现及关联证据、项目名称、来源摘要、职责关系、Wiki 内容和深链都须在团队/对象/原件来源 ACL 交集内服务端过滤；权限撤销清除缓存，小样本汇总防推断。来源不可达、数据缺失、真实 0 与同步中断分别显示；保留最后核实时间。团队 Git 不存受限原文、生产凭据、实时库存/价格、客户信息或完整会话/Prompt/Tool Call trace；业务系统负责实时状态和审批。

**原型仅示意**三 tab、最新进展的固定虚构指标与双栏精选条目、全局概览默认同时呈现项目 A/B/C 与产品线 P/Q/R 的关系版图和按版本去重的能力落点、智能诊断的**三种固定模拟巡检线索与本地反馈**、统一只读详情与显式创作分流；不展示重复统计或 Wiki 正文。B/C、Q/R 和多数交叉关系是待核的布局占位，不是核准业务归属或能力覆盖；只有 A/P 的部分示意关联有既有演示来源。模拟巡检没有扫描任务、真实来源读回、真实 ACL 或宿主运行回执，不能证明 AI 已发现本团队问题。没有任何真实文档级 WeKnora 映射，所以历史资料仅显示原文未接入、没有可点击的外部深链。原型不接团队仓库、WeKnora API/登录、Git/CI、Provider/SkillHub 或真实权限。**待验证**：真实团队业务对象与跨线关系、实际文档/版本映射与跳转、对象查找习惯、指标口径与真实调用/引用回执、周报取用、巡检候选的准确性和处理价值。
