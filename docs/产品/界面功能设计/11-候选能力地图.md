# 11 · 候选能力地图（拟议页面规格）

> 这是无真实访谈时用于评审的一类任务的**候选**梳理，不是团队盘点结果、组织能力覆盖率或绩效看板。作为 Workbench 的任务/资产内页，不按管理者身份另开导航。返回[页面索引](README.md)。依据：[产品蓝图](../03-Workbench如何解决.md)、[初版假设](../04-初版假设与迭代.md)、[交互原型](../可视化原型/index.html)、[信息架构](../../方案/09-工作台信息架构与核心对象.md)。

## 场景与目的

本团队获授权的负责成员在**一类限定任务**中人工列出关键判断点，判断“现有依据是否可用、谁维护、下一步该做什么”；其他有权成员可查具体判断点并去资产位置补背景/证据。地图促成补证、限定范围、申请外部 Tool、改善入口、安排维护或明确逐次人工决定，不自动将知识条数、Skill 推荐、Tool 列表或一次试跑转成能力成熟结论。示例“核对交接资料：清单适用/例外升级/任务实时状态/临时审批”均为虚构，不能当本团队真实任务承诺。

## 页面内容

- 顶部：本团队与资产空间、任务名称/典型情境、梳理人及日期、限定分母“本次梳理的任务与判断点”、来源与验证状态；未知项显式显示，未核实不能标“已覆盖”。
- 判断点列表：判断问题、适用范围、当前归类（有人会但没依据/只有资料/已确认特定版本/范围不清或过期/找不到或无权用/缺维护人/缺真实结果证据/需要外部实时查询/本就逐次人工决定/未知）、下一步责任人与回访点。分类允许多个并存，不合成单分数。
- 点开侧栏：仅展示当前身份有权看的 Git 资产路径/版本和来源、确认与复核范围、关联[Skill 创作会话](07-Skill创作会话.md)中的步骤/依赖（不是已加载状态）、外部 Tool 的提供方/接入/授权前提、反馈及修订状态；并列“真实任务结果证据、依据可靠性、能否被本团队其他有权人复用、维护容量、投入是否值得”，缺数据写未知。
- 可执行动作：去对应版本选区评论、补证/发起修订、请有权人确认、核对 Tool 接入、标记需逐次人工处理、约定复核；动作能否执行按当前判断点与来源权限显示，地图本身不授予审核权。

## 单判断点的场景评估卡合同（拟设计）

地图以工作台的**同一材料／能力意图**所关联的限定任务判断点为单位，一份输入可指向多个判断点；仍由有权负责人划定范围/分母，不自动从文件或聊天抽取“覆盖率”。每张卡显示：任务情境、判断问题/预期结果、对象与起止时间、样本/观察窗；场景 owner、知识/Skill 维护 owner、核证责任人及有权业务决定者（分别列明，未知则待指派）；来源/版本、材料授权和本场景格式解析/锚点/未读范围；最近核实、下次复核、有效/失效依据；正反例、真实任务结果/缺口、下一项证据与动作。人员历史分工、文档作者与业务批准权不能互推；失效/撤权后停止按旧范围推荐，待重新核证。

| 证据列 | 卡片如何判断与归因 | 不足时的状态 |
| --- | --- | --- |
| 知识 | 可访问的 Git ID／准确版本、来源/适用及有效时间、正式审核与 WeKnora 逐文档读回；原生 DSH 真实引用事件另列 | 资料或提及、无版本/授权/引用事件只能标待核，不计已用 |
| Skill | 按[创作会话的分层判断](07-Skill创作会话.md#一条-skill-的分层质量判断拟设计不是单项评分)关联具体判断点：任务值不值得封装及适用旧版；有权 ID/准确版本/digest 与来源；触发/输入/输出/异常/停止契约、固定知识与 Tool/effects 依赖、owner；指定修订真实脱敏测试的期望/实际断言；指定审核与 canonical 受保护 Git main 合并核验决定 `skill.released`，package digest 只标识构建；可选 SkillHub/Registry release/version/digest 读回单列 `registry_released`（未知不遮蔽已核 Git 发布）。逐目标安装、DSH 加载、执行及技术/契约/业务结果另列对应环境、时间与回执 | 缺来源/版本写未知并补证，不称“没有 Skill”；仅有合成比较、推荐、测试样例或发布均不能推定安装、执行或业务成功；具体缺陷修订指定版，逐次裁量保留人工 |
| Tool | 接口目录与提供方、接入环境、对象/字段/用途授权及运行时真实调用回执、结果时点 | 目录可见/申请/试参不等于已获调用权限或成功查当前值 |
| 来源/场景结果 | 原件定位及授权、文件/附件格式能力及覆盖范围、业务权威当前事实、任务结果/反例 | 不能访问或无法解析写未知及责任人，不填“无证据即不存在” |

卡片阶段为「暂定 → 待补证/待裁定 → 限定范围内已核证」，也可能「不适用／已失效／不资产化」；每个结论附证据来源、有效时间及责任人。**已核证场景判断不等于知识已发布、Skill 已执行或业务任务已成功**；正式资产状态仍按各自门禁与精确版本展示。证据门槛先核材料资格与本场景解析，再核已有知识/Skill 的版本、有效范围及 QA，再核测试/审核/目标读回，最后才看宿主真实引用/加载/执行和有权 Tool 调用及任务结果。阻断可转补证、现有资产修订、Tool 提供方申请或逐次人工处理；未知的外部回执先对账，不能自动变为成功。原生 DSH 及未来数字员工使用证据均尚未接入本地图；静态原型的四点 fixture 不运行模型、子 Agent 或 Tool，不生成正式场景卡或真实覆盖统计。

## 功能流程与状态

| 触发与前提 | 用户 / 系统步骤 | 状态变化与成功去向 | 失败、权限或未知去向 |
| --- | --- | --- | --- |
| 从工作台/资产进入；团队资产空间已绑定且获授权查看候选任务 | 服务端按团队、资产与来源 ACL 读取本次人工梳理的任务和判断点；显示数量及梳理范围 | `加载中→候选地图/本范围尚未梳理`；选择判断点查看证据 | 无权不得看到无权来源内容或可推断摘要；加载/来源不可确认不能显示零覆盖，提示重试/联系负责成员 |
| 点击一个判断点；有权看其证据 | 人核对关键判断、来源版本/适用条件、实际任务结果与维护人；系统分开列“已确认”“仅资料”“需人工”“未知”等证据状态 | `待梳理→候选归类→待业务负责人核对`；确认后仍仅代表该判断点在**已限定范围**内的候选结论 | 来源冲突、旧版过期、无可见证据、Tool 状态不明时保持未知/待核对；不得推定“不存在知识”或引用未经确认的总结 |
| 选补证、修订或维护安排；拥有目标资产的对应动作权限 | 系统保留任务/判断点与版本上下文，用户跳对应页选区评论、提出候选修订；有权负责人决定缩小范围、安排人或保留人工路径；回访后再核对 | `发现缺口→已分派/待补证/待确认→有处理结论`；成功回到判断点显示**受理、确认、正式发布**各自证据，不自动称业务已改善 | 无锚点可留任务疑点；无 owner 则待指派/升级，不能假称已转交；修订失败/发布未知留原状态待对账，旧版评论需人工核对重定位 |
| 选“需要当前数据或逐次审批”；目标 Tool 条目有可发现权 | 查看[已开通 Tool](08-已开通Tool.md)或[Tool 广场](09-Tool广场.md)的前提；当前任务继续在 DSH/原业务系统由有权人处理 | 判断点记为“依赖外部数据（授权待核验）”或“逐次人工决定”，不把它算知识缺口；回到[DSH 对话与任务](01-DSH对话与任务.md) | 无接口、无权限、失败或状态未知时回原系统/人工，不提供伪实时值；申请意向不改变状态，不能替当前业务审批 |

正式知识只有经 Git 审核、CI、人类批准及获授权 WeKnora 逐文档读回后可按版本引用；Skill 已批准未合并仍审核中，指定审核且 canonical 受保护 Git main 合并核验才为已发布；Registry 读回可选且另列，管理员固定包 fallback 仅在 Git 已发布后供下游取包而非另一种发布。地图链接到各自证据，不修改确认状态。真实任务结果和维护负担需后续观察，无法从页面访问量或资产数量计算。

## 跨页路径

[工作台](02-Workbench工作台.md)进入本团队地图；[团队资产的智能诊断](10-资产与发布.md)可从业务流衔接候选定位到这类**事先限定**的任务及判断点，但自动发现的证据缺失不替代人工划定任务范围或确认覆盖率。从[DSH 对话与任务](01-DSH对话与任务.md)的任务疑点进入对应判断点，从选中文本到[知识创作会话](03-知识创作会话.md)与[内容讨论](04-内容讨论.md)补背景；需要改变正文则去[修订提议](05-修订提议.md)，有权人到[修订核对](06-修订核对.md)，正式版本/反馈的只读展示到[团队资产](10-资产与发布.md)，发布操作仍在创作会话。稳定步骤可转[Skill 创作会话](07-Skill创作会话.md)，外部数据需求到两个 Tool tab；所有跳转保留团队、判断点、授权资产版本，但不携带敏感原文越权流转。

## 访问与数据边界

只对本团队独立 Git 仓库与获准来源建立可见链接，服务端核验团队、资产空间及每个证据的 ACL；同一个 Workbench 安装在别的团队不汇总地图或互看缺口。来源无权时不显示泄露内容的摘要，也不因地图可见赋予选区贡献、Skill 审核、Tool 调用或业务决定权。仅留最小关联和状态；不保存生产业务原文、完整 Prompt/Tool trace 或个人使用轨迹。任何聚合仅限经授权的范围、明确分母与样本/时间窗口；小样本可能反推个人时抑制，不做个人排行或全组织能力百分比。

## 与当前原型的差距及待确认

原型仅为虚构一类任务的四个可点判断点，展示模拟发布后的一个状态变化及到讨论/Tool 的链接；无真实梳理、来源 ACL 核验、版本状态读回、负责人核对、真实结果或容量证据。即使全部标注也不等于任务已成功。

- 本团队要选哪一类可查来源、风险可控且有人确认的任务；判断点与分母由谁人工核对？
- 哪些状态有外部证据可自动读取，哪些只能明确保持“待核验/未知”？多久复核过期判断？
- 当有文档但任务仍卡住、无人维护或本就需逐次审批时，谁决定改入口、补资源或停止资产化？
