# 03｜知识创作会话：围绕判断和依据工作，不让草稿冒充版本

> 页面位置：Workbench 的知识创作规格覆盖同一材料工作区的「导入来源 → 事实梳理 → 经验总结 → 加入知识库 → 可选 Skill 核对（可跳过）」以及按需展开的指定版本深层修订，不是独立一级入口。导入面向获准的完整本地文件、在正式产品中经授权且受限获取/解析能力已验证的来源链接，或完整合成材料；事实、经验分别对当前选中项待核稿评论，并在右侧随项更新、不悬浮固定地对照已有事实记录或正式知识准确版本。事实中的数字按授权就地核口径；第四步用去向文件树预览来源、事实、经验及非知识路径和独立门禁；正式产品拟只在稳定可测 Skill 缺口存在时提出第五步，而当前 HTML 始终显示可跳过的第五步合成案例导航，不能核实缺口；深层 Skill 创作另见[07](07-Skill创作会话.md)。本页亦可继续对指定来源或知识版本作草稿核对与有权发布；只有经核对、审核并读回的**具体正式知识版本**才可供团队引用。现有静态原型用 111 行完整虚构合成周报和指定本地参考文件指纹命中的同套人工编排线索演示五步、去向树与合成对照；这不是实时提取、授权、冲突裁定或发布；已有 K-01 v1 的评论及指定修订另行演示。

## 何时进入，要完成什么

成员从工作台同一材料工作区导入完整获准材料，在事实梳理和经验总结分别核当前选中项待核稿、评论及同项已有内容，至加入知识库看独立去向文件树与门禁；没有稳定可测 Skill 缺口时直接跳过第五步「Skill 核对」，有具体缺口才作合成比较。只有指定正式版确需补证／修订或有可核新增理由时才按需进入更深层的版本操作。已有版本异议也可从有权资产详情精准进入，未来 DSH 深链仍待验证。另一条拟议路径是在 DSH 原生任务中发现团队知识疑点：先核这条判断**从哪里来、哪一版、什么条件适用**，成员主动运行[任务复盘 Skill](12-任务复盘Skill.md)讨论调整能否复用，用户核对并脱敏后手工复制最小线索至统一入口；DSH 结果卡精确跳转尚待验证。会议纪要、复盘线索和既有知识异议无需先被分成“新知识／已有知识”入口；粘贴文字或选择获准使用的文件，产品拟在后台核对已知，再识别增量。当前原型只对固定样例展示本地人工编排的场景判断，不对自由文本真实检索/识别。复盘里的“用户确认可复用”不是正式草稿内容确认，也不证明实际检索或调用。报告、PPT 等任务产物只有在分享授权和格式能力确认后才能作为来源材料处理；本页只将其中值得核查、可长期复用的判断与适用边界作为知识候选，不将整个产物直接变成正式知识，也不修改当前 ERP 库存或采购价格。

## 产品核心：主动发现团队认知的增量，而非请用户写知识

用户从获准引用的会议纪要／文件、粘贴的脱敏复盘线索或既有版本异议进入**同一受理流程**；若线索先由本人手动保存到[个人 Inbox](02-Workbench工作台.md#个人-inbox手动保存回访删除不自动转团队)，主动导航到此页只展示待核定位，**不抓取链接、不提交候选或创建会话**；成员在本入口明确选用该链接用于知识梳理、当前主体/来源/用途/目标空间获准且目标受限获取与解析能力经验证后，才可临时抓取固定版本并逐区块解析以辅助只读判断。此时不自动分享给团队或建正式草稿；未通过获取/解析门禁则仅留有权最小待核定位，不能假装读到原件。成员另行选定内容/来源/团队目标、再次授权且目的页重验后，才可独立受理最小候选并返回提交回执（仍不建 Session/Draft）。仅后来明确决定正式知识创作或指定版修订，服务端再核空间、来源/基线及动作权限后才创建 Creation Session/Draft；也可以先找已有知识。来源既可是一份文件，也可是一组相互印证的记录。当前静态原型可粘贴文字，或从本机读取不超过 200 KB 的 UTF-8 TXT／MD／CSV 到同一输入框；没有网络上传、服务端解析或持久化。只有载入脱敏内置周报，或在本地选取字节级 SHA-256 指纹与指定样本完全相同的文件，才展示人工预编排议题及折叠的参考范围清单（22 条线索为内部 fixture 数据，页面只显示各段关联数量）；普通粘贴的非演示文本（包括与指定文件内容相同的粘贴）不会获得这套结果。指纹不是来源真实性或授权证明。任意其他内容停在“无法提取”，不套用演示结果。未来文件/授权资料引用要先核入口、授权和证据锚点，复用相同的知识识别与核证步骤。系统负责提出**零到多个完整待核议题**及不提炼理由，并让每条议题可以追到原子线索；对照已有知识属于后台核证，不要求用户经历单独的查库步骤。用户核对可见来源、纠正说法、补充关键条件；谁能确认正式内容与发布仍按资产策略授权。来源登记不是知识确认；本产品不默认读取完整对话、未经授权的附件或原系统资料。

### 产物分层：来源、待核事实、待核经验、正式版

| 层次 | 解决的问题 | 能做与不能做 |
| --- | --- | --- |
| 原始材料／来源定位 | 当时谁在什么版本、什么时间记载或计划了什么？ | Workbench 留最小定位和核证锚点；原文默认在有权原系统，只有 WeKnora 确有对应来源文档、逐文档深链和权限读回时才跳转外部阅读。可找回当时说法，不代表如今属实或已获业务批准。 |
| 事实梳理／待核时点说法 | 这份材料分别对哪些项目／产品线说了什么、发生于何时，哪些只是预测或计划？ | 从来源章节与句段进入按对象／时点去重的事实点：一章可零到多项，同一事实可关联多章，来源定位不随草稿改变。来源说法保持不变，另有可评论的事实梳理待核稿。正式产品先持久保存有权评论及所针对的草稿修订；只有原生回复的回合归属和成功终态均经目标 DSH 核实、草稿基线仍一致，才生成该点新待核稿（v2、v3……），保留旧稿、评论与回退；否则保留原稿，允许人工改写。绝不代替业务系统核证当前状态。事实可回对象或报表，不必被包装成通用经验。 |
| 方法经验／待核判断 | 下一次遇到什么问题，哪些材料合起来暗示什么有条件的判断？ | 系统按整份材料综合提出 0..N 条可读的连贯经验稿，内含问题、暂拟结论、支持与局限、适用和停止条件、反例及来源；用户在段落评论后，获权评论先独立持久化；只有可核归属且已成功结束的回复针对当前草稿修订才可生成下一版完整待核经验稿，旧回复不覆盖新稿。原生回合能力未验证时仍可自然语言人工改写，保留原稿、评论及版本历史，不填一排必填字段。议题仍不是已批准正文。 |
| 正式知识／准确版本 | 有权成员何时可以依什么证据与范围使用它？ | 主张、依据和反证得到核证，既有 ID／基线已对照，责任与版本治理明确；Git 有权审核合并、WeKnora 正式版按版本／commit／ACL 读回和检索验证后，才称该版团队可用。 |

**产品目的不是把周报切碎归类再填满矩阵，而是使下次任务能够正确调用少数完整判断。** 每个议题必须说清“下次遇到什么—建议如何判断—为什么—什么条件下有效—什么情况下不能照用—还需哪项核证”。用户修改的是这一完整议题的判断与边界，内部矩阵索引和线索只服务于证据下钻、时态与整份材料覆盖审计；当前 HTML 不显示矩阵格，对某格打勾也不让议题变成正式知识。尚无充分证据、既有版本已覆盖或只有当期数据时，允许**零条正式知识增量**，明确返回来源／业务系统／任务或指定已有版本，而非为 KPI、计划或规则列制造新正文。

固定周报演示只把两类不同的待核判断抬到主视图：项目 A 的**备选料联合评估**，以及横跨包装与结构件场景的**需求整合与质量／交付取舍**。前者的小试与订单没有证明最终替代成功，后者两段来源说法不等于两次已核证的降本效果；二者均欠权威结果、反例、批准边界和已有知识精确版本。货代竞价、VMI、质量异常、价格波动时的成本复核、产品线 C 风险和物流处置等仍保留为独立待核线索与业务事实核证去向，不合并成这两条知识的“支持案例”；KPI 留报表、下周四组计划留任务，附件未读。准入门槛、8D/RCA 时限、锁价和当次运费安排不凭单份周报升格为已批准规则。

#### 第二步怎样承接章节，并向用户询问缺证与差异

章节只负责导航、原文阅读及来源锚点；事实点是按对象、状态与时点独立维护的**来源主张的待核梳理**，不是章节摘要、正式知识或现行权威事实。第二步沿第一步的章节目录显示本章原文及零到多条关联事实；当章没有可独立核证的事实时明确说清仅留来源／报表／计划／附件或非正文，不为了数量生成卡片。同一事实可由进展章与后续计划章共同引用，但按稳定事实 ID 只保存一份草稿、评论及反馈；在计划章看到的引用仍属于计划，不能把未来动作写成已发生。合成全文的行号须来自该全文实际唯一短句的定位，参考文件行段须来自指纹对应的另一份人工清单；两份材料即便同为 111 行也不互认逐句来源。真实产品需按原件版本、精确段落与 ACL 核证，不依靠演示指纹证明资格。

围绕**当前事实或经验条目**，把会影响结论的缺口问成具体问题，并同屏给对应已有内容的准确 ID／版本（若真实读回不到则明确未知）。用户可选择：纠正当前理解（评论当前待核稿；评论本身先保存，符合回合关联和版本门后才生成下一份完整待核稿并展示差异、旧稿与回退）；提供有权可查的证据定位（记为待读取）；纠正对旧版的理解（待核准确基线、适用时间与范围）；认为确有冲突（并列说法，待有权人员裁定）；暂无法判断或不是本人负责（保留待核，不虚构承接人）。四类反馈均须绑定条目 ID、当前问题及来源／已有版定位，切换条目、章节、步骤、材料或撤权时清除未提交输入；已提交的本地反馈不跨材料复用。**反馈 ≠ 证据读回，差异主张 ≠ 冲突裁定，草稿更正 ≠ 原件更改／现行事实核证／正式版修订。** 静态页面只存浏览器内存与虚构对照，不派单、不触达原系统；正式产品须以独立的有权读回与版本审核链承接。

### 证据检查层：业务对象 × 事实／经验／规则

获授权且版本可定位的来源仍须按**项目／产品线／跨项目专题／待关联事项 × 有时效的事实／有条件的经验／需批准的规则**逐段盘点，记录原话或获准的脱敏概述、行段、状态（已发生／预测／计划）、排除理由和未读附件。对用户，先把事实按业务对象连续罗列，不按周报区块切碎；同一条事实显示不可变的来源时点说法、预测/计划边界与单独可修改的待核梳理稿；用户就点评论先保存评论，符合回合关联与版本门后才由回复形成新稿，或由有权者人工改写形成新稿，逐版留旧正文与评论，不逐条点“确认”。任何草稿版本都不覆盖原件或将来源说法写成已核事实。经验则可吸收多个范围与对象，却只保留一个稳定议题 ID；一个范围也可以限制或反驳某议题。内部下钻以对象 × 类型的矩阵索引组织 22 条原子处理线索的证据及非知识去向；当前 HTML 仅显示折叠的逐段参考范围清单和各段关联数量，不显示矩阵格或全部线索 ID，不要求逐条编辑或计数确认；空格不表示团队不存在规则。原型材料匹配后才展示这层人工 fixture；它没有核验真实来源、已有知识或事实。

每段经验并列呈现支持与反例／局限，待核已有版关系不能写成“查无重复”或“已发现冲突”。用户以段落评论、自然语言整体改写、标记继续待核或暂不沉淀表达意见；后台仍保留判断、范围、停止点、来源和版本等结构化核证要素，不把它们变成用户的必填表格。问题只问对结论有影响、且可访问已有正式版与来源都无法提供的缺口；静态演示仅展示预编排待核问题，评论后使用**标明身份的本地预置回复**生成下一版待核稿，**没有真正查询已有知识或与 DSH Session 对话，也不持久化评论**。正式产品须由 Workbench 服务端先按当前权限持久保存评论、目标条目及草稿修订并返回可查回执，刷新/失败仍能找回；能否由 Client 向目标 DSH 原生 Session 发评论与获准的最小草稿上下文，以及取得本次 turn 的持久回复及成功终态，仍待目标宿主实测。`accepted` 只说明接纳，不是完成；只有回复唯一关联该评论、turn 与固定草稿基线且成功结束，服务端按当前权限与版本 CAS 创建新待核稿修订，才在界面切换当前稿，同时保留旧稿和评论。失败、超时、取消、撤权、重复/迟到、关联不明或已有较新修订时，均不覆盖当前稿，显示待核/冲突及可恢复下一步；不盲目重发，需先读回对账。若目标宿主无可靠的回合关联与完成回执，首期仅保留评论和人工改写待核稿，不声称自动原生回复已接通。评论和人工改写后的新稿都使经验议题重新待讨论，撤销基于旧稿的本地“看过”状态；这不是身份、来源 ACL、事实或发布批准的验证。预计到货、拟上线或停线风险不得改写成已发生；结构校验不能代替人的语义核证。

### 完整材料导入与覆盖（原型已有长篇合成全文阅读；真实核证拟设计）

导入的目标是获准分享、可定位原件版本的**整份材料**，可以是本地文件，也可以是成员在知识入口明确选用且受限获取能力已验证的来源链接，而不是只贴提纲：保留可访问的章节／页段、形成与截止时间、逐段来源锚点以及附件读取或未取得状态；按原件权限过滤显示和留存。若演练无法使用真实原件，则另提供篇幅、章节、时态与多种去向均完整的**脱敏合成 fixture**，清楚标为合成；不能用下文几行缩写假称完整周报，也不能从文件名或哈希认定来源真实或获授权。解析失败、截断、受限段落、未读附件和缺页逐项列覆盖范围／原因；不完整时停止相应事实确认及新增建议，原件仍留获准的原系统。真实正文、敏感价格／数值及附件不得为了演示复制进公开 Git。

当前 `index.html` 可经文件选择器在本机全文阅读不超过 200 KB 的 UTF-8 TXT／MD／CSV，内置一份可按章节阅读的 111 行完整虚构合成周报；对指定本地参考文件仅用原始字节的完整 SHA-256 命中预编排清单。虚构材料虽覆盖类似章节并可导航，人工范围清单并不是对它逐句实时提取，更不是对任意本地文件解析并核验授权。以下覆盖合同规定演示的处理范围及正式产品目标粒度，不代表通用全文抽取、服务端解析或来源授权已实现。

#### 完整周报的覆盖合同（静态原型已逐段人工编排，非真实抽取）

### 两条独立去向：原件外部定位／阅读与正式知识

**来源卡先定位，不默认搬运。** 从本地输入、原系统链接或复盘片段得到的只是未受理线索；确有后端受理回执时，PostgreSQL 记录团队空间、来源类型与系统、获准显示的最小定位、源对象 ID／版本或哈希、形成／有效时间、敏感度／授权范围、留存期限、关联线索、最后核验时点及每条处理操作的状态。未知字段写「待核」，不得生成假的文档 ID 或假深链。用户能看见「原系统有权定位／WeKnora 对应来源文档已核可跳／原文未接入或待人工核对」等有证据的去向；原件留存仅在单独批准时显示相应操作和读回，不作为默认流程。登记来源、单独批准的原件副本、目标 WeKnora 来源文档、从来源提炼正式知识是不同事件。一份来源可支持多条候选，一条知识可引用多份来源，不因原件已经可读就判其观点成立。

复制、团队分享与留存各自核实来源所有者许可、用途、敏感等级、团队／对象／来源 ACL、保留期、撤权与删除要求；其中一项获准不推定其余获准。未获准或过期时仅保留**不泄露原文的待核定位**（连标题／定位本身敏感时也应脱敏或不展示），不抓取或持久化全文。原件默认留在有权原系统；确需复制保存时另经批准，以受控加密对象存储保留必要副本并设到期/撤权清理，PG 只留引用和流程状态，**不将原件、附件或受限摘录写入团队 Git**。Workbench 不提供持久原文阅读器，也不默认建设独立来源全文索引。需要读长篇原文时，仅在目标 WeKnora 已独立托管该准确来源文档、确认来源 ID/版本与 document ID/version、ACL 及逐文档安全深链后，才展示「在 WeKnora 阅读」，由目标重新验证阅读权限；WeKnora 仅索引正式知识或无精确映射时退回有权原系统定位/人工核对，并显示「原文未接入／无法核实」。来源文档可读不等于正式知识已发布，正式知识版本仍走独立链路；本地文件的获准临时预览/解析不等于原文已归档或未来可从 Workbench 阅读。

**正式知识另走受控版本链。** 经验线索核完证据、条件和已有知识关系后，才对新 ID 建候选，或对准确的旧 ID／Git 基线提出补证、修订；对象行只是多对多查找关联，不决定规范目录。先查团队可见且可核版本，检索不可用时不能从无结果推断不存在或推荐新建。只有已批准的正文按 `knowledge/<domain>/<topic>/<knowledge-slug>/` 进入受控 Git；经具体草稿确认、MR／CI、人审、受保护分支 merge 后，由验签、去重的事件落库并触发 outbox／worker **从该 merge commit 取正文**，按空间和固定知识版本送 WeKnora 正式知识索引。不是从用户粘贴、归档原件、Wiki 或索引分块反向写 Git。收到 provider 请求的回执或 Git merge 后仍待验证；按 `asset_space_id / knowledge_id / version / source_commit / repo_path / ACL` 逐文档读回 WeKnora 的真实 document ID／index version／source 与授权范围，再做该版本在有权范围的检索冒烟验证，才称该版「团队可用」。索引及来源文档必须分别保存目标 ID、版本和映射；WeKnora 的文档页/历史不替代 Git 的批准版本和审核证据。

**派生页面与图谱不是第三份正式正文。** 若目标 WeKnora 实例确有相应能力且来源与正式版均获准，Wiki 页面可从可访问的具体来源文档／知识版本派生并显示生成依据、时间、页面 ID、所据文档 ID／版本及可见范围；Wiki 的**页面关系图**表达页面间主题、引用/导航连接，不代表现实业务对象间的已核事实。另一个**实体关系知识图谱**涉及项目、产品线、责任或规则等业务实体及关系，边必须标出来源句段／正式知识版本、有效区间、待核或人工核准状态；模型抽取或 Wiki 链接均只是候选边，不能推导当前分工、业务批准或正式规则。两类图及 Wiki 均以可访问证据和 ACL 交集服务端过滤，撤权、源版本变化、失效或退役后重验、收敛/移除相关节点边与派生页，不把未完成对账的旧内容继续推荐。Wiki 编辑、手工 Markdown 更新及分块改写即便目标产品支持，也不构成上传原件或 Git 的双向同步；如改了正式判断，只能产生绑定原 ID／基线的修订线索，重新走 Git 审核、索引读回。Wiki/图谱生成、文档级 ACL、版本映射、精确深链、清理/回写 API 均待目标环境逐项验证，未验则只展示「未生成／无法核实」，不承诺自动同步。

失败时来源与知识的操作分别记录：可选副本处理或 WeKnora 来源深链核验失败不抹掉有权原系统定位；原系统变更、撤权、保留期届满先限制来源及其派生视图，再核有权目标的访问/清理回执。正式知识 MR/CI/人审失败留草稿；已 merge 但 ingest、逐文档读回、ACL 或检索验证失败/未知，标该**新版本**「待对账／暂不可用」，保留操作 ID、重试依据与承接人，不盲目重复创建或将旧版索引冒充新版。旧版已验证可用与新版待验证并列，但旧版若自身过期、失权或证据失效须停用/警示，不能因为新版失败继续无条件引用。重试前用固定 commit、知识 ID／版本及 provider 状态查重对账；来源和正式版恢复后重建受影响的索引及 Wiki/图谱并逐项核对，未知不算成功也不算已删除。

### 从最小线索到唯一归位的三道门槛

| 阶段 | 最少要有／需核实 | 未满足时 |
| --- | --- | --- |
| 暂存待核线索 | 获准分享的最小主张或问题、可访问的来源定位／版本（未知须注明）、输入来源与待核点；不要求用户立刻写全正文 | 不转存受限原件；可保留无正文的待授权问题，不能显示“已收来源” |
| 送指定草稿核对 | 来源及引用资格、已有知识 ID／基线或可核查重结论、主张与来源原话区分、适用与不适用范围／时间、反证／冲突和承接者；确实未知的关键项留在补证而非填造 | 可继续整理或请求补证，不把候选作为可引用版 |
| 正式发布及目标读回 | 新建时校验 taxonomy、路径与重复 canonical key、owner、敏感度、CODEOWNERS；既有时锁定 ID／基线及修订差异；具体内容确认、Git／CI、人审、目标版本与 ACL 读回 | 只展示对应未完成门禁，不能把内容确认或 Git merged 当作团队可用 |

正式团队资产仓库的规范路径为 `knowledge/<domain>/<topic>/<knowledge-slug>/`（仓库根直接有 `knowledge/`，不是在根下再套同名仓库目录），包含 `KNOWLEDGE.md`、`metadata.yaml`、`sources.yaml`、`CHANGELOG.md`；这是**拟建的团队资产仓库**约定，非本个人研究仓库已有的正式目录。当前静态页面的第四步有九类本地树分支：来源、时点事实、待核经验、规则、当期 KPI、计划、一次性处置、附件／非正文与外部 Tool；对本地标为值得继续核对的经验才显示条件性 `knowledge/…` 文字提示，**没有按逐线索生成规范文件预览，Tool 分支也不执行权限申请或接口调用**。产品拟设计的树才应进一步按材料片段／稳定线索 ID 展示来源保留在有权原系统或获准归档／阅读索引、事实回权威业务对象、经验引用已有准确版本或候选修订／新增、规则回批准版、指标回报表、计划／一次性处置回任务、Tool 申请回提供方；各分支保留引用锚点、权限、时间及阻断，允许一段来源对应多条去向，树节点不代表已归档或已确认。只有来源资格、查重、责任及分类可核的**正式知识候选**才显示规范 Git 路径与文件预览；待核线索和来源、时点事实、KPI、计划不得渲染成 Git 文件，Skill 也不能嵌套在 `knowledge/` 下。Workbench 新建前依据受控 taxonomy 建议 domain/topic 与唯一 slug，展示预览并核 owner、敏感度、重复 key 与 CODEOWNERS；不明则交 steward，不能自行创建分类。已有知识只在原 ID／路径按指定基线修订；移动需受控迁移与索引对账。项目、产品线、专题仅为可多选的查找关联，同一版本只保留一份权威正文。Git 是正式版权威，WeKnora 是经批准版本按 ID／路径／commit／ACL 映射的检索层，文档级读回后才可报可用。

### 可转换为提取 Skill 的议题合同

输入只含**明确选定且获授权**的最小来源内容／定位、版本／形成时间／可引用范围、本次任务目的及真正检索可引用的知识 ID／版本／条件。内部先逐段辨时态和覆盖：借对象 × 事实／经验／规则矩阵把各段和 0..N 条原子处理线索送至来源、事实核证、规则核证或知识判断；输出给用户的主层则是 0..N 条**完整知识议题**，每条含未来问题、暂拟判断、支持／反例、适用／停止条件、来源版本／范围、确实影响结论的证据缺口与既有知识关系。单段可同时支持或限制一个议题，一条议题可汇聚多段／多份有权来源，跨项目也只保留一个 ID；不要从“22 条线索”推导“22 篇知识”。

已有版可核时先决定准确 ID／版本的引用、补证、指定版本修订、冲突待裁定，最后才是经查重后的新增；另可返回重复、不沉淀或无可核知识增量。检索不可用、来源失权、版本不明、附件未读或关键反证缺失时停止对应**结论或入库建议**，说明谁／什么系统可核，不冒充查重成功、已批准规则或现行事实。输出审计层含逐段去向、未读／排除、线索与议题映射及限制，不生成已确认知识或正式目录文件。固定指纹的人工 fixture 不是 Skill 执行、授权或核证回执；与用户主动触发的[任务复盘 Skill](12-任务复盘Skill.md)分工不同，二者都未实际安装／运行验证。正式产品如另行决定用 DSH 原生 `ctx.sessions` 辅助一次评论，评论须先由 Workbench 独立持久化，再在目标环境验证插件获权、来源用途/ACL、最小草稿与评论的安全提交，以及持久回复与成功 turn 的唯一关联；失败、超时或归属不明均不得替换讨论草稿。缺可靠契约时仍可保存评论并人工改写待核稿。**这是待验证的可选集成假设，不是本页当前流程的前提、已实现的插件功能或真实模型生成。** 本规格不宣称本轮插件已实现代码/假会话测试，不凭 Client 类型或本地演示推定 Session 注入、宿主历史回看、模型去向/保留策略；Host token 和内部 RPC 不能充当插件凭据。静态原型仍只用本地预置回复，不启动后台服务、DSH Session 或 Provider，不发送生产周报、受限原件或附件。

## 同一材料入口的知识判别（拟设计：四步主路＋可跳过的第五步 Skill 核对）

工作台「提炼知识&经验」进入**导入来源 → 事实梳理 → 经验总结 → 加入知识库 → 可选 Skill 核对（可跳过）**；已有或外部形成的 Skill 可从左侧「打磨可复用的技能」直接走独立候选核对，不经材料四步，也不是独立体检页。导入来源时按完整文件或长篇完整合成 fixture 核分享、保留和阅读索引授权、格式与附件可读范围、页段/版本锚点及未读范围；失败则留有权原系统或最小线索。事实梳理逐项列来源时点说法、发生/预测/计划与权威依据；经验总结逐项讨论连贯的待核判断、支持、局限与反例。两步都以**当前选中项的待核稿与评论**为桌面约 2/3、**与该项对应的可访问已有时点事实记录／正式知识准确版本对照**为约 1/3；选择切换即重置右栏对应对象，随主内容滚动而非悬浮固定，不继续显示前一项，移动端对照紧跟本项。右栏对事实按对象、时间、权威业务记录与当前性核查，对经验按主张、条件、反例和正式知识基线核查；两步共用来源 ID／版本、权限、有效期、证据状态、差异和下一步，不将事实、经验混为同一比较对象。逐项标「已核／来源自述待核／冲突／未取得／不适用」，已核必须有可核依据，不能由本地样本、语义相似或“看过”推出。影响事实判断的数字就在事实梳理中核指标定义、统计口径、时间窗和有权报表；**仅当前身份、用途、对象/字段、时间窗及只读通道获授权**才可就地 Tool 核验，未授权／未接入／未知时待核并回原系统，不另列数字步骤。「加入知识库」以去向文件树分列来源留存/阅读、事实核权威系统、经验已有知识引用/补证/指定修订/可核新增、批准规则、报表、一次性任务及 Tool 申请；仅有条件的正式知识候选预览 Git 规范文件，树节点不合并各条发布门禁。正式产品第五步仅在稳定可测且有具体 Skill 缺口时出现；当前静态 HTML 始终显示该可跳过入口，仅提供合成 Skill／人工写法及正常/边界/异常示例，不能核实缺口；不是实际试跑或胜出判断，更不是独立体检页。只有确有指定正式知识版本的补证、修订或可核新增理由时才进入知识深层版本工作，Skill 需深层创作时另到[Skill 创作会话](07-Skill创作会话.md)，两者不互为强制步骤。当前浏览器支持本地小型 UTF-8 TXT／MD／CSV 全文阅读及内置长篇合成周报，五步导航、同项预编排对照、第四步去向树与第五步合成 Skill 比较均为静态演示；没有 PDF/PPT 解析、真实授权、通用候选抽取、准确版本查重或 Tool 运行，不能把「载入成功」报成「能力检查通过」。

对每张待核判断先做现有知识的适用性 QA：列出**可访问且可读回的准确 ID／版本**、主张/对象/条件、来源、有效起止及复核时点；检查是否真的覆盖、只缺新证据、要修改边界、发生冲突或无法核查。用户看到支持、反例、误用风险、场景 owner、知识维护 owner 和有权确认者（未知写待指派），而不是一键推荐新目录。可核已有版优先引用/补证/指定版本修订；只有来源资格、查重范围、必要反证、责任与时间边界可核后才建议新建。对于来源未读或无法获权、格式能力未知、已有索引不可达、无法核当前事实，停在最小线索与人工补证，不向团队发布。

本页的**场景评估卡**只把候选与限定任务判断点相连，显示「暂定／待补证」或具体已核证且在有效范围内的版本，不以“本地看过”升级状态；场景卡不是正式知识正文。正式知识还需指定草稿与基线核对、Git/CI/人审、WeKnora 按版本/commit/ACL 逐文档读回及有权范围检索验证；即便发布，后续任务引用须另核 DSH 宿主的真实引用回执。未来数字员工也需有权身份和版本引用事件；当前未接入，不将原型的选段评论、预置回复或本地文件读入记作知识被实际使用。

| 事实梳理 | 沿导入时的章节目录读可滚动的本章原文、关联的简明事实行及零事实章理由；同一条事实在多章节仅保留一份待核稿与反馈。桌面约 2/3 为当前选中事实点待核稿／选段或整段评论，1/3 为同一事实点的有权时点记录／准确版本对照，右栏随选中项更新而不悬浮固定，移动端跟在本项后。当前条目有定向缺证／差异问题：草稿纠正另生成新待核全文；证据定位、旧版理解、冲突异议与暂无法判断只留未核反馈，不冒充裁定。各项标「已核／来源自述待核／冲突／未取得／不适用」，按需展开参考文件的 111 行范围清单及关联线索数量；22 条线索 ID 仅在内部 fixture，不逐格确认。影响判断的数字在此核指标／报表口径；仅在当前身份、用途、对象/字段、时间窗、只读通道均获授权时就地核 Tool，静态 fixture 不作真实调用 | 评论先持久保存；仅目标 DSH 已核成功回复且草稿版本仍匹配，或有权者人工改写，才生成新待核事实稿并保留旧稿与来源说法；Tool 未授权或状态未知则回有权报表／业务系统，不固化数值为知识 |
| 经验总结 | 对每条完整经验议题分别呈现连贯判断、支持/反例、适用/停止条件和待核稿评论；桌面约 2/3 当前选中议题、1/3 同一议题的可访问正式知识准确版本对照，右栏随选中项更新而不悬浮固定，移动端紧跟本项；逐项标相同证据状态，来源下钻按需展开。经验稿可改写为下一版待核全文，保留差异与回退 | 既有正式版需要修改时须锁定准确 ID／Git 基线、反证和草稿；当前评论不覆盖来源或正式版 |
| 加入知识库 | **产品拟设计**以去向文件树显示各材料片段／线索分别流向有权原系统或获准来源阅读、权威业务对象事实、已有知识准确版本引用／补证／指定修订／可核新增、批准规则、报表／任务及 Tool 申请；每个节点标状态、来源锚点和未满足门禁。仅可核的正式知识候选预览 `knowledge/<domain>/<topic>/<knowledge-slug>/` 和受控文件，不给原件、附件、当期数字、业务事实或计划伪造 Git 文件；树的层次是去向，不是资产类型父子关系 | 确有可核知识增量或指定正式版修订时进入知识深层版本核对；来源定位及可选外部阅读、事实核证、Git 发布各自独立。无稳定可测 Skill 缺口则在此结束、跳过第五步；**现有 HTML** 只按固定类别预览去向和条件性 `knowledge/…` 提示，不生成规范文件预览；虽有 Tool 去向树节点，却不发起申请或调用，更不提交、归档或发布 |
| Skill 核对（第五步，可跳过） | 有具体旧版质量问题或稳定可测且核实无适用旧版时，条件性并列合成 Skill／人工写法的正常、边界、异常比较，展示准确版本、依赖和仍缺的证据；允许直接「跳过 Skill 核对」，不改变第四步各去向状态 | 仅有权且有真实脱敏测试条件、维护责任和稳定流程时进入[Skill 创作会话](07-Skill创作会话.md)的独立深层工作区；合成对照不是试跑、批准、发布或加载；静态 HTML 已提供第五步与本地跳过状态，但不能验证缺口真实存在或确有适用旧版 |

当前待核稿的**选段评论／v2、v3／旧稿回退**属于事实梳理和经验总结两步，不必先过「加入知识库」才能操作；K-01 指定正式版修订及审核是按条件进入的深层工作，不是第二套必经主路。第五步 Skill 核对同样不是知识发布的门禁：跳过仍可保留第四步各项去向和明确未核项，也不会自动生成 Skill。现有静态 HTML 已用本地去向树和第五步／跳过控件示意这条路径，树中合成路径与本地关键词回复仍只是人工 fixture，换议题、换材料、撤权或迟到的演示回复不得替换当前稿。

划线仅针对**当前待核稿正文**，不作用于来源说法或正式知识。评论框紧贴正文，仅需一条自然语言输入；评论锚点绑定稳定事实点／经验议题 ID、当前草稿 vN、正文快照、选段文本和起止位置；提交前再核一次，换稿／回退／改写／换议题／阶段／材料或撤权后旧选段失效。键盘与移动端可用整段评论入口。静态原型只对有限方向给出标明身份的本地预置完整回复；不支持任意评论的模型生成，刷新后不保留评论。演示失败后只在当前浏览器状态保留原稿、原评论输入与选段；正式产品的已提交评论由 Workbench 服务端持久保存，未提交输入不冒充回执。失败时可先读回状态，再由用户修改或重试；取消、回复无法唯一归属或迟到也不替换当前稿，不能把待核 v2 当作正式知识 v2。

“整体”指同一个界面检查各类产物及未决问题，不是把来源定位/外部阅读、业务事实核证与正式知识发布合成一个原子事务。来源外跳仅在实际文档/权限/版本可核时显示；事实要回权威业务记录核时间、状态与反证；经验须核已有准确版本、条件与反例，再走 Git 审核及 WeKnora 目标版本读回。评论与本地看过都不自动改变正式版；来源在 WeKnora 可读不代表知识版可用，Git merge 亦不代表来源获准公开。原型没有真实提交或任何目标回执。

旧有的 K-01 v1 → 评论 → R-02 提议 → 指定修订核对 → 模拟审核/读回是另一条既有知识纠错链，保留在可展开的知识记录中，不与本次周报候选混同。知识到 Skill 不是必经路径；稳定可测试的方法才另进[Skill 创作会话](07-Skill创作会话.md)。

按[团队知识骨架](13-团队知识骨架与工作记录.md)，本页不仅供新建，还要从业务对象、来源记录和既有正式版本进入**查看、纠错与提炼**。列表/搜索先用团队选择的项目、产品线、专题或关键词定位；每条结果标“业务对象事实／团队经验”、关联对象、来源与最后核实时间、具体版本的“整理中／待核对／团队可用／已停用”，并把团队可用 v1 与整理中的 v2 分开。工作记录应有独立的来源视图和原件版本，不显示为已确认知识；改栏目/关联不会复制正文或改变稳定 ID。

- 明确的团队空间、内容对象 ID、关联项目/产品线、Git 基线版本与草稿修订、具体版本状态、来源权限和更新时间；从 DSH 跳转时显示原任务返回入口，重新鉴权后再显示正文。业务对象页面先展示可核对的当前事实及“截至何时”，再链接来源时间线、经验与 Skill；不能从最新一条纪要自动填“当前”。
- 详情区分**事实**（陈述、生效/截至区间、权威系统/来源及反证、最近核实时间）与**经验**（判断或约定、依据、适用与不适用范围、反例和复核点）；侧栏展示有权查看的来源版本、关联对象、争议/评论与版本历程。原始资料、成员补充、Agent 整理和已确认判断分层；仅有资料或用户口述时标“待核”，不显示“已确认”。人员分工是有时效的事实，不自动授予系统审核或发布权限。
- 对具体资产版本的段落定位、评论与来源线索入口；旧版继续只读，基于旧资产启动修改时须选择精确 Git 基线并另建修订提议/创作会话，草稿差异在[修订提议](05-修订提议.md)中呈现；正式版可同时继续可引用，不能被会话覆盖。
- 新知识候选按阶段收集：初存仅需获准分享的最小问题/陈述、来源定位（未知明确标注）和待核点；先由产品给出建议类型、与已有知识的关系及不提取理由。只有送核时才补足确实影响结论且既有知识不能提供的适用/不适用范围、有效时间、反证、责任与来源资格；项目/产品线关联可待定。不能迫使使用者在初存时编造当前分工、生效时间或负责人。
- **一个「加入知识库」去向树预览，多个独立门禁与回执**：正式产品拟按材料范围／稳定线索为叶节点，分别显示来源、事实、待核经验、规则、报表、计划、Tool 等去向；仅满足可核条件的正式知识候选才展开目标 taxonomy／Git 文件预览，其余不是 Git 文件。现有 HTML 的第四步按九类固定类别分别显示本地树与未满足门禁，其中报表、计划、一次性处置各占一节点，另列附件／非正文和外部 Tool；**Tool 节点不执行申请或接口调用，也没有规范文件预览**；在经验标为值得核后才提示条件性 `knowledge/…` 路径。明确「当前仅预览，尚不能提交」，**不尝试写仓库、核实当前事实或归档来源**。第五步 Skill 核对可跳过，绝不使第四步自动获准。正式产品如受理整体意向，也要逐对象分层受理：对来源核 ACL、原件版本与归档资格，对事实核权威系统与时效，对经验核指定草稿、已有知识精确版本、反例及操作者身份；一项通过不推定其他项通过。若缺批准记录、原件权限、已有知识版本或审核资格，就显示该项阻断/待补及承接人，而不是先报仓库已提交。实际 Git 提交/MR、CI、人审与 merge 各有独立回执，完成目标版本读回和检索验证之后才报「团队可用」。当前静态原型已有本地去向树与第五步合成核对／跳过控件，但没有逐线索的真实受理或核证回执；不写仓库、不归档、不索引、不生成 Wiki、不送审、不实际发布；议题本地看过也不解除阻断。对已有 K-01 的可选旧修订演示仍保留独立的确认、审核和读回门禁，不能被本周报的议题演示代替。

| 建立新的候选事实或团队经验 | 从已提交且获准分享的复盘线索、有权访问的工作记录/业务对象或资料开始；先判是否已有同一对象/经验及其版本。事实核原系统、发生与生效时间、反证；经验核重复性、条件、反例和误用风险。填最少陈述、来源与待核问题 | 创建创作会话，按对象或来源关联候选，邀请有权访问材料的成员进入[内容讨论](04-内容讨论.md)；确定可改内容后进[修订提议](05-修订提议.md) | 未提交的粘贴不标“已收到”；有来源不代表来源观点正确。证据不足可留待补，不自动发布；一次性事项/实时事实回原任务或 Tool；无承接者显示待安排，不伪造责任人 |
| 对比历史与当前正文 | 对比明确版本的来源、适用范围、确认和停用记录；指出哪个版本曾被引用 | 可针对相应基线发起修订，发布后旧引用仍留审计线索 | 遇版本冲突不静默覆盖旧评论，已过期内容必须清楚警示并去受控纠错路径 |

| 暂存/退出创作会话 | 会话记录草稿与最近操作，不赋予正式知识地位；返回任务保留可失效定位 | 继续该草稿或结束一次性讨论，给发起者可理解的回执 | 存储故障时不能报“已保存”；资料权限变化要及时收敛可见范围 |

### 什么时候不做知识

“这次库存还有几件”是当下事实，应通过获授权的只读 Tool 查询；“按这个库存自动下单”是业务决定/写操作，不能写成知识就绕过审批；“每次按稳定步骤核对两版清单”可能适合作 [Skill 创作](07-Skill创作会话.md)，但要有可测试的停止条件。团队成员可贡献内容，有权确认和正式发布仍是单独动作。

## 跨页与原型差距

进入[内容讨论](04-内容讨论.md)后可补来源、背景，形成[修订提议](05-修订提议.md)；[修订核对](06-修订核对.md)只对特定草稿和范围确认；随后的正式审核、发布、读回与异常对账留在**本知识创作会话**的指定修订流程，完成后到只读[团队资产](10-资产与发布.md)查看版本结果。返回 DSH 时重新核验任务和当前版本，不把新草稿注入已确认结果。

**现有静态原型与正式产品的差距（以实际页面验收为准）**：内置 **111 行完整虚构合成周报**可按章节全文阅读；本地参考文件可通过文件选择器（不超过 200 KB 的 UTF-8 TXT／MD／CSV）阅读全文，但只有字节指纹匹配才与内置材料共享人工编排线索，任意其他文件／粘贴不触发提取。事实的主视图沿第一步的章节目录导航，在可滚动本章原文下列关联的事实行（可零项），再展示当前事实点待核稿／评论与同项合成对照；同一事实跨章节保留单一草稿和反馈，章节的数量不等于事实数量。内置合成全文仅按其实际唯一短句展示行号，参考文件的人工行段只用于参考文件，不把它当合成全文的逐句证明。两步均有定向缺证与已有版差异反馈：纠正稿走有限关键词的本地预置下一版及旧稿回退；证据定位、旧版理解、认为冲突与暂无法判断只作本机未核记录，不触发核证、裁定、派单或正式版变更。桌面主稿与右栏约为 2/3 与 1/3，窄屏对照排在本项之后；右栏随项更新且随正文滚动，仍没有读取真实权威时点事实记录或正式知识准确版本。111 显示行的折叠范围清单属于**固定参考文件**；22 条线索 ID 只保留于内部 fixture，页面显示各段关联数量；这些都不是对虚构全文逐句定位或核证。影响事实判断的数字仍须就地核报表口径及 Tool 授权条件，原型不作真实查询。第四步按固定类别展示本地去向树和未完成门禁（Tool 仅作为独立去向节点，不发起申请或调用；没有 Git 规范文件预览），第五步有合成 Skill／人工写法和跳过状态；均不执行真实去向或 Skill 测试，也无仓库写入或发布。待核事实/经验稿可就当前正文选段评论、查看有限关键词的预置下一版全文、差异与回退；事实评论不覆盖来源说法，经验评论/改写撤销旧稿的本地看过。静态数据不是实时抽取、授权、权威事实核证、准确旧版查重或证据已核。来源未登记／归档／索引，Wiki/图谱未生成；不要填凭据或受限材料解锁。旧 K-01 v1 评论、R-02 提议、指定修订确认和模拟审核/读回保留为独立旧版演示，不能代替新周报的去向门槛。**原型未做到**：真实文件上传与复杂格式解析、来源接入、实际候选提取/去重、模型生成、真实 Tool 查询及指标核对、受控仓库写入、会话恢复、真实跨系统导航。**待验证**：不同格式的证据锚点、目标环境授权检索完整性、Wiki 派生权限、已有知识核对成本、谁承担核证及维护。
