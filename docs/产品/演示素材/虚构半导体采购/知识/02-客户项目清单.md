### PX-A 的两个日期与两个供给数字

- V1 原请求 2026-11-20 是对照基准，不能由此补造企业已承诺的原交期。
- V2 2026-11-13 是客户提出的提前请求，不是采购团队已接受的交付承诺。
- 800 件是客户请求总量，日期提前并未创造一份额外的 800 件订单。
- 500 件是封测方的**演练确认窗口/条件性排期讨论范围**，只说明会议可以围绕该范围核查排期条件。
- “确认窗口”在这里不等于已锁定排产，更不等于封测方已确认供应 500 件。
- 原文使用“封测方的演练确认窗口”时，必须按这一限制解释；它不是供应商确认函或可交数量。
- 300 件是对剩余数量的**未确认缺口**描述，不得因 800－500 的算式而升级为可供或已获批供给。
- 500 件与 300 件不构成“已有 800 件”这一业务结论；前者仍有条件，后者尚未确认。
- 即便后续完成排期核验，`DEMO-LOT-7` 待判仍是一条独立质量约束；本包没有该后续结果。
- [K11 条件推演](./11-交期产能推演.md)可比较路径，但计算不更新本项目卡的承诺状态。
- [K09 新闻线索](./09-行业新闻链接线索.md)不能作为供应落实、质量放行或订单接受依据。

## 版本与证据：同一项目可有多个请求状态

| 状态名称 | 定义 | PX-A 截点例子 | 允许迁移的证据类型 |
|---|---|---|---|
| 原请求记录 | 保留变更前客户请求供对照 | 800 件，2026-11-20 | 可追溯的原请求或版本依据 |
| 新请求待接受 | 保存客户新希望但不替企业决策 | V2 改请 2026-11-13，数量未变 | K07 与 K10 对照 |
| 内部条件讨论 | 评估是否可能达成条件 | 500 件条件性排期讨论 | K06 的带条件陈述 |
| 未确认供应 | 尚无成立的供给结论 | 300 件缺口 | 缺口计算加“未确认”标识 |
| 质量待判 | 单独等待质量依据 | `DEMO-LOT-7` | K12 的状态记录 |
| 承诺待审批 | 可准备材料但不能对外承诺 | 提前交期无批准 | 须另有有权审批，当前无 |
| 已批准/已发送 | 只能由独立审批或发送回执证明 | **本包不存在该状态事实** | 不可由来信、会议、草稿推断 |

- 此表的状态类型用于判断资料能支持哪句话；“允许迁移的证据类型”不是已获取证据清单。
- K07 邮件能支持客户提出了请求，不能证明内部已接受该请求。
- K06 会议能支持讨论过排期条件，不能证明封测方已完成供应确认。
- K12 的待判状态对日期讨论有约束，但不能被任何排产表自动解除。
- K08 未发草稿只能证明有待复核文本，不能成为已发送的状态迁移凭证。
- 如来源间冲突，保留各自 ID、时间、原文状态和待核原因，不选择最乐观的版本覆盖另一条。
- 没有真实审批人或回执，不能为“已批准/已发送”列虚构负责者。

- 保存旧版本 ID、变更来源、变更时间和接受或拒绝结果，是未来维护要求，不代表现有文档已经有数据库审计。
- 若没有客户订单编号、供给确认或权限回执，应明写“待核”，不能编造交易号。

## 反例与证据失效的处理

- 反例：“PX-A 已批准 800 件在 2026-11-13 发货。”错误地把 V2 请求、500 件讨论、300 件缺口和质量待判压成一个承诺。
- 反例：“封测方已经确认供应 500 件。”将条件窗口讨论升级为外部确认。
- 反例：“还有 300 件可从 PX-B 调来。”跨客户、料号与项目挪用独立申请。
- 反例：“质量仍待判，但赶工可以先交。”把计划压力当成质量放行依据。
- 反例：“已有未发送草稿，客户已经同意。”把内部草稿当成外部往来回执。
- 反例：“PX-C 预测量说明 200 件已经下单。”把预测状态抹掉。
- 反例：“新闻说行业需求变旺，所以订单自动增长。”让背景线索篡改交易字段。
- 反例：“K02 引用了 K07，因此任意角色可读 K07 原件。”将文档链接误当访问授权。
- 若发现文件与固定 V1 口径冲突，应标记争议来源与待核，不自动选择更乐观的说法。
- 若来源缺失，应写出“本包无证据”，不生成看似真实的客户确认、供方回执或审批记录。
- 若新材料声称有后续事实，应另建明确版本并核验出处；不能悄悄改写 V1 快照。

## 易混淆说法的逐项判读

| 看似相近的说法 | 在本台账中的准确含义 | 应避免的写法 |
|---|---|---|
| 客户需要 800 件 | PX-A 提出试产请求 | 企业已接受 800 件订单 |
| 交付窗口提前 | PX-A 从 11/20 改请 11/13 | 已批准 11/13 发货 |
| 演练确认窗口 500 件 | 封测条件性排期讨论 | 供应商已确认 500 件 |
| 还差 300 件 | PX-A 未确认供应缺口 | 300 件已经能供 |
| PX-B 也有 300 件 | PX-B 独立申请量 | 可直接转给 PX-A |
| PX-C 有 200 件 | PX-C 预测量 | 已签 200 件订单 |
| 待判批次 | `DEMO-LOT-7` 尚未放行 | 已检合格可以交付 |
| 草稿已写 | K08 可用于待复核 | 已发信且客户已同意 |
| 推演有路径 | K11 描述条件情景 | 审批已落定 |

- “确认窗口”是原始表述的判读风险点；如果缺少“仅为条件性讨论”，读者容易误认供应已锁定。
- 若摘要必须压缩语句，应优先保留“请求”“申请”“预测”“未确认”“待判”等状态词，而不是仅保留数字。
- 如果界面只允许一行描述，宁可写“PX-A 加急请求待核，供给/质量有限制”，也不要写“PX-A 800 件可交”。

## 项目交接的最小问题包

### PX-A 交给供给与质量复核时

- 问供给计划：500 件讨论的具体条件是什么，是否有独立确认凭证？现有快照只给条件性讨论。

- 问质量接口：`DEMO-LOT-7` 待判需要什么判定材料？现有快照没有放行结果。
- 问需求协调：K07 所示 V2 与原请求的差异是否被准确记录？现有口径是数量不变、日期提前。
- 问客户协调：K08 是否仍为待复核草稿？现有快照无发送记录。
- 上述问题不能在台账中被预填为“已答复”或“已完成”。

### PX-B 和 PX-C 分别交接时

- 对 PX-B 先问订单依据和独立供给确认，不从 PX-A 的会议推断答案。

- 对 PX-C 先问预测是否有独立的确定订单证据，缺少时继续保持预测。
- 对 PX-C 不要求供给人员为一个未确定的交期倒填排产时间。
- 两项目的材料必须使用各自 ID 和料号，不能因人数、数量或客户场景相近而合并。
- 如果交接过程中有人给出更乐观的口头陈述，应先标记“待核来源”，不静默变更 V1。
