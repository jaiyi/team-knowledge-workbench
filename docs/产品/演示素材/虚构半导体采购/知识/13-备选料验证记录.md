## 3. 工程门：是否值得发起验证

工程核查应由有权设计角色提出对象、版本、功能边界和可核验的验证计划。
本包没有设计输入或真实器件参数，因此无法比较电气兼容性或功能等效性。
不能用同类名称、料号相似、模型推断、供应商宣传代替项目特定设计判断。

### 工程输入问题

1. `DEMO-PART-A` 在 PX-A 设计中的功能定位是什么？须按授权设计资料作答。
2. 候选拟替换哪一处器件、板级版本与应用范围？不能用“所有 PX-A”代替。
3. 是否存在受限设计信息的读取权限？未授权时只提问题，不拉取规格文件。
4. 边界工况、接口、电气限制和性能目标如何由工程定义？本包不给数值。
5. 软件、固件、启动、时序等系统依赖是否需要验证？不能假定完全无改动。
6. 封装、引脚与热路径的匹配关系是否有受权设计审查？目前没有。
7. 哪些差异需要客户共同确认，不应由供应方单独接受？待工程分类。
8. 验证用的参考版本及变更记录如何锁定，避免测错设计版本？

### 工程输出门槛

- 有明确的设计版本、比较对象、负责角色和可见范围。
- 有受权的兼容矩阵，逐项指出已证、未证和不适用，不允许“总体相当”一句话。
- 有针对边界工况的试验计划与接受准则，均由工程先定义，而非本页编造。
- 有可追溯的样品及试验结果，若尚无样品则状态只能为计划/询证。
- 有签署的工程评审结论及其适用范围；口头认可不升级状态。

**失败/停止条件**：如果任一关键接口或项目边界不满足，停止宣称可互换；可由工程另定研究范围。
工程初步正面判断也不等于客户批准或可供数量。

## 4. 封装与测试门：不能只看器件功能

即使功能比较得到正面线索，也要核对封装形式与实际工艺流程是否适配。
云屿封测的既有排程讨论不能证明候选在同一设备、程序和窗口可被处理。
本包没有候选测试程序、产线验证、样品装配或测试通过记录。

### 需拟定的验证问题

- 候选样品、封装形式及板级装配对象如何建立一一对应的记录？
- 原有测试覆盖目标是否仍适用，哪些测试项目需由工程重审？
- 测试程序与工装如需变更，谁批准版本并保留回退方式？
- 装配与可追溯标签如何防止候选和原物料混料？
- 工序异常与复测由谁判断，如何与原料号结果区分？
- 若需要额外验证步骤，排程影响由谁核实而不是在此估算时间？
- 谁能批准让候选进入正式生产路径，而不是停留在隔离试验？

不能根据本页推断封装可直接替换、测试可复用或额外成本为零。
若拿不到工艺与测试的受权记录，候选仅维持实验议题，不排入 PX-A 提前供给。

### 林澈应确认的质量问题

1. 原物料待判问题是否涉及拟比较的失效模式？没有复测结论就不归因。
2. 候选的风险评估应覆盖哪些项目要求？由授权质量/工程共同界定。
3. 验证计划应包含什么可靠性和一致性检查？本页不给数值门限。
4. 试验样品的来源、版本和测试报告如何绑定，防止来源不明结果被引用。
5. 若试验出现异常，怎样隔离候选样品并中止进一步引入？
6. 批量使用前是否需额外质量认证、变更审核或客户批准？由有权流程判断。
7. 面向计划或客户协调应输出何种最小状态，避免扩散受限复测细节？

### 质量门的证据包

- 已授权的验证计划及其适用样品/项目版本。
- 可追溯的检测、可靠性和异常处置记录；没有记录不能写“通过”。
- 批次与范围明确的批准结果及受权签署。
- 对原 `DEMO-LOT-7` 隔离仍独立有效的状态说明。

**停止点**：原批次待判或候选无质量批准时，不能把任何相关范围写成可交数量。
原批次将来放行与候选将来放行是两个不同判断，不应混用一个“质量通过”标签。

- 如果供给说法与试验版本不符，谁暂停采购讨论？

任何答复若只有意向或宣传材料，仍不能写成已备货或能够满足 2026-11-13。

## 9. 验证计划草案：提出问题，不假装已经执行

### 设计审查前

- 由有权工程角色界定比较对象和可使用的受控设计资料。
- 确认客户需求仍指向 `DEMO-PART-A`，不直接改 K02 项目台账。
- 识别是否需要样品和隔离环境；尚不能声称已经入库。
- 为每项试验预先设定接受准则和责任人，不编造阈值。

### 试验期间

- 用可追溯样品及版本记录试验条件，原物料与备选料分开。
- 将功能、电气、封装、测试、可靠性及异常记录按责任角色归档。
- 不把单项通过写成总体等效；异常必须保留并触发复核。
- 试验结果属于内部技术判断，不能自动对客户变更作答。

### 试验之后

- 由工程、质量分别判定自己的适用范围及保留意见。
- 由供给核对与批准版本一致的批次和实际可用性。
- 由有权客户协调征询、记录客户对具体变更的回应。
- 由负责人核审批、采购、对客承诺和业务系统变更是否具备完整链路。

这些是未来可能执行的步骤；截至截点没有试验计划批准、样品测试或签署结果。

## 10. 假设路径及其可证伪条件

### H1｜只作技术研究

前提：授权工程愿意审查候选与目标设计的适用性。
可得结论：生成验证计划及未解风险，不更改采购和客户交付状态。
可证伪：发现关键设计接口不匹配，或无法取得合法设计输入。
停止门：无工程授权或明确不可兼容时不推进可替换宣传。

### H2｜试验有正面结果，供给仍未知

前提：取得可追溯样品和针对特定版本的试验结论。
可得结论：只讨论被试验覆盖的性能项，不宣布批量可得或有交期。
可证伪：供给没有相同版本/范围的受权批次或可靠来源。
停止门：无批量供应和质量链，不向 K11 填入数量。

### H3｜供给声称有量，技术未通过

前提：出现供应方资源线索，但工程/质量审查尚缺。
可得结论：可记录供给问题，不创建物料替换单。
可证伪：资源版本不同、批次无法追溯或适配检查失败。
停止门：采购请求、下单和客户承诺均不执行。

### H4｜工程与质量通过，客户未接受

前提：有针对明确版本及范围的授权判断；这是纯假设。
可得结论：可准备客户征询资料，仍不改客户订单料号。
可证伪：客户不接受、附条件接受或要求进一步验证。
停止门：没有书面接受和版本变更前不替换 PX-A 需求。

### H5｜客户原则上愿意讨论，其他门未齐

前提：实际有权渠道表达研究意向；目前并不存在这种回执。
可得结论：进一步问清客户所需材料，不将意向升为批准。
可证伪：客户对具体料号、范围或试产用途作出限制。
停止门：缺工程、质量或供给任一门仍不承诺时间和数量。

上述路径没有预设成功率、测试阈值、批次构成、成本或保证日期。
任何一个“若”句都不能作为 2026-10-28 已发生的事实被检索引用。

## 11. 变更控制：如果有新证据，先核对象

| 新材料类型 | 先检查 | 不能立刻更新 |
|---|---|---|
| 工程比较表 | 设计版本、对象和签署权限 | 客户已接受 |
| 试验报告 | 样品、工况、结果及异常范围 | 批量质量已放行 |
| 质量结论 | 具体批次/版本和批准范围 | 封测资源已锁 |
| 供应意向 | 物料版本、可追溯来源和条件 | 候选可交数量 |
| 客户咨询回复 | 具体变更、措辞与授权来源 | 正式接受或订单已改 |
| 客户接受回执 | 项目、物料、数量、窗口、版本 | 制造与质量已完成 |
| 内部批准 | 批准主体、内容、限制和时间 | 实际发送/实际下单 |

同名 `DEMO-ALT-A` 若对应不同样品或设计版本，须分别记录，不能混成一份“验证通过”。
不得将新证据倒填为原截点已知；历史拒绝/待核记录保留便于追溯。
若有相反结果，明确受影响的门槛，暂停只引用有利结果的摘要。

## 12. 证据与权限交接卡（拟议）

- **工程→质量**：提供受权设计对象、试验版本、样品映射与可审阅结果。
- **质量→供给**：提供适用范围明确的批准/隔离状态，不传播超出目的的内部细节。
- **供给→负责人**：提供同一物料版本的批次、来源、条件及影响评估。
- **负责人→吴衡**：明确是否获准向客户征询、允许的表述与尚未满足的门槛。
- **吴衡→客户**：如将来受权发送，保留具体文本、发送事实和客户回复。

## 16. 样品身份与结论范围的对照规则

验证结果只能覆盖其明确关联的样品、设计版本和试验条件；样品尚不存在于本包。
若将来有多个候选样品，不可因为都使用 `DEMO-ALT-A` 代号就合并测试结论。

| 要核对的身份字段 | 为什么要对齐 | 未对齐时怎么写 |
|---|---|---|
| 候选来源与版本 | 确定工程讨论和供给记录指向同一对象 | 对象未匹配，暂停可用结论 |
| 样品/批次标识 | 防止样品测试结果外推到不明批次 | 测试范围不足 |
| PX-A 设计版本 | 判断结论适用的板级用途 | 无法宣称设计兼容 |
| 测试计划版本 | 判断结果是否按受权准则得出 | 仅保留原始线索 |
| 质量审核范围 | 区分试验许可与量产放行 | 无量产质量结论 |
| 供应批次版本 | 对齐实验样品与拟采购对象 | 供给匹配未知 |
| 客户批准范围 | 确定客户同意的是研究还是实际替换 | 无已接受变更 |

样品试验、工艺试作、量产资格与客户订单修改是四个不同对象的证明责任。
供应批次即使与试验样品同名，仍需追溯，不可省去差异审查。
客户回复若只认可研究，不应记录为接受 PX-A 在目标窗口交付备选料。
任何一项身份不一致时，应附差异和责任角色提问，而非取最乐观解释。

### 验证记录的最小审阅顺序

1. 查对象是否和计划使用对象一致；无同一性证明时不继续外推。
2. 查试验预先批准的范围；事后挑选有利指标不能替代接受准则。
3. 查结果是否完整保留异常和未覆盖工况；没有结果不能写“通过”。
4. 查工程签署的结论边界；不得转述为质量批准。
5. 查质量签署和批次适用范围；不得转述为供给可得。
6. 查供应回执的量与时间状态；不得转述为客户接受。
7. 查客户正式回复的具体项目/变更范围；不得转述为已完成交付。

上述顺序是拟议审核方法，不表示任一环节已形成文档或已被执行。
