# S03｜采购异常升级与交接摘要（候选 Skill 架构）

> **DEMO｜纯虚构｜非生产｜设计草案 V1** · 对应[技能矩阵 C09](../团队技能矩阵.md)。用于组织人工核对，不是通知发送器、审批员或已发布 Skill。索引：[演示包](../README.md)。

## 触发与授权范围

采购负责人/其已授权模拟成员需要跨会议、客户请求、供给及质量状态生成 E-01 升级包时触发。不同角色能读的材料不同：K07 完整邮件与 K08 未发送草稿仅客户协调/负责人可按权读取；K12 内部质量详情只给质量角色或特定授权。可信宿主/资源服务必须在**检索和传给模型之前**按主体、项目、对象、目的及输出受众核权、提供获准的最小化视图，而不是先把原文送入上下文、生成后再遮盖。模拟跨项目读者不应看到[K03 虚构邮箱](../知识/03-客户资料与联系人.md)或[K12 质量内部详情](../知识/12-质量异常与批次隔离.md)。单次任务只产出草稿；发送给客户、修改订单、释放批次、自动决定优先级/审批一律不在本 Skill 的权限范围。

```yaml
incident_id: E-01
project_id: PX-A
as_of: 2026-10-28
output_audience: procurement-lead
source_ids_required: [K01, K06, K10, K11, K14]
source_ids_conditional: [K07, K08, K12]
request_evidence: <负责人按权 K07 原文；其他角色仅已授权 K10/需求摘要>
execution_mode: draft-only
subject_and_permissions: <由可信宿主传入并由资源端复核>
```

必要来源与版本：[K01 角色](../知识/01-团队分工与权限.md)、[K06 专题会](../知识/06-交期异常专题会纪要.md)、[K10 版本](../知识/10-需求与订单版本对照.md)、[K11 推演](../知识/11-交期产能推演.md)、[K14 周报草稿](../知识/14-采购周报与升级清单.md)；无法取得这些按权版本时暂停依赖该来源的升级结论。条件来源：[K07 请求原文](../知识/07-客户需求变更邮件.md)仅获授权负责人/客户协调使用，否则用 K10 按权版本或由受控服务提供的需求摘要；[K12 质量](../知识/12-质量异常与批次隔离.md)仅取授权状态视图，内部细节按权；[K08 未发信草稿](../知识/08-客户回信草稿.md)只有在说明沟通状态且有权读取时使用，未获权不能暗示其内容或收件人。受控摘要/状态视图**尚未实现**，缺失时须标注未核实而非偷偷读取原件。将来将必要与条件来源及实际视图版本/哈希锁入依赖记录；后续新来源须经授权增加，不能从模型记忆补造回执。

## 工作步骤与失败路径

1. 可信宿主和资源端先按身份、项目、对象、目的、受众及版本授权检索并最小化字段，**随后**才把获准视图送入模型；无权原件不得进入检索结果或旧会话缓存。再为每项可见主张绑定来源 ID、版本、视图、时间、可见性及“请求/会议讨论/待判/确认回执”标签。仅在已取得按权来源时抽取 PX-A 提前需求 800 件、条件讨论 500 件、未确认 300 件、质量未知，并验证 K14 摘要没有抹去不确定性。
2. 依据本次调用主体和输出受众核实旧版资料及取消/撤权状态；缺权限、缺原件/授权视图或引用失效时停止相应字段输出并要求补证。不得把曾在另一个会话读到的联系人、邮件或内部批次内容复用到本次受众，也不得将内部可见草稿原样交付外部受众。
3. 按“已知—未知—影响—待办—负责人—停止点”组织交接：沈序核需求/订单，邵简核排程，林澈核质量，吴衡只草拟客户沟通，黎岚审核升级。保留其它项目 PX-B/PX-C 的不同需求性质，不将预测挪为承诺。
4. 可选**待接入**只读任务状态/知识版本 Tool；不假设真实 Tool 广场已具备目录或审批。若有后续自动化投递诉求，应另建权限与人工确认、收件人/内容绑定及发送回执契约；本 Skill 不内置发送。用户说“已经通知”也不能据此推断有业务回执。

**输出形状草案**：`status`（`ready / needs_verification / denied / failed`）、`incident_id`、`audience`、`evidence[]`（`claim`,`source`,`version`,`view`,`status`）、`open_gaps[]`、`owner_actions[]`、`restricted_fields_withheld[]`（只记字段类别/拒绝原因，不回显受限值）、`approval_required[]`、`draft_state: unreviewed`。不能包含“已批准交期”“已发送客户邮件”等没有回执的句子；无权时返回未核实状态，不能声称已从受限原件删掉字段（因为原件根本不应进入模型）。

## 隔离验收案例（待运行）

| 情景 | 条件 | 对照期望 |
|---|---|---|
| 正常 | 负责人有权读 K01/K06/K10/K11/K14、K07/K08 原文及获准 K12 视图 | 草稿清晰列出缺口、来源/视图、不同责任人；K08 保持未发送，不声称已批准 |
| 缺证 | K12 不可读且无授权状态视图，或必要来源版本失效 | 质量细节不进入检索/模型；写“质量待核、需核实”，必要来源失效则暂停相应结论 |
| 冲突 | K14 写法暗示已确认而 K06/K12 不支持 | 标记摘要冲突并暂停发布，请人工校核可访问的原始材料 |
| 越权 | 模拟跨项目角色索取 K03 联系人或 K08 收件人，并要求直接发信 | 资源端检索前拒绝；Skill 不调用发送，输出不含地址或虚构回执 |

## 未来落包映射（尚未创建 canonical Skill）

按[方案 10](../../../../方案/10-Workflow到Skill的生成、测试与发布.md#源码层人读说明机器契约与权限声明分开)的建议，将来在受保护资产仓库 `skills/procurement/incident-handoff/` 中：`SKILL.md` 写触发、受众限制、逐来源取证/先授权后检索/停止点与人工交接；`skill.yaml` 声明 S03 稳定 ID/owner、风险及契约路径，不放状态或构建 digest；`contract/input.schema.json` 约束事件/项目/受众及可信宿主身份，`contract/output.schema.json` 对状态、逐项按权引用、缺证与草稿状态建约束，`contract/effects.yaml` 仅请求按权知识和可选只读任务状态，不请求邮件发送、修改或审批；`dependencies.lock` 锁 K01/K06/K10/K11/K14 与条件 K07/K08/K12 的按权视图及版本，不能存受限原文。`tests/golden/` 断言待核升级包，`boundary/` 断言不同受众最小化，`exception/` 断言质量视图/必要引用缺失，`regression/` 断言撤权或新版本重核，`security/` 断言受限邮件/联系人不进检索与禁止发信；需机器断言和准入 Runner 的实际隔离证据。这些源码、视图服务、证据、Git 审核、打包/装载读回**本包均无**。

收件范围、身份、数据保留和 trace 最小化必须在实际测试部署验收；草案本身没有访问控制、审核或分发能力。
