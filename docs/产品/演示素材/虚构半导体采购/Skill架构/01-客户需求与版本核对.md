# S01｜客户需求与版本核对（候选 Skill 架构）

> **DEMO｜纯虚构｜非生产｜设计草案 V1** · 对应[技能矩阵 C01](../团队技能矩阵.md)。非已发布 `SKILL.md`，无已接入 Tool/运行结果/真实订单。面向采购需求协调的只读辅助；不得代表兆易创新或虚构客户作正式确认。索引：[演示包](../README.md)。

## 触发、角色和任务边界

当用户请求“比较 PX-A 的原需求与新请求，哪些已确认？”时触发；主体必须有项目及来源材料的阅读授权。按 [K01 权限边界](../知识/01-团队分工与权限.md)，需求协调沈序（虚构）**不得读取 K07 完整邮件**，只可由受控资源服务按权从原件生成去标识需求摘要；本包没有这份独立摘要文件，也没有已运行的生成服务。客户协调吴衡和负责人按权可读完整 K07；任何角色都不能因能读摘要而获得原件权限。拒绝跨项目读取 [K03 联系人](../知识/03-客户资料与联系人.md)或调用写订单、发邮件、释放批次接口。不得从邮件、新闻或模型记忆自行扩大许可；有权审批人负责正式订单/对外承诺。

## 输入契约草案（全部为演练字段）

```yaml
project_id: PX-A
requester_role: demand-coordinator
as_of: 2026-10-28
source_ids_required: [K05, K10]
source_ids_conditional: [K06, K12]
request_evidence: <有权角色可用 K07；需求协调仅用受控服务按权生成的去标识摘要>
identity_and_acl: <由可信宿主/资源端决策，不接受调用者自填授权>
mode: read-only
```

真实实现必须由宿主提供已认证主体、租户/项目/对象/目的权限、可信时间和获准源版本；`request_evidence` 是设计占位，不是允许调用者指定未授权原件。知识依赖：[K05 原目标](../知识/05-采购周例会纪要.md)、[K10 版本对照](../知识/10-需求与订单版本对照.md)和新请求的**按权视图**（完整 [K07](../知识/07-客户需求变更邮件.md)只给客户协调/负责人；需求协调需资源端预检索授权后生成的去标识摘要，尚未实现）；反向证据：[K06 条件资源](../知识/06-交期异常专题会纪要.md)及[K12 待判](../知识/12-质量异常与批次隔离.md)的按权视图。版本与哈希应锁定到可核验的来源和授权视图；出现新订单/撤权时重新查询、失效旧缓存。本演练只有静态 V1 文件；未能取得经授权的新请求视图时只可列缺证，不能靠 K10 的转述反查或索取 K07 原文。

## 决策流程与停止点

1. 可信宿主与资源端在检索、生成摘要和传给模型**之前**核验项目/目的/对象 ACL；对需求协调只返回经预授权的去标识视图，不把完整 K07 先送入模型再遮盖。摘要服务尚未实现或受限来源无授权时停止该字段；旧会话缓存不可复用。
2. 从按权可见的每个来源提取主张、时间和事实状态：K05 的 2026-11-20 为原目标；获准 K07 原文或获准摘要中的 2026-11-13 为客户**请求**，两者均针对 800 件；K10 仅作版本交叉核对，不提供正式变更回执。缺少获准新请求视图时不输出已核对 V2 的结论；若 K06/K12 视图缺失，仍可列需求差异，但供应/质量栏仅记待核而非作可交付判断。
3. 独立查询（**待接入**）只读订单/接受回执 Tool 时，需要有可验证来源 ID、角色和版本；若工具不存在/拒绝/超时，标注“未核实”并停止于待核清单，不能以“没查到”推断订单不存在。
4. 检查 K06/K12 的交期/质量约束；将“需求变更请求”“双方接受”“实际交付可行”分三列，不用客户催促覆盖后两列。
5. 仅输出带证据与差异的摘要，交人核对；不修改订单、不发邮件、不自动触发 S02。

**输出 JSON 形状草案**：`status`（`ready / needs_verification / denied / failed`）、`project_id`、`old_target`、`requested_target`、`requested_qty`、`request_status`、`accepted_status`（`unknown`）、`supply_status`、`source_refs`（来源 ID/版本/**视图**）、`missing_evidence`、`review_owner`、`prohibited_actions`。只在取得相应授权视图时列出：PX-A｜800 件｜原目标 2026-11-20｜请求 2026-11-13｜尚无接受与供给确认；引用 K05、按权 K07 摘要或原文、K10、按权 K06/K12。缺摘要服务/原件权限或回执时返回 `needs_verification`/`denied` 及缺证原因，不能制造已访问原件的引用。

## 隔离验收案例（待运行）

| 案例 | 输入/变化 | 对照期望 |
|---|---|---|
| 正常 | 有权的客户协调/负责人读取 K05/K07/K10，或需求协调取得经授权的去标识摘要及 K05/K10 | 正确列两个日期和 800 件，明确 V2 未接受；需求协调不检索 K07 原文 |

| 冲突 | 获准的新请求视图称 2026-11-13，而旧纪要为 2026-11-20 | 按来源时间并列，不将较新文本自动变成承诺 |
| 越权 | 需求协调尝试读取 K07 原文，或非 PX-A 主体要求 K03 邮箱/写订单 | 资源端在检索前拒绝敏感读取/写入；模型不接收原文或假执行回执 |
