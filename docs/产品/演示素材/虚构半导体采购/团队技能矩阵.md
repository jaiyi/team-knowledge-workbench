# 半导体采购团队技能矩阵（演练能力地图）

> **DEMO｜纯虚构｜非生产** · 版本 V1，2026-10-28；仅作为团队知识工程产品功能验收输入，不代表兆易创新的真实团队评价、标准流程或生产系统能力。下表“技能”指**候选可复用工作能力**，不是已安装、已执行或已发布 Skill。业务 ID、数量、角色均来自[演示包基线](./README.md)。

## 判断规则

将能稳定描述输入、判断点、输出和停止条件的能力标为“可设计 Skill”；缺少真实授权 API、可靠输入或人工判断无法拆分的能力暂保留人工/知识支持。每条首先追问“以何版本、谁授权、读了什么、能产生什么后果”。下表的“可接 Tool”均为**测试时可能申请的能力**，目前没有接入、审批或运行证明；不得把矩阵当成自动化授权清单。

| ID / 能力与判断点 | 必要输入与证据（关联样本） | 期望产物 / 演练责任角色 | Skill 适配与潜在 Tool 前提（均未接入） | 人工边界 / 关键负例 |
|---|---|---|---|---|
| C01 客户需求与版本核对：新请求是否已被接受？ | K05、K10 与按权 K07 请求视图；核订单/回执 | 需求差异和待核清单；沈序 | **候选 Skill S01**；可申请只读需求/订单版本查询 | 沈序不读 K07 原文；缺接受证据不可写“已承诺”，不能改订单 |
| C02 客户联系人与项目权限校对：能否看到/联系此人？ | K01、K03、K07；请求主体和项目授权 | 去标识摘要或有权收件清单；吴衡 | 知识＋权限网关；可能只读联系人目录 | 非项目成员请求邮箱应拒绝；不自动外发 |

| C06 质量隔离与放行判定：批次能否使用？ | K12、K06；正式质量回执缺失 | 待判/已判及批准路径；林澈 | **保留人工/质量系统**，仅只读辅助 | `DEMO-LOT-7` 未获放行，不得由 Agent 解除隔离 |
| C07 替代料评估分流：候选是否可用？ | K13、K12、K11；规格/可靠性/客户接受缺失 | 分职能核查问题单；林澈、技术角色 | 知识支持，非自动批准 Skill | 仅有 `DEMO-ALT-A` 代号不能认定兼容或填补 300 件 |
| C08 预测与确定订单分离：项目如何入计划？ | K02、K05、K10 | PX-C 预测标签与条件计划；沈序 | 可设计只读规则校验，需订单系统证据 | 预测 200 件不等于确定订单或可挤占产能 |
| C09 异常升级与交接摘要：先处理哪个风险？ | K01、K06、K11、K12、K14 | 证据/缺口/责任人的升级包；黎岚 | **候选 Skill S03**；只生成待复核摘要 | 不能代替客户确认、质量放行或审批 |
| C10 会议纪要事实抽取：说法是否等于结论？ | K05、K06，发言人与时间 | 带出处与待办的结构化纪要；沈序 | 可设计，但源文需人工校对 | “讨论 500 件”不可写“已批准交付 500 件” |

| C12 周报复核与最小化分发：谁能看哪些字段？ | K14、K03、K01；分发范围与批准 | 去敏周报候选与审核清单；黎岚 | 可设计只读草稿生成；发信/发布需单独 Tool 权限 | 不在跨项目周报复制联系人，保存不等于已分发 |

**关联样本**：K01–K14 即 `知识/01`–`知识/14`，具体路径见[演示包目录](./README.md)。这里不衡量现实员工能力，也不以“完成 12 项”证明 12 个 Skill 已实现。针对 S01、S02、S03 的流程、契约草案和拒绝样例，分别见[需求版本核对](./Skill架构/01-客户需求与版本核对.md)、[交期方案比较](./Skill架构/02-交期偏移与方案比较.md)、[异常升级交接](./Skill架构/03-异常升级与交接摘要.md)。

## 从地图走到真正的 Skill（尚未实施）

只有对实际身份、目标对象、数据权限、证据版本和测试空间边界达成契约，补全受保护资产仓库的 `SKILL.md`、`skill.yaml`、`contract/`、`dependencies.lock`、五类测试与隔离运行证据，经指定审核及 Git 受保护主分支合并，才可宣称 Skill 已发布；构建 digest、目标分发/安装及 DSH 加载/执行须分别读回，不能用发布代替。入口「打磨可复用的技能」可以独立核对这三条候选，不要求先强制走全部材料流程；本演示仅提供设计样本，不实现 Tool、审批或发布。
