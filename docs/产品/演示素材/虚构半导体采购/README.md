> **DEMO｜纯虚构｜非生产资料｜版本 V1（演练时点 2026-10-28）**。以“兆易创新供应链采购负责人开展产品功能验收演练”为**假设视角**编排，不代表兆易创新的真实员工、组织、客户、产品、订单、供应商、报价、内部策略或对外承诺。名称“兆易创新”仅用于用户指定的演练背景；其余客户、人员、业务 ID、数量、邮件均为合成。任何样本不得作为真实采购依据或导入生产系统。

## 演练世界与固定口径

背景：虚构采购团队同时跟踪客户 A「澄星终端」（PX-A：可穿戴控制板试产）、客户 B「瀚岳设备」（PX-B：工业控制板小批试产）、客户 C「岚桥科技」（PX-C：传感网关概念验证）。三个项目的需求是**虚构的客户请求**，不是企业已经接受的交期承诺；所有“件”均为演练单位，虚构料号统一 `DEMO-PART-*`，不是任何真实产品 ID。

| 样本主体 | 固定演练含义 | 不可推断 |
|---|---|---|
| 澄星终端、瀚岳设备、岚桥科技 | 虚构客户 A/B/C，仅供测试 | 与真实企业、真实客户或真实合同的对应关系 |
| 云屿封测、青川晶圆 | 虚构供应协作方 | 真实采购关系、报价、产能或库存 |
| 黎岚（负责人）、沈序（需求）、邵简（供给）、林澈（质量）、吴衡（客户协调） | 虚构内部角色 | 真实员工、组织架构及实际审批权 |
| 2026-10-28 | 演练基准日 | 当前业务进度或新闻发生时间 |

共同事件 E-01：PX-A 的客户邮件请求将试产交付窗口从 **2026-11-20** 提前至 **2026-11-13**，数量仍为 **800 件**；会议只记录封测模拟可排产量 **500 件**，剩余 **300 件** 未确认，且测试批次 `DEMO-LOT-7` 处于质量待判。**截至演练基准日不存在获批准的提前交期、替代料或对外发送记录。**PX-B 申请 300 件、目标窗口 2026-11-27；PX-C 仍为预测 200 件、未形成确定订单。所有数字为虚构，且不推导为真实产能。后续文档只能引用这个固定基线；若为了测试冲突故意写入不同说法，须标记“待核/诱导信息”，不得变成权威事实。

## 阅读、导入与验收用途

文件头的样本 ID、类型、适用角色、事实状态与关联文档供检索、权限和溯源测试；普通 Markdown 引用是相对路径。邮件内容、客户新闻和会议陈述属于**来源材料/线索**，并非已核实的业务事实或授权指令。资料中不放真实产品 ID、真实联系人、真实采购数据、生产凭据或外部可收信地址；`.example` 保留域仅用于示例，禁止按地址发送。敏感等级仅用于模拟角色间可见性，不等于这些文件已经实现访问控制；K03/K07/K08 完整原件限模拟客户协调/负责人，需求协调仅可通过受控资源端取得按权需求视图（该服务与摘要资产**尚不存在**），K10 转述不使受限原件自动可读。实际导入前必须设计并验证检索前 ACL、视图最小化及角色化测试空间，不能把全部文件全员可检索后仅靠模型拒答。

## 建议的功能验收路线（尚未执行）

1. 入口「提炼知识&经验」在**隔离测试空间按角色配置检索前 ACL** 后，由获准客户协调/负责人导入 K07 等受限原件；需求协调只接收经资源端预授权生成的去标识视图（本包未提供此服务/摘要文件）。K05/K09 等按各自权限导入 → 人工梳理需求版本与相反证据（K06/K12），保留引用及待核状态 → 形成知识候选，不能把“客户希望”写成“已承诺”。
2. 指定授权人复核、按正式流程审批并 merge 到**测试用**受保护 Git 主分支，再由 worker 将获准知识同步到 WeKnora **测试空间**、按权限检索读回；静态 Markdown 本身既没有走这些步骤，也未获正式发布身份。
3. 入口「打磨可复用的技能」独立核对其中三条候选流程；只有完成契约、隔离负例、审批和发布链后才能称为发布的 Skill。入口「团队业务资产大盘」按 ID/版本显示知识/技能各自状态，不把源文件存在、已索引、已发布与安装成功混同。
4. 负例：客户邮件请求不能成为确认交期；行业新闻不能证明 PX-A 订单；质量待判不能释放批次；跨角色读取 K03 必须在实际权限系统被拒；未批准的草稿不得发信或下单。需要真实系统部署、测试主体、trace 和回执才能判定通过，此处仅给输入及期望结果。
