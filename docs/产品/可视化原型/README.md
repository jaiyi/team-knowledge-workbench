# Team Knowledge Workbench · 团队共创产品概念稿

## 五个入口，按问题选择而非逐关完成

Workbench 五个入口为 **我的工作台／提炼知识&经验／打磨可复用的技能／连接业务数据源／团队业务资产大盘**。其中「我的工作台」在原有使用反馈之外，已用浏览器内存演示个人 Inbox 的手动暂存／查看／删除与到知识页的待核交接提示；它不持久化、不返回真实源任务或获得团队再次授权/受理。其前面的「原生对话 · 示意」属于 DSH Desktop 宿主，**不计入 Workbench 导航**；原型仅保留静态跨界跳转，不连接真实 DSH 会话。

| Workbench 当前入口（括号内为旧名称） | 何时进入 / 静态原型边界 |
| --- | --- |
| 我的工作台（我的使用与改进） | 手动暂存虚构的个人线索、查看或删除，主动到知识页核来源；下方继续演练虚构使用与反馈。没有真实身份/持久化、源任务返回、团队再次授权、成功率或受理回执。 |
| 提炼知识&经验（导入材料） | 尊重来源语境，从有权材料梳理事实、经验和适用条件；本地阅读与候选去向不等于核证或入库。 |
| 打磨可复用的技能（引入 Skill） | 评估已有／外部 Skill 候选，核边界并做本地修订演练；不等于已取得包、执行或发布。 |
| 连接业务数据源（业务接口目录） | 查目录、数据责任方与接入资格；本页无真实连接、查询或授权回执。 |
| 团队业务资产大盘（团队资产） | 查已有成果、准确版、可用范围及维护线索；固定虚构指标不代表正式仓库读回。 |

反馈可以指向准确版复用、来源核证、方法打磨或业务数据的有权通道；**当次任务已解决就停止**，不强迫沉淀新资产。拟议持久化 Inbox 只在成员有权且明确选择时手动保存最小线索：元数据目标为 PG，允许安全回读时仅留原系统引用，获准复制才用授权加密对象存储；当前原型只有暂存内存项，没有 PG、对象存储或真实个人记录。已有本地 `knowledge-inbox/deposits/` 与其 Skill 是独立的用户工作区交接示例，不接入产品 Inbox；反馈、Session、Git 和 WeKnora 也不自动入箱。未来 IM 需针对消息来源、参与方和用途另行征得同意，现阶段不接入。详情见[我的工作台规格](../界面功能设计/02-Workbench工作台.md)。后文的「导入来源」「引入候选」如指页面内具体操作，仍保留原称。

经验总结 → 加入知识库 → 优化已有 Skill · 可跳过」；后者在页内以**四阶段**处理团队已有版或外部／本地候选：「引入 Skill → 自动校验 → 具体修改与复测 → 审核提交」。**当前 HTML 已演示的 Skill 交互**：阶段①只有一个按输入形态分流的选择区，回①不清空候选，原版/预置改版采购样包选择后重新诊断，去掉独立「引入新 Skill」清空入口；来源线索、目录或不同团队资产版本与上一输入关联不明时先确认是否替换本页输入，确认也不证明同一包。阶段②仅对两份固定虚构采购样包比较预置停止片段和文件名，本地目录只比较文件名（最多前 80 项），其他情况明确无法比较真实内容；旧结果不会转移给新输入。阶段③上方默认显示按当前诊断和失败断言生成的 DSH 手动交接提示词：仅有文字建议可继续编辑本地草稿，有获准改后包则回①按原输入形态提供、经②重诊断后重新拟稿和演练。案例数量与逐例结果只在②展示，③只操作当前草稿的本地规则重演。**未实现**真实 DSH 带回包内容的读取、任意包解析、同一 Skill 的身份核验、真实文件 diff 或受控 Runner；固定改版不是 DSH fallback）及逐目标安装的不同状态。样包仅供解释交互，不是从真实报告抽取或经过审核的团队包；演练与虚构齐门样例不能当真实测试或发布。材料第五步只是可选的关联路径，不要求已有或外部 Skill 先导入周报；「引入」不表示已上传包、已入团队资产、已发布或已安装。「导入来源」把选择本地文件和粘贴文字并列展示，内置演示是独立操作；后选的来源替换前一个。内置的是可按章节阅读全文的 **111 行完整虚构合成周报**，不是短报告或真实参考文件原文；文件选择器也可在浏览器内阅读全文读取不超过 200 KB 的 UTF-8 TXT／MD／CSV。章节目录与正文各有独立滚动，行范围在章节名下一行以浅绿色小字显示；Markdown 的标题、列表和表格等只做安全的本地阅读排版，原生 HTML 不执行、宽表可横向滚动。分章只是阅读索引，不等于事实或经验被自动拆解、核证或入库。只有内置示例或字节 SHA-256 精确命中指定本地参考文件，才显示人工编排的事实／经验议题；粘贴原文、其他文件均不触发真实抽取。第二步沿第一步的章节目录展示可滚动原文及本章关联的简明事实行，默认定位首个有关联事实的章节；可切换到零事实章节查看不提炼理由。同一事实可关联多个章节，但只维护一份待核稿与反馈。内置周报的定位只取其确切短句的实际行号，指定参考文件则按其自己的人工行段与章节相交，二者不能互称逐句引用。事实和经验分别按**当前选中项 Tool 的**本地去向树**和阻断说明；仅在经验条目被本地标记为值得继续核对后，才在经验节点下出现条件性 `knowledge/…` 路径，并无 Git 文件预览或写入，Tool 节点也不申请权限或调用接口。第五步用虚构 SK-01 v1 的合成 Skill／人工写法对照正常／边界／异常情境，可跳过且不影响第四步；并未运行或测试 Skill。**拟设计而非 HTML 已实现**：获准、可定位版本的完整材料逐段核证，真实时点事实与正式知识准确版本的授权对照，数字的有权报表／只读 Tool 核验，Tool 请求单独分流，只有可核正式知识候选才展开 `knowledge/<domain>/<topic>/<knowledge-slug>/` 的规范文件预览，以及真实测试、审批和发布。静态页面无真实身份／来源授权、模型、任意材料抽取、权威检索／核证、Tool 调用或仓库写入；下文演示路线仅描述浏览器内状态。

知识创作的事实画线评论、经验评论后查看完整下一版待核稿、旧稿对比／回退及来源覆盖下钻，分别归入事实梳理与经验总结的待核讨论；指定正式知识版本的受控修订仍按门禁进入深层工作区，不是另一条必经流程。原型回复按有限关键词选本地预置稿，非模型输出或任意文本生成；未覆盖的评论保留原稿并提示失败。分别核事实与经验的待核稿及已有知识对照，折叠的参考范围清单覆盖 111 显示行，22 条处理线索仅是内部 fixture 索引（界面显示各段关联数量，不列全部 ID），只作证据下钻，不能代替两步各自的评论和依据状态。内置完整脱敏合成周报与指定本地参考文件的完整 SHA-256 指纹只用于命中人工编排结果；非样本不实际抽取或检索。文件只在本地读取，未登记来源、上传、归档或生成 Wiki；不要输入无权分享的原件。**静态页面没有后端核验、仓库提交或发布能力。**

**这不是已安装的 DeepSeek Harness Desktop 插件，也不连接企业资料、团队仓库、业务系统、Tool 目录、Git/CI 或 Provider。** 团队、资料 A/B、知识版本、Skill 建议、库存/价格 Tool 与审核发布结果均为虚构。输入仅在当前页面内存中用于演示；请勿填写真实产品/部件 ID、库存、价格、生产凭据或其他敏感内容。

## 从「我的工作台」走查五个入口

直接打开 [index.html](index.html) 默认到 **Workbench「我的工作台」**（左侧单独分组的「原生对话 · 示意」属于 DSH 宿主，而非 Workbench 第六个入口）：顶部个人 Inbox 可手动填虚构标题、来源定位与短备注、填入示例、暂存到本页内存、查看或删除（最多 10 条）；主动选某项去「提炼知识&经验」只带待核定位提示，不携带原文、不自动抽取、共享或创建团队事项。刷新/模拟撤权会清空 Inbox；没有后端、跨设备保存、真实来源权限或删除回执。其下首屏分开显示知识「召回／适用」和 Skill「实际执行」的指标位置，但都明确为**暂无可计算数据**；三个记录是固定虚构情景，不是本人的真实调用或可计算样本。点「知识 · 清单适用判断」查看虚构事件定位和 K-01 v1、缺少正确版本与适用结果的证据；选「找错版本／适用条件不明」，说明可留空，提交后仅出现「用户报告／待核实」。点「演示记录候选分流（不派单）」看四段进度：反馈提交、候选去向待核、正式资产未变、下次结果未知；返回列表后从「我的反馈进展」继续看。另从 Skill 技术异常与无事件引用情景演示不同归因，后者照样可以报告。首屏「模拟未绑定并清除本地暂存/反馈」会隐藏 Inbox 条目、使用记录及数量并清理内存；恢复后只有干净的固定情景。刷新同样重置。不会上传完整 trace、读取真实 Session、自动归因/派单/修订或真正计算成功率。

如果业务系统已有版本说明或有权联系人足以处理原任务，可从左侧回宿主，无需提交反馈或新建资产；确有具体缺口时，再按需使用左侧「提炼知识&经验」「打磨可复用的技能」「连接业务数据源」或「团队业务资产大盘」，不在工作台重复摆放入口导航。下面的旧演示路线仍可从左侧宿主「原生对话 · 示意」进入，是独立虚构任务的其它去向，并非这三条固定情景的真实运行历史。

## 建议演示路线

**先走一条允许停止的虚构任务，而不是把所有页面当成必经流程。** 从「DSH Desktop → 对话与任务」的“这次应该用哪版清单？”开始，先核任务类型、生效时点、来源资格及原业务系统处理状态；如果原系统的版本说明或有权联系人已足够，就回原流程结束，不导入材料、不引入 Skill。若确有缺口，再到 Workbench 工作台，按具体疑点分别看 S-01 来源与业务对象、材料中的待核事实/经验、K-01 v1 的讨论→R-02 提议→指定修订核对、已有 Skill 和外部 Tool 的前提，最后从团队业务资产大盘和四个判断点复查版本与未知。它们是**可选且独立的去向**，并非同一份虚构任务真的跨系统跑通：来源不可得时补证或暂停；已有准确知识够用时只引用；没有稳定步骤就不封装 Skill；无接口授权就回有权业务系统；修订可补证、拒绝或暂缓；一次性事项可不沉淀。工作台事项关闭、模拟发布、目录试参与地图判断均不能证明当次任务成功或下一次收益。真实试点须另取得业务侧许可、一手任务样本、人工基线、总维护/审核耗时及业务结果责任人的独立核对，见[初版验证协议](../04-初版假设与迭代.md#真实试点前的原始素材研究和独立复核协议)与[跨页评审矩阵](../界面功能设计/README.md#同一任务跨页评审矩阵拟议检查非业务发现)。以下编号仅是按页检查静态交互的路线，不是顺序完成全部资产动作的指令。

1. 从左侧 **DSH Desktop 宿主示意 → 原生对话 · 示意**进入（首次打开默认在上述 Workbench「我的工作台」）：原生会话的位置是宿主任务主线，但这里的对话仍只是预置示意，**不是插件重新实现的 DSH Session**。任务仍由宿主和原业务系统完成；知识结果、候选 Skill、外部 Tool 都放在次级可展开示意中。先核这次任务的类型、适用时点和原业务系统状态；若有权版本说明或人工核对已足以处理，就留在原流程，不强迫进入 Workbench。展开后选择「已确认／只有资料／资料冲突」仅切换虚构结果；推荐不等于 Skill 已安装、加载或执行，Tool 列表可见不等于已调用。静态对话不接受任务输入或提交。
2. 当用户认为本次任务值得回顾时，主动点 **「演示调用任务复盘 Skill」**：先看任务目标、资产使用证据与用户额外调整（未有记录则标「无法确认」）；再逐条选择「可复用／有条件可复用／特殊处理／证据不足」，决定待核线索去向：核工作记录来源、核项目／产品线事实、提炼经验、更新／新建知识、讨论 Skill、核外部 Tool，亦可「暂不沉淀」。最后回答是否有报告/PPT、能否分享。未讨论完不会生成交接结论；特殊处理／证据不足时不建立通用资产。
3. 在复盘结论处**手动选中并复制**获准分享的最小脱敏示例文本，按选择进入工作记录、业务对象、知识或 Skill 页面。知识页可粘贴或从本地文件读入文字；复盘交接、材料定位加问题和旧版异议不需要不同入口。不过，可在同一输入区域载入脱敏周报结构示例，在「事实梳理」逐项阅读本期事实稿和同项合成对照，在「经验总结」逐项阅读人工编排的两条方法议题及同项合成对照，并按需展开参考索引的逐段范围清单；普通自由输入**不会自动提取事实或经验**。其他页面仍是「模拟提交候选供核查」。复盘讨论和打开页面不自动转交；来源页只收定位与核证线索，不登记整份纪要；业务对象页只收待核事实线索，不认定当前分工。即使模拟提交，也不创建正式知识、修订或运行日志。受限报告/PPT 不显示标题或原文、不上传；即使用户称可以分享，仍需核实来源、权限和实际资料库入口，**资料提交与正式知识发布是两条不同流程**。
4. 打开左侧 **团队业务资产大盘**，依次切换 **最新进展／全局概览／智能诊断**。最新进展顶部是知识/Skill/Tool 三组虚构指标：可用存量大字、本周发布或开通及引用/执行/调用次数与使用人次小字；下方左列是项目/产线的事实进展与风险线索，右列是经验/技能更新。可从标题或正文**直接点击文字**进入团队业务资产大盘内的只读详情，返回原 tab；不是另外一排“看只读详情”按钮。经核准的原材料可以整理为项目/产品的成果、风险和有依据的后续安排，知识/Skill 动态可供团队周报引用。**全局概览不重复数字**：默认同时看见项目 A/B/C 与产品线 P/Q/R 的工作主题和交叉关系，接着看按 ID/版本去重的知识与 Skill 落点；其中 B/C、Q/R 及多数关系是待核的演示占位，不能当作真实归属或能力覆盖率。智能诊断用三条固定虚构巡检候选分别示意事实说法冲突、约定进展复核和限定业务流衔接缺口；可点进证据详情，主动反馈待补证或不适用。它并未扫描真实来源，反馈也不派单。固定样例不读仓库，也不随模拟发布按钮或 Tool 试参重算；浏览详情不会自动派单或进入带审核控件的页面。
5. 在 **全局概览** 先从全队业务版图看三条产品线、三个项目以及它们的交叉主题：项目 A 同时连到产品线 P 的演示知识关联和产品线 Q 的待核关系，后者不能当成已核归属。选项目或产线可高亮关联、在同页看简短上下文；选择“看全团队”恢复全局。下方 K-01 v1 只出现一次，关联项目 A 和产品线 P；点 K-01、K-02 或 SK-02 进入团队业务资产大盘内的精简只读详情，返回保留所选对象。K-01 v1 是有条件的演示可用版，R-02 可并行整理，不能用修订候选覆盖正式版；SK-02 的发布不等于已安装或实际执行。只有在详情明确选择「继续处理」后才进入相应的知识/Skill 创作或事实核证会话；真实目的页必须重验身份、来源 ACL、对象 ID 与版本基线。若要演练原有 K-01 v1 的评论与 R-02 修订，可进入**知识创作会话**底部的可展开 K-01 记录：选中旧版文段发表评论，进入修订提议和指定修订核对，再回到这份记录模拟审核和目标读回。它不是新周报议题提炼流程的发布结果，也不能绕过已有审核门禁；审核/发布按钮不在团队业务资产大盘只读页。
6. 在选中项目 A 或产品线 P 后，从上下文里的 **历史出处** 点击 S-01 来源摘要，进入团队业务资产大盘内的来源只读详情。正式产品若已核对这份文档的 WeKnora 文档 ID/版本、权限和具体深链，才在它旁边出现「在 WeKnora 阅读 ↗」，直接在新页面打开**对应文档**，而非整个知识库首页。原型未读取登录后文档，也没有可核实的 S-01/K-01 深链，故只显示“原文未接入”，**不提供虚构跳转或独立 Wiki 区块**；概览也不复制历史原文。
7. 从左侧独立的 **连接业务数据源** 入口进入（实际为虚构目录与授权前提示意，未建立真实连接）：在**团队可发现**默认看到首条 ERP 库存接口的右侧详情，列表的每条 Tool 都显示「本团队实际调用次数：暂无法统计」，不再单列一块用量面板。按虚构目录的 ERP / MES 标签筛选、搜索“库存”可改变结果与默认详情；输入唯一允许的脱敏示例 `DEMO-001`，点击「模拟参数测试」查看固定本地结果。库存详情里可展开**本地试参情景**：仅演示这一个测试按钮在“条件就绪／待授权／未接入／状态未知”下能否点击，不表示真实接入、授权或调用，也不影响其他 Tool 或宿主任务。随后切换 **待申请**，默认看首条可发现但未开通接口的详情，搜索“价格”或选择采购标签查看采购价格接口的参数结构与外部申请去向；未开通项**没有试调入口**，「模拟记录申请意向」仅在内存中记意向。列表/标签/详情并不连接真实数据中台；目录实际分类应取提供方 API，正式搜索要按团队权限在服务端分页执行。原型没有 PG 聚合或宿主成功调用回执，浏览、试参和推荐均不算真实调用；宿主任务里的外部 Tool 查询也是单独的固定虚构值，不可当 ERP 调用或复盘运行证据。
8. 打开 **Workbench「我的工作台」**：先手动填虚构线索标题、来源定位和给自己的备注，可暂存本页内存、查看、删除或从所选项主动去知识页看待核提示；这**没有**将内容提交团队，也没有真实原系统返回或再次授权。其下首屏继续看分开的知识／Skill 指标「不可计算」、最近使用的三条固定虚构记录、每条可选的本地反馈与四段回访状态；选择类别即可提交，不要求说明或 trace。候选诊断与演示分流不确认根因、分派人员、发布资产或业务效果，反馈后可返回列表继续查看本地进展。工作台不再重复展示左侧四入口及讨论/修订/资产的导航卡；解决原任务后可从左侧回宿主或直接停止，确有缺口才按需进入其它入口；「提炼知识&经验」与「打磨可复用的技能」不是完成任务的前置步骤。进入材料工作区的五步静态导航时，本地输入必须获准，内置 111 行完整虚构合成周报可按章节阅读全文，文件选择器可在本机阅读全文读取获准的 UTF-8 TXT／MD／CSV（≤200 KB），但仅指定字节指纹匹配时有人工编排议题；粘贴即使内容相同也不会命中。事实梳理沿第一步的章节目录读本章原文，再选关联的事实行：标题、非正文或只留来源的章节允许零事实；同一 SRM／质量／风险事实可由正文进展和下周计划共同指向同一稿，不把计划说成完成。经验总结选择完整方法议题。两步各自展示当前项待核稿／评论（桌面约 2/3）及**同项 ID** 的合成预置对照（约 1/3；移动端排在本项之后），切换选中项时一同更新；本机证据定位和冲突反馈保留于同一条目的当前问题下，但不等于真实读取、有权裁定或正式版更改；切换项、步骤或材料清除未提交反馈。人工 fixture 不能称已核到权威事实或正式知识版本。数字口径与 Tool 授权条件均需另行核实。第四步「加入知识库」用本地树按九类去向分别预览未满足门禁（不预览规范 Git 文件，Tool 节点不申请权限或调用接口）；第五步按需看合成 Skill／人工写法的正常、边界、异常示例，也可跳过，不影响第四步。指定知识版本修订与 Skill 深层创作各有独立门禁，均非演示树节点自动提交。工作台的个人 Inbox 条目和反馈进度只留在本页内存，不是已持久化、已授权转交、已受理或已发布的团队事项；模拟撤权或刷新后清除。工作台不汇总真实身份、指派和生命周期，模拟未绑定时隐藏个人情景及数量而不把不可见当作零使用。原工作台固定「需要我处理／我关注的进展」两张情景卡已从首页移除；真实待办的生成规则仍见[工作台事项机制](../界面功能设计/02-Workbench工作台.md)。
9. 不先整理材料，直接点左侧 **打磨可复用的技能**（原「引入 Skill」）：现有页面从资产版或外部／本地候选选择；外部区域可选本地预置的虚构采购周报样包，走四阶段。① 同一输入区选预置虚构采购原版 v0.1／改版 v0.2、团队资产、获准目录或外部定位；原版/改版只能比较页面预置的停止片段与文件名，不读取 DSH 真包。② 当前输入的已知信息、未知权限、缺口责任、testcase 计数及按需逐例结果集中展示；重新提供目录仅比较文件名，外部同名/同链接也不能证明同一 Skill。③ 上方直接显示按当前诊断、责任与失败断言生成的 DSH 手动提示词，不携带用户填写的来源链接、路径或自由文本；只得到文字建议则继续在本地待核草稿修改，取得获准改后包则回①同一输入区重新选择，进入②重诊断。③的一组业务边界字段可生成九项固定样包的**内存拟议预览**并对当前草稿运行五例浏览器规则演练；旧输入或草稿的演练不会作为新输入的测试。到别的页面再进「打磨可复用的技能」会保留本次打开页面的当前候选；不同资产基线或不明来源需在①确认替换而非静默覆盖。**没有**读取任意改后包或真实 diff，没有正式 Skill Creation Session ID、DSH 原生会话嵌入或跨刷新恢复；④ 五门当前候选始终阻断。另有**隔离的虚构齐门示例**依次演示请求、外部结果未知对账、模拟受理、指定 Git/CI/有权人审核（未合并仍审核中）、canonical 受保护 Git main 合并核验后的 `skill.released`，再选择可选 Registry release/version/digest 读回／读回未知对账，或 Git 已发布后管理员固定包 fallback（不是发布），最后演示逐目标 pinned digest 安装读回；它与当前候选和任何真实服务无关。TeamAI 作为上游流程编排入口尚待接口核实，不代替 Git 发布权威或可选 Registry 的读回。真实 Runner 测试仍为零；SK-02、来源线索、Git/ZIP 与仅文件名的本地目录不套用采购包九文件及五例；其他固定虚构目录可演示其各自文本规则而非真实 Skill 执行。材料第五步独立且可跳过，所有状态刷新即丢失。
10. 在左侧 **团队业务资产大盘 → 智能诊断** 看 AI 巡检雷达的三类预置演示发现：核清单 A 与模板 B 是否在同一任务及生效时间冲突；核项目 A 的约定复核点之后能否取得权威进展；核限定交接流程中 Skill 实际运行、Tool 授权与人工判断的衔接。逐条进入只读详情看来源、未知点及建议动作，可本地标「待补证／不适用」，返回卡片能看到反馈；没有真实扫描、通知或自动个人待办。流程衔接的详情还可**主动**打开一类虚构任务的四个判断点；候选能力地图不是全团队自动覆盖率。此处的 SK-02 v1.1 是另一份虚构 Skill，与「加入知识库」中用于比较的 SK-01 v1 周报整理示例不是同一资产或修订链。

## 材料主路径与按需进入的深层会话

**现有 HTML 是五步静态演示，拟议业务门禁尚未实现。** 导入可载入 111 行完整虚构合成周报，或通过文件选择器本机读取获准使用的 UTF-8 TXT／MD／CSV（≤200 KB）并阅读全文；指纹不匹配或粘贴文本只能阅读，不能取得固定议题。第二、三步均以当前选中事实点／经验议题的待核稿及评论为主，旁边是**同 ID 的本地预编排对照**（桌面约 2/3 与 1/3，随项更新、随正文滚动；移动端紧跟本项），不是已查到的有权时点事实记录或正式知识准确版本。第四步有本地去向树：来源、时点事实、待核经验、规则、当期 KPI、计划、一次性处置、附件／非正文、外部 Tool 各有去向与未完成门禁；`knowledge/…` 只是条件性新建路径提示，**没有创建文件或提交 Git**，Tool 树节点也没有真实申请或调用接口。第五步的 SK-01 v1 及合成 Skill／人工写法的正常／边界／异常比较可跳过，不阻断去向树；不是旧版缺口已核实、真实试跑或通过记录。**产品拟设计**才要求逐段核获准来源版本与覆盖、同项可访问的权威事实／正式知识准确版本、按报表口径及身份／用途／对象字段／时间窗／只读通道授权就地核数字与 Tool、仅在真实可核条件满足后为 Tool 申请与调用提供受控流程，且仅在可核正式知识候选上预览 `knowledge/<domain>/<topic>/<knowledge-slug>/` 的规范文件；深层知识修订、Skill 真实脱敏测试与发布另走独立门禁，不能由静态五步声称完成。

**事实梳理／经验总结中的讨论**：在相应当前待核稿上选段评论、查看本地预置的完整下一版待核稿（v2、v3……）、差异、旧稿与回退；无选区可评论整段。只有指定参考周报完整 SHA-256 字节匹配或内置 **111 行完整虚构合成周报**才提供这套人工编排议题；粘贴相同全文或其他输入也不触发抽取，文件指纹不证明分享资格。事实与经验各自选择一个稳定条目 ID，并随选择同时更换左侧待核稿与右侧合成已有内容对照，不跨项粘留；来源当时说法、正式知识及原件均不被覆盖。需核查才按需展开**参考文件**的 32 段／111 显示行范围清单及各段关联数量（22 条处理线索是内部索引，不在页面逐条展示；附件未读、尾部非正文排除）；虚构全文虽同为 111 行且结构相似，不能将参考文件行号当作它的逐句抽取或已核证据。项目 A 备选料与跨场景需求整合两段经验只是不同的待核议题，可继续待核或不沉淀；页面在本地标记“值得继续核对”后仅显示条件性新目录路径 `knowledge/…`，**并未查到准确旧版或渲染 Git 文件**。可核旧版时修订原 ID、或查重后新增规范目录 `knowledge/<domain>/<topic>/<knowledge-slug>/`，均为后续产品目标，不等于当前已写仓库。来源、事实、规则、KPI／计划／一次性处置各归其有权去向，不强迫都成为知识。本地评论仅命中有限预置方向；未覆盖则保原稿并允许重试，换材料／议题或撤权使未提交选区失效。旧 K-01 v1 → R-02 在另一可展开记录中独立演示，不能当本周报已发布。详见[知识创作规格](../界面功能设计/03-知识创作会话.md#材料主路四步可跳过的第五步与指定版本深层操作的分工)。
**完整周报覆盖合同（静态原型已人工编排逐段去向，非实时解析）**见[知识创作规格的逐区块表](../界面功能设计/03-知识创作会话.md#完整周报的覆盖合同静态原型已逐段人工编排非真实抽取)：**指定本地参考文件**的来源元数据、五类 KPI、主料/包装、MRO/IT、SRM/培训、供应商开发、质量与月度评估、三条彼此独立的降本路径（需求整合、货代竞价、VMI）、价格风险中已开展的成本复核与拟讨论的锁价方式、产品线 C 的预测/处置/待验证替代、下周四组计划及未读附件引用均在范围清单中有去向；107–111 的围栏、`eof` 等尾部非正文排除。固定人工索引按对象与知识类型区分线索，一段可关联多条，也可没有条目并给理由；**22 条线索不等于 22 篇知识**，完整覆盖不等于逐行入知识，不复制受限原始数据。`index.html` 的内置材料是**111 行完整虚构合成周报，不是真实参考周报的原文**；只读本地参考文件通过文件选择器载入后也可阅读全文。文件 SHA-256 `85018947cb5bd65e694b4f2a1e3f31769abc51c4f61fd8a6a96e30b93b4301c2` 命中时展示同一套人工编排覆盖与候选，指纹仅证明字节一致，不证明已解析、授权、核证或查重；粘贴原文亦不会命中。两条完整议题仍只是由线索人工综合的待核判断，而非自动抽取或已发布知识。无真实集成或自动提取，Git 正式版与 WeKnora 来源阅读／正式知识检索仍须分别授权和读回。

- **静态原型与真实插件集成不是一回事**：双击 `index.html` 只调用本地预置回复，评论触发的“生成中／失败／下一版”都在浏览器内存中演示，不发网络，也不能证明已接入模型。本轮交付的是产品文档与静态页面，并未实现或验收 DSH Client 的原生 Session 修订。若将来使用公开 `ctx.sessions`，目标 Profile 的插件权限、成功 turn 的唯一关联、宿主历史可回看及模型去向／留存策略仍须另行实测；这里不安装或运行真实 DSH／Provider，也不发送生产材料。评论、草稿 v2 或本地 `accepted` 都不算正式知识版本或发布回执。
- **Skill 引入与提交审核门槛（四阶段演示；真实能力拟设计）**：目标①同一输入区按团队资产、样包、本地目录或来源定位选择，DSH 修订包也回①，取当前实际输入重诊断；能核实原包内容和关联时才比较，无法核实时明确待核，不假定“同名即同包”。②仅核已取得信息，并集中展示案例数量与按需逐例结果；③集中编辑本次业务边界、批量拟议文件、复测，或审阅当前候选的诊断、缺项责任及失败断言后手动回 DSH 讨论（不自动发送、回复不直接改包）；输入/修订变化旧结果失效。④五项提交前质量门核对。**现有 HTML 已演示统一阶段①及预置虚构样包的有限修订对照，但不能读入真实 DSH 改后包或生成真实 diff**；静态页面无法真正上传／解析任意包、生成受控文件、运行受控 Runner 或取得授权/CI/SkillHub/TeamAI 读回，不能让字段非空或演练通过冒充五门齐备。独立虚构发布链仅说明提交请求不等于受理、批准不等于 Git 合并发布、包 digest 不等于发布、可选 Registry 读回不等于 Git 发布；Git 已发布后 Registry 未知不能遮蔽发布，而安装、DSH 加载、执行及业务结果仍各需自己的回执；TeamAI 上游编排契约仍需确认。生命周期五层判断与材料路径的可跳过第五步是不同概念。

## 刻意保留的边界

- 同一 Workbench 可以被不同团队安装，但每个团队的 `team-knowledge-asset`、Git 仓库、草稿及授权各自独立；本产品体验不设计跨团队分享。团队内可贡献，不等于所有敏感来源或正式审批动作无条件开放。
- 选中内容评论是低门槛协作方式的**产品假设**，并未通过用户测试证明最优。真实实现需要稳定锚点、旧版快照、重新定位／冲突处理及审计；首版不做多人实时协同编辑。
- 没有角色视角切换，但仍需对具体确认、审核、发布和 Skill 运行做真实身份与权限校验；本页的模拟绑定或模拟确认都不是授权事实。
- 团队仓库可以记录获准展示的 Tool 目录引用及 Skill 依赖，不能创作 ERP/MES/数仓生产接口、批准价格/库存数据访问或保存查询结果。列表、分类标签、参数结构应从外部提供方/数据中台的目录 API 按可见权限取得；本原型仅用虚构预置条目。实际接口由外部提供方接入，数据责任方限定字段、对象和用途，DSH 运行时再次检查用户/服务身份与工具策略；低风险只读试参也须有经批准的测试通道，广场无试调。若增加团队调用次数，应依据授权的宿主成功调用回执做最小化 PostgreSQL 时间窗聚合，不存参数、结果或完整 trace，不以本地按钮点击冒充调用；无证据显示暂无法统计。申请不等于获批，查询能力仍待目标环境验证。写入业务系统的 Tool 不采用查询示意的门禁。
- Creation Session 不等于 DSH Runtime Session；Market 安装和面板加载不等于正式资产发布。真实知识发布须 Git/CI、指定人审与 WeKnora 逐文档读回；Skill 的 `skill.released` 则仅在指定审核及 canonical 受保护 Git main 合并核验后成立。SkillHub/Registry 的 release/readback 可选，另记 `registry_released`；管理员固定包 fallback 仅在 Git 发布后供下游取包而非发布。逐目标安装、DSH profile 加载、执行及业务结果分别核证。Skill 建议不代表宿主已支持自动匹配，该宿主能力尚待目标环境验证。
- 本页不持久化、不上传输入、不请求远端；复盘中的自由文本更正不进入示例交接，知识、Skill、来源核对与业务事实核对的粘贴草稿分别留在当前页面内存，刷新或模拟撤权即清空。知识页可以选择本地小型 UTF-8 TXT／MD／CSV 并读入同一文字框，但**没有**网络文件上传、PDF／Office／邮件解析、知识库授权检索或查重、任意材料自动提取、提取 Skill 执行、Git 归档/提交、WeKnora 索引或正式发布。也没有 Clipboard 自动读写；不要输入生产凭据、敏感原文、完整 Prompt 或 Tool Call trace。模拟提交候选、评论和状态不能充当交付、真实业务结果或收益证据。
